# 服务器测试包生成与验收规则（2026-08-15 压缩前快照）

最后更新：2026-08-13（compile module provider闭包、短探针复用与 compile-fail core 闭合）

本文件只定义所有服务器测试包共有的生成、运行、回传和发布门。读取范围由
`生成前必读索引.md` 决定；算子语义、硬件字段和版本状态分别由算子专项规则、`NDP硬件字段语义.md`、`.agents/plan.md` 与 task record 管理。

## 1. 适用范围和基本结论

本规则适用于创建、修改、重打包或发布任何服务器消费目录/ZIP。简化的是用户在服务器上的人工步骤，不是测试内容。结构 valid、ZIP exact-set、仿真自然完成或内部写请求都不能替代算子专项语义门和正式 readback。

所有新包在服务器结果验收前固定为：

```text
candidate_release=false
evidence_level<=E2_LOCAL_ONLY
```

历史包、失败包、手工回传和发布资产默认永久只读；新包使用全新 package/install/run/return 身份，不原地修补或覆盖。唯一例外是
`CDA-SERVER-RETURN-WAVEFORM-INCREMENTAL-REVIEW-RETENTION-001` 明确允许在正式回传完整收集、
family/mainline 双消费和核心证据派生完成后，按精确 SHA 受控淘汰本地重型 raw-waveform return；
该例外不适用于服务器测试包、task record、报告、core return 或未消费证据。

### 1.1 严格检查前移、服务器最小预检

规则 ID：`CDA-SERVER-STRICT-LOCAL-AUDIT-MINIMAL-RUNTIME-PREFLIGHT-001`

服务器测试的首要目标是尽快进入真实 compile/run，定位配置语义或 RTL 问题；不能让测试包
生成失误或无必要的服务器环境自检反复消耗测试轮次。所有严格、可在本地完成的检查必须在
交付最终 ZIP 前完成，服务器端默认只保留启动和结果可信性所必需的最小检查。

本地最终 ZIP 自检仍必须严格覆盖：源测试包 ZIP/sidecar、CRC/exact-set、manifest-bound package
payload、runner 真实控制流正负控、SCA/SCA_D、runtime readback target absent、observer
源码/编译参数/runtime/return 绑定、canonical decision、结果联合门和 return allowlist。
本地可以发现的语法、硬编码 SHA 漂移、namespace、路径、入口、预置 D、runner 提前退出等
问题不得带到服务器。

服务器运行前不得用“存在性证明”代替真实运行。runner 只允许做不读取服务器既有内容的
参数/路径语法检查、arm exactly-once partial-return finalizer，并在约定的 package-owned
namespace 中执行本包明确拥有的覆盖式安装/复跑初始化；随后应直接执行 production
`cd`/install/compile/sim 命令。`cd`、复制、创建 package-owned 子目录、compiler 或 simv 的
自然成功/失败就是运行事实，不得在它们前面再增加同义探针。

尤其禁止在 production compile/sim 前执行 `test -e/-f/-d/-r/-x/-L`、`stat`、`find`、
`readlink/realpath`、hash/tree inventory、`git` identity、`command -v/which`、Make dry-run、
module/provider lookup probe，或任何其它用于证明服务器已有文件、目录、module、library、
tool、RTL、TB、Makefile、filelist、support file 是否存在/完整/可读的命令。不得因为这些
对象“未被预先证明存在”而停止 runner。最终 ZIP 内的 package-owned payload、runner、
observer、SCA、execplan、return allowlist 等严格检查必须全部在本地 final-ZIP audit 完成；
服务器端不重复做一套存在性审计。

默认禁止在 runner preflight 中枚举、哈希、比较或要求服务器既有的具体 RTL、TB、
Makefile、filelist、support file、Git/commit、README、observer 文件或整棵源码树，也
禁止把这些服务器文件的历史路径/SHA 写成运行前成功条件。只有用户明确要求一次独立的
服务器源码身份审计，或明确授权本包事务式修改某个服务器文件时，才允许对该精确目标做
检查；该可选审计不得成为普通包进入 compile 的前置门。

package-local observer/辅助文件属于包自身，只在本地 final-ZIP 自检中按 manifest 单一事实源
核验；runner 不得再维护第二份硬编码 expected SHA，也不得在服务器安装后逐文件重验。真实
compile/run 失败应保存 actual cwd/argv、完整 compile/sim log、first true error、exit status、
`simulation_started` 与最小 core return 并回传，不得通过增加服务器文件预检查来“避免”自然
失败。服务器已有 module/provider/toolchain 是否可用，只由同一 production compile 的真实结果
裁决；历史成功、路径名、单个目录缺失或本地猜测均不能替代该结果。

违反本门分为：

- 本地本应发现却带到服务器的 package/runner 错误：
  `PACKAGE_LOCAL_DELIVERY_SELF_AUDIT_ESCAPE`；
- 无必要服务器文件检查导致未进入 compile：
  `PACKAGE_RUNTIME_PREFLIGHT_OVERREACH`。

两者都必须修包，但不得据此推断算子配置或 RTL 失败。

此前的 `CDA-SERVER-COMPILE-MODULE-PROVIDER-CLOSURE-001` 与
`compile_environment_attestation` 不再是 current/next-fresh blocking gate：它们要求在 production
compile 前读取服务器 provider/path 或运行短探针，违反本节“真实命令先行”裁决。既有
`server_compile_environment_gate` 资产仅可作为正式 compile 已失败后的只读诊断/历史收据解析器，
不得由 runner、final ZIP release driver 或 first-fresh audit 调用，也不得 HOLD/拒绝 package。

#### 失败后回看原生 ndp-sim 路径

任一 production compile/sim、SCA preload、目标 stage 或 return 失败后，owner 在设计 successor 前
必须回看实际衍生来源，而不是先增加新的服务器 preflight：

1. 绑定并重读 current `ndp-sim` commit，以及本轮实际消费的 native README、handler、mapper、
   encoder、address planner、`model_execplan/main.py`、SCA writer/assembler；服务器入口同时读取
   `NDP_copy01/README_HARDWARE_SIM_ENTRY.md` 和活动 Makefile/TB/filelist；
2. 把失败 attempt 的 actual cwd/argv/env、`+SCA_CFG`、`+SCA_CFG_D`、`Repeat_Num`、execplan、
   cfg path、compile/sim log 与原生/已验证路径逐项分类为 `SAME`、`PACKAGE_DERIVATION`、
   `NATIVE_DOCUMENT_IMPLEMENTATION_DRIFT`、`SERVER_RUNTIME_UNKNOWN`；仓库没有保存的服务器
   loader/start/wait/readback 命令必须标为 unknown，禁止猜测；
3. 优先核查已知原生陷阱：调用 cwd 与 `../model_execplan/main.py` 路径、顶层 Python exit 0
   是否掩盖 bitstream 子失败、日志是否明确 `Regenerated ... operator(s)`、SCA 与 SCA_D 是否同包且
   同时显式传入、TB 是否回显正确文件、execplan/bitstream/SCA actual consumer path 是否一致；
4. native differential 是失败后的候选生成与证据登记，不是服务器运行前存在性门。只有差异属于
   package-owned bytes/argv 且会改变 actual input、production launch 或 return 时，才回到本地聚合
   validator 修包；服务器环境差异只记录并让 production command/return 裁决；
5. 每轮只运行一次本地聚合 non-interference 检查和一次 exact-final-ZIP 复核；不得逐个错误重构包。

### 1.2 本地发布门优先级、适用性与最小阻断集

规则 ID：`CDA-SERVER-LOCAL-RELEASE-GATE-IMPACT-APPLICABILITY-001`

本地自检的目标是阻止会让服务器 **无法进入真实 compile/run、执行错误配置、丢失关键
return，或产生不可裁决结果** 的错误，不是最大化检查数量。任何新生成、重建或 fresh
identity 的包，必须在 final audit 中发布单一 `release_gate_matrix`，逐项声明
`gate_id/applicable/reason/changed_surface/evidence/blocking`。只列规则 SHA、builder 自报
PASS 或累计负控数量不能替代该矩阵。

以下是最小阻断集：

1. **package identity/bootstrap**：final ZIP/sidecar、CRC/single-root/path safety、
   manifest exact-set/per-file receipt、fresh namespace、bootstrap tree immutability、
   内层路径预算、runtime D absent；
2. **真实 runner 控制流**：fresh extract 调用最终入口，完成package/install preflight，
   以安全stub实际到达一次compile，并走完EXIT及声明的signal finalizer；不得只检查脚本文本；
3. **package-local HDL compile readiness**：仅当actual compile argv引用package-local HDL
   时适用；对exact final bytes执行focused syntax/scope/name-resolution、actual-consumer
   coverage及规定负控；
4. **materialized config consumer contract**：仅当本包新增/修改配置、mapping、bitstream、
   execplan、SCA或地址绑定时适用；必须复用
   `CDA-CONFIG-MATERIALIZED-ROUNDTRIP-001`、
   `CDA-CONFIG-CAUSAL-TRANSACTION-LEDGER-001`、
   `CDA-CONFIG-BOUNDARY-MICROTRACE-001`、
   `CDA-CONFIG-PHYSICAL-BANK-ROW-VALIDITY-001` 与目标专项规则，从最终materialized产物
   验证transaction/address/mask、物理bank/row/column可达性及其direct consumers、
   producer supply→Buffer→consumer occurrence、terminal、lifetime和正式D覆盖。
   公式模型、aggregate容量内、builder摘要或“可编码”不能替代；冻结且逐字节复用的
   numeric/W3/golden不重复分析；
5. **observer/canonical result trust**：仅当新增/修改诊断observer、parser、progress或
   canonical predicate时适用；必须完成四向绑定、event qualification、actual-consumer
   closure和下述trace单元门；
6. **return/result gate**：allowlist、RETURN_MANIFEST exact-set/required-missing、
   partial-signal回收、natural terminal与formal D联合门必须由最终runner和collector闭合。

适用性与裁剪规则：

- `always`：1、2、6；它们直接决定包能否启动和结果能否回收；
- `changed-surface`：3、4、5，只在相应最终运行面存在或改变时阻断；不允许因“不想实现”
  而标记不适用；
- 既有资产若exact bytes、直接消费者和current语义规则均未变，可引用已验证receipt及
  byte-equality/current-match证明，不得重复跑整套numeric、W3、全RTL域或历史版本负控；
- 与compile/run、实际配置或结果可信性无因果关系的样式检查、报告排版、重复统计、
  未进入最终ZIP的中间目录检查固定为`record_only`，失败只告警，不得阻止上机；
- 负控按 **失败机制/等价覆盖类** 合并：每类至少一个真实变异，并强制保留最近一次同类
  `PACKAGE_LOCAL_DELIVERY_SELF_AUDIT_ESCAPE` 或配置反例；禁止为了数量重复运行同义
  token删除、同一布尔门的多份正则检查。actual-consumer逐表达式覆盖仍服从其专项规则；
- full-design production elaboration、服务器既有源码树身份、完整服务器环境和真实仿真
  不得搬成本地阻断门；本地只保证包能正常进入服务器真实compile并可靠暴露DUT/工具差异。

final audit 必须由一个顶层release driver针对final ZIP生成；它可以调用共享core和算子专项
extension，但不得手工汇总多个builder自报布尔值。机器记录至少包含：

```json
{
  "release_gate_matrix": {
    "core_always": {"applicable": true, "pass": true},
    "runner": {"applicable": true, "pass": true},
    "package_local_hdl": {"applicable": true, "pass": true},
    "materialized_config": {"applicable": true, "pass": true},
    "diagnostic_semantics": {"applicable": true, "pass": true},
    "return_result": {"applicable": true, "pass": true},
    "record_only_warnings": []
  },
  "blocking_failures": [],
  "pass": true
}
```

字段名可以不同，但证据含义不得省略。任一适用阻断门失败，状态固定为
`PACKAGE_LOCAL_RELEASE_GATE_FAILED`；`record_only`告警不能被改写成阻断失败。
本规则发布前已经冻结且未运行的current包，不因新增矩阵格式本身强制重建或暂停；其下一
fresh successor必须应用本门。若旧包因其它current规则已处于hold，仍按原解锁条件处理。

### 1.3 next-fresh 构包编译档案、聚合预检与收据复用

以下构建控制规则先以 `SHADOW_ONLY_NEXT_FRESH` 发布。它们只作用于本规则发布后开始设计的
next fresh successor；发布时已经处于构建、final audit、`pending`、服务器运行或return
分析中的本次/current包一律不修改、不重建、不替换、不暂停，也不得因为缺少本节新增
profile而改变其family release。第一次真实fresh包必须先与family现有validator做一次
shadow compare；无论match或divergence都只记录，不改变family release。只有主线另行裁决
blocking promotion后，才允许把本节shadow结果升级为发布阻断门。

规则 ID：`CDA-SERVER-PACKAGE-COMPILED-BUILD-PROFILE-001`

1. next fresh successor在复制冻结workload、物化staging tree、生成ZIP或执行昂贵负控之前，
   必须先由共享入口编译一份`server-package-build-profile-v1`。当前shadow入口为
   `tools/server_package_pipeline.py prepare`；family builder只提供package spec和family
   extension，不得手写第二套公共规则适用性。
2. profile必须读取并绑定`生成前必读索引.md`、本规则、共享gate registry、输入文件、
   validator与fixture身份，并把每个公共门机械分类为
   `blocking_applicable/receipt_reuse/record_only/not_applicable`。只记录“已读SHA”不能
   替代适用性计算或验证证据。
3. v1只接受`lifecycle=NEXT_FRESH_SUCCESSOR`、`shadow_only=true`、
   `current_package_impact=false`。任何current/pending/tested包、正在构建的本次包或正式
   return都必须被共享入口拒绝，禁止借shadow驱动重写其资产或发布状态。
4. profile只决定后续应执行/复用哪些门，不得自行声明package PASS、natural terminal、
   formal D、E4/E5或服务器release。

规则 ID：`CDA-SERVER-PACKAGE-BLOCKING-CAUSAL-CLASS-001`

1. 共享gate registry中的每个`blocking_applicable`门必须至少绑定一个且只能绑定以下因果类：
   `server_start`、`actual_input`、`state_safety`、`return`，并给出失败如何影响该类的
   `blocking_effect`。缺少映射、只写“规则要求”或只影响说明/排版/冗余收据时，不得成为
   blocking；默认降为`record_only`。
2. `server_start`只覆盖会使唯一入口、production compile/elaboration或simulation无法启动的
   包内条件；`actual_input`只覆盖服务器实际打开的config/matrix/bitstream/execplan/SCA路径与
   字节；`state_safety`只覆盖路径逃逸、覆盖未知项、非fresh运行状态或current pickup歧义；
   `return`只覆盖shared finalizer、allowlist、canonical result和正式结果联合门。
3. observer/报告格式只有在它实际参与本轮canonical/progress/result裁决时才可映射`return`；
   可选备注、非裁决统计、环境偏好或未进入final ZIP的中间报告一律`record_only`。
4. profile和final report必须逐门输出`causal_blocking_classes`、`blocking_effect`和
   `execution_group`。负控必须证明删掉真实blocking consumer会影响对应四类之一；修改
   record-only字段不得改变服务器命令、actual input、状态写入或return exact-set。

规则 ID：`CDA-SERVER-PACKAGE-AGGREGATE-PREFLIGHT-001`

1. 所有不依赖最终ZIP且成本低的检查必须在昂贵物化前一次运行并收集完整错误集合，至少覆盖：
   rule/profile identity、package/family/lifecycle、changed-surface词表、输入size/SHA、
   path/namespace预算、validator/fixture identity、receipt引用和storage disposition。
2. 该阶段禁止遇到首错即停止；必须发布`all_errors_collected=true`及全部错误。只有聚合预检
   通过后，才允许开始两份fresh tree、压缩、focused HDL、runner harness或final-ZIP audit。
3. staging tree形成后，package-local HDL、actual-consumer、predicate、runner与return
   binding应先对冻结tree聚合检查；同一tree的一处修正只使受影响门及其直接消费者失效，
   不得无条件重跑无关numeric/W3、冻结config、全RTL域或已闭合公共负控。
4. storage rotation只改变存储状态；若exact ZIP SHA未变，rotation后只执行storage audit，
   复用原final-ZIP内容收据，不重复运行整套内容门。
5. 一次构包事务固定只有一个`prebuild_aggregate`顶层调用、一个冻结staging-tree聚合调用和
   一个`final_zip_release_driver`顶层调用。final driver可在内部执行多个适用子门，但对同一
   exact ZIP SHA只能被调用一次；禁止每发现一处错误就先压缩一个新ZIP再重跑全部门。
6. 廉价检查必须用统一`server-package-cheap-check-result-v1`收据输入共享pipeline；pipeline
   一次读取全部收据并同时发布所有blocking errors和record-only warnings。只有完整错误集合
   关闭后才物化/压缩；若final ZIP SHA未变则复用exact内容收据，SHA改变时只对新exact ZIP
   执行一次fresh release driver。

规则 ID：`CDA-SERVER-PACKAGE-CONTENT-ADDRESSED-RECEIPT-REUSE-001`

1. 收据复用键至少绑定：相关输入tree/surface SHA、规则语义版本、validator SHA、fixture
   registry SHA和直接消费者等价性。任一身份漂移、exact bytes不等、consumer变化或旧结果
   非PASS时，必须拒绝复用并把该门恢复为`blocking_applicable`。
2. validator报告必须把临时目录、PID、随机staging路径和本地一次性return ZIP SHA与语义
   判据分离；缓存键只使用规范化语义内容。不得因临时路径不同把语义相同的正负控重复计算，
   也不得忽略真正进入final ZIP的字节差异。
3. package仍须在两个全新目录独立形成完整tree并证明最终ZIP逐字节确定；冻结且已验证的
   payload可分别复制到两目录并复核tree SHA，不要求重新运行无关上游生成器。
4. receipt cache只能省略等价验证，不能降低final ZIP exact-set、runner真实控制流、
   runtime-D absent、workload provenance、natural terminal、正式D、E4/E5或RTL授权门。

共享机器合同固定为：

- `schemas/server_package_build_profile_v1.schema.json`
- `schemas/server_package_cheap_check_result_v1.schema.json`
- `contracts/server_package_build_gate_registry_v1.json`
- `tools/server_package_pipeline.py`
- `schemas/current_family_pointer_v1.schema.json`
- `contracts/current_family_pointer_registry_v1.json`
- `tools/build_current_family_pointer.py`

规则 ID：`CDA-SERVER-PACKAGE-CURRENT-FAMILY-POINTER-001`

1. current待测包的唯一机器入口由
   `tools/build_current_family_pointer.py`从current
   `PACKAGE_STORAGE_INDEX.json`和包含exact `package_base`的最新package task record自动生成；
   `.agents/plan.md`只参与漂移lint，不参与current package选择。
2. 每个pending family必须恰好一个package，storage index中的pickup ZIP receipt必须与磁盘
   bytes/SHA一致，所选task record必须包含exact package base。任一歧义或缺失都fail closed，
   但plan未及时同步只报告`plan_coherence.pass=false`，不得因此重建、替换或hold已验证包。
3. storage index SHA变化后，任何构包、return分析或运行顺序裁决前必须重生成pointer；不得继续
   引用已被tested/superseded取代的会话记忆、旧plan行或手写版本号。
4. pointer只指向current pending package及其最新绑定记录，不修改plan、family release、
   package bytes、存储状态或服务器状态。

首次真实shadow compare至少回传：exact package spec/profile/family validator/family report
SHA、四态disposition、聚合错误集合、缓存命中/拒绝原因、各阶段墙钟，以及
match/divergence。未完成该compare前不得删除或绕过family validator。

## 2. 输入和完整重建

规则 ID：`CDA-SERVER-WORKLOAD-PROVENANCE-001`

1. package manifest 必须记录生成工具、锁定提交/patchset、输入路径、大小、SHA-256、
   命令、cwd、退出码和目标算子。
2. 配置语义、地址或 mapping 有变化时，必须从本轮最终 address-bound JSON 完整重建：

   ```text
   planner → encoder → mapping → bitstream → execplan → SCA/SCA_D
   ```

3. 每个产物绑定本轮 provenance。输出哈希与旧版相同不能代替重建收据。
4. workload 若完全冻结且配置语义未变，可以逐字节复用本轮已验证的冻结 workload，但必须验证其原始完整重建 receipt 和 exact tree identity；不得从服务器残留、旧失败 run 或被否决包抽取文件。
5. 正式数据来自本轮授权 tensor/golden/relayout；bridge 必须是可审计、确定性的最小
   机械转换，不能发明配置语义或吞掉原生错误。

## 3. 包结构、身份和确定性

每个包至少包含：

```text
PREPARE_AND_RUN.sh
README.md
TEST_PACKAGE_MANIFEST.json
workload/
```

需要只读观测时可增加 `tb_probe/`，但必须满足第 6 节。manifest 必须给出：

- schema/version、package/install/run/return 唯一名称；
- workload、脚本、可选 observer 的逐文件大小和 SHA-256；
- 包 exact file set、禁止项、预算和预期回传名；
- SCA/SCA_D、execplan、golden、动态门和 focused identity 集；
- `functional_rtl_modified=false`，除非本轮得到明确 repair 授权。

发布前必须从两个全新目录独立构建两次。ZIP entry path、mode、内容、manifest、payload tree 和最终 ZIP SHA-256 必须逐字节一致；时间戳等非确定元数据必须规范化。源测试包 exact ZIP 与 `.sha256` sidecar 都要通过专项 validator。不得只验证解包目录。

规则 ID：`CDA-SERVER-PACKAGE-INTERNAL-PATH-LENGTH-BUDGET-001`

后续新生成、重建或使用 fresh identity 发布的服务器测试包，必须优先缩短 package 内层路径，
避免服务器解压、安装、compile、run、return staging 或工具生成中间文件时超过路径字符限制。
本规则不要求仅因路径风格重建、改名或失效已经冻结且已通过 current 自检的现有包；现有包一旦
因其他原因重建或派生 fresh identity，就必须应用本门。

1. ZIP 的 single-root/最外层 install identity 可以保留较长、可读、可追溯的算子和版本名称；
   该长身份只出现一次。内层目录不得再次逐级重复 package/test/operator/stage 的完整长名称，
   语义说明、长 test ID、来源和 SHA 放入 manifest/report，不靠深层文件名承载；
2. 内层优先采用稳定、确定性的短命名空间，例如 `w/`、`cfg/`、`map/`、`bs/`、`ep/`、
   `sca/`、`obs/`、`log/`、`d/`。同类多成员使用短 ID 或固定宽度序号；缩写映射必须写入
   manifest，且所有 SCA/SCA_D、execplan、runner、observer、return allowlist 和 validator
   引用同步绑定。不得只改 ZIP member 名而留下旧引用；
3. 本地设计目标默认是：最外层 single-root 之后的内部相对路径不超过 128 个字符、内部层级
   不超过 8 层、单个内层 component 不超过 48 个字符。原生工具或 ABI 必须保留的 canonical
   leaf 可以例外，但应先缩短父目录，并在 manifest 记录例外理由；这些目标不是要求无意义地
   重命名工具链强制文件；
4. package manifest 必须声明 `path_length_budget`，至少包含
   `declared_target_root_max_chars`、`max_projected_absolute_path_chars`、
   `max_zip_member_chars`、`max_inner_suffix_chars`、`max_inner_depth`、最长路径成员及例外。
   默认按服务器目标根最长 96 字符、package 控制的 projected absolute path 最长 240 字符
   做本地保守验收；任务已知根更短可保留余量，已知工具链有更低限制时必须采用更低值；
   其中最长 projected relative path 必须保存 exact string 与实际字符数；validator须从
   final ZIP、运行布局和全部直接消费者重新枚举后证明
   `declared_longest_string == computed_longest_string`、
   `declared_longest_chars == len(computed_longest_string)` 且
   `max_projected_absolute_path_chars == declared_target_root_max_chars + 1 +
   declared_longest_chars`。只比较“不超过上限”不能替代三项精确等式；
5. 独立 final-ZIP validator 必须在 fresh extract 后枚举所有 package-controlled install、
   workload、compile/run 工作目录、observer、readback 和 return-staging 路径，机械计算
   `<declared target-root budget>/<package-controlled relative path>` 的最坏长度，并验证
   manifest 引用闭合。超过声明预算时先缩短内层目录/文件名，不得通过缩短唯一外层身份到
   无法追溯、删除必需 payload，或假设服务器会自动支持长路径来放行；
6. 真实 runner 只做一个 compile 前的廉价保护：以用户传入根的实际规范化长度重算上述
   package-controlled 最长绝对路径。若实际根比声明预算更长并导致超过限制，应在 compile
   前给出最长成员和所需缩短字符数后 fail closed；不得等到解压一半、VCS 生成中间文件或
   simulation 后才发现。该保护不是服务器源码/环境自检，也不得递归扫描服务器 RTL 树；
7. final-ZIP 负控至少覆盖：人为增加一个超预算深层成员、在内层重复完整长 identity，以及
   缩短 member 后不更新一个直接消费者引用；三者都必须在服务器运行前 fail closed。

本门的目的只是让包能可靠解压、安装和执行，不要求为了形式统一而压缩所有可读名称，也不允许
牺牲身份、exact-set、ABI、数值资产或证据门。路径预算通过只证明 package-controlled 路径
可执行，不替代真实 compile、natural terminal、正式 D 或 E3/E4/E5。

规则 ID：`CDA-SERVER-INSTALL-SUBTREE-RUNTIME-LAYOUT-001`

所有后续新建、重建或 fresh identity 的服务器测试包，package-owned runtime 工作状态统一
放在用户传入 `NDP_copy0x` 根中 **运行前已经存在** 的 `install/` 子树；禁止在该根之外建立
`work_root/cfg_root/run/evidence/compile`，也禁止为了隔离运行向 NDP 根新增直接子项。
规则发布时已经在测、pending、return分析或final audit中的current包不追溯重建；其下一次因
其它原因产生fresh successor时必须迁移。

1. 公共精确布局固定为：
   - SCA、matrix、bitstream及其安装consumer的 cfg root：
     `$server_root/install/cfg_pkg/<install_name>`；
   - run/evidence/compile root：
     `$server_root/install/codex_runs/<package_id>/<attempt>/...`；
   - 只有`install`必须在runner写任何package状态前preflight证明已经存在、是real
     directory且不为symlink；禁止要求用户手工创建二级目录；
   - package允许且应使用共享helper在real `install`下以原子`mkdir`语义创建
     `install/cfg_pkg`、`install/codex_runs`及更深的package/attempt目录。两个共享
     二级目录若被并发创建，只接受最终对象为同一路径real directory；同名file/symlink、
     路径逃逸均fail closed。首次执行时leaf应由本包创建；同一exact package顺序重复执行时，
     helper必须按`CDA-SERVER-PACKAGE-REPEAT-EXECUTION-EXACT-OWNED-RESET-001`只重置并重建
     本包精确拥有的cfg/attempt leaf，不得因同名旧运行内容存在而要求用户手工清理。
2. runner必须在写入前后保存NDP根直接子项的`name+type` exact-set；normal、
   package/path preflight失败、compile失败及`HUP/INT/TERM`六种控制流均必须证明集合不变。
   `install/`内部新增本轮隔离子树不算根直接项变化；在根下新增`work/run/evidence/cfg`
   或把同名目录移到根外立即fail closed。
3. TB的生产cwd固定为用户传入的`$server_root`时，SCA中的每个matrix/bitstream读取路径
   必须从该cwd机械解析到上述exact cfg root中的实际安装文件。final-ZIP validator须枚举
   exact SCA JSON的全部`path` consumer，计算`$server_root/<sca-path>`，再与
   `source ZIP member → install projection → exact runtime bytes`逐项闭合；同时核对runner
   实际`+SCA_CFG/+SCA_CFG_D`指向该cfg root中的对应文件。仅证明文件存在于package、
   `cfg_root`字符串看似正确或SCA aggregate数量一致均不足。wrong install prefix、缺任一
   matrix/bitstream、从错误cwd恰好命中同名文件都必须fail closed。
4. 正式return仍只允许由共享finalizer原子发布到fixed result root
   `/home/panqs/ndp/simresult`。每次执行的文件名必须唯一并绑定package identity与
   execution tag，例如
   `<package_id>_r<UTC-epoch-ns>_<pid>_return.zip[.sha256]`；不得删除、覆盖或改名该目录中
   既有return。为本次唯一目标执行同目录原子rename创建的有界临时项是唯一例外；不得把
   simresult或其临时项用作cfg、compile、run、evidence、readback工作根，也不得在其它
   外部目录保留package-owned状态。
5. 共享finalizer及其所需变量默认值必须在第一个可能失败的参数、父目录、路径预算、
   package/install preflight之前完成arm。任何上述失败都必须通过同一finalizer产生
   allowlist-only partial return；不得先执行package-local path-budget/preflight，失败后
   因trap尚未安装而只在终端输出一行错误。safe runner harness必须覆盖normal、
   preflight-fail、compile-fail、`HUP/INT/TERM`，逐场景绑定exact runner SHA、command/cwd、
   compile/simulation是否到达、根exact-set、外部写集合以及fixed simresult return路径。
6. future fresh package必须在final ZIP中包含
   `SERVER_RUNTIME_LAYOUT_CONTRACT.json`和当前共享helper的exact bytes，并由：
   - `schemas/server_package_runtime_layout_v1.schema.json`
   - `schemas/server_package_runtime_layout_harness_v1.schema.json`
   - `tools/server_package_runtime_layout.py`
   - `tools/validate_server_package_runtime_layout.py`
   对exact final ZIP执行阻断验收。family validator可以叠加本族检查，但不得重写、跳过或
   以builder自报PASS替代该共享门。
7. 本门采用最小阻断和一次聚合策略：只有可能阻止compile/simulation启动、使TB读取错误
   matrix/bitstream、写出`install`或覆盖已有项、破坏根直接项、超过实际路径上限，或使
   partial/final return不可达的问题才阻断。`cfg_pkg/codex_runs`初始不存在、由哪个并发
   进程创建等只记收据，不得报错。validator必须一次遍历聚合全部廉价错误，不得发现一处
   即要求重构包；共享helper的目录类型/并发/六场景负控由公共工具回归证明，不要求每个
   family重复昂贵package物化。每个fresh family只对自身exact final ZIP运行一次适用门；
   与服务器运行、输入打开或return没有因果关系的环境建议、身份备注和优化偏好只能
   `record_only`，不得升级为blocking。

本门只关闭package运行布局、open-path、路径预算算术和partial-return控制流；不改变
workload/config/numeric/observer/RTL字节，不替代production compile、simulation、
natural terminal、正式D或E3/E4/E5。

规则 ID：`CDA-SERVER-PACKAGE-REPEAT-EXECUTION-EXACT-OWNED-RESET-001`

同一测试包允许在同一个`NDP_copy0x`上顺序重复执行。重复执行兼容只改变package-owned
runtime状态和本轮return文件名，不把重复运行冒充fresh package identity或E5。

1. 共享helper只允许重置以下两个由已校验`package_id/install_name/attempt`机械得到的
   exact目录：
   - `$server_root/install/cfg_pkg/<install_name>`；
   - `$server_root/install/codex_runs/<package_id>/<attempt>`。
   reset前必须证明目标在real `install`下、目标自身是real directory，并递归拒绝任何
   symlink或special filesystem entry；同名file/symlink一律fail closed。
2. `install/cfg_pkg`、`install/codex_runs`、package parent、其他install name、其他package、
   其他attempt和NDP根直接项均为foreign/shared state，必须逐字节保留。不得递归清理共享
   parent，不得使用glob选择删除目标，也不得删除或覆盖未知兄弟项。
3. helper应在payload root之外写入精确ownership marker，并绑定package/install/attempt/kind。
   有marker时任一身份不一致必须fail closed。为兼容本规则发布前已执行的current包，允许在
   精确路径和全部安全检查通过后对无marker的legacy exact leaf进行一次adoption；不得据此
   adoption父目录、兄弟目录或非精确路径。
4. reset与重新安装用于消除上轮同名matrix/bitstream/config、compile、evidence和日志污染；
   package-owned `wave.fsdb`和shard属于该exact attempt leaf，必须随该leaf一起清除并由本次执行
   重新生成；不得因同名波形已存在而退出，也不得复用其SHA/mtime作为本轮证据。
   规则只保证顺序重复执行。相同package的并发执行不在本合同内，不得声称具有并发锁或事务
   隔离。
5. return必须遵守本节上一规则的per-execution唯一文件名并保留历史结果。若极端情况下本次
   唯一目标已存在，应fail closed且不得覆盖；这不等同于固定return名造成的常态重跑冲突。
6. final-ZIP门必须至少覆盖：首次只有real `install`、同包二次执行并清除stale cfg/run、
   foreign cfg/run兄弟项保留、ownership mismatch、目标file/symlink、tree内symlink/special、
   NDP根exact-set变化和唯一return命名。package功能资产未变时，numeric/config/workload/
   RTL收据按changed-surface复用；只fresh验证runtime layout、runner和return publisher。

本门映射`state_safety`与`return`，不降低actual input、runtime-D absent、natural terminal、
正式D、E4/E5或functional RTL授权门。

规则 ID：`CDA-SERVER-FINAL-ZIP-RULE-SELF-AUDIT-001`

测试包完成生成后、向主线报告 `PACKAGE_READY_NOT_RUN` 前，责任会话必须重新完整读取当时
current 的生成前索引、公共服务器包规则和目标算子专项规则，并以最终源测试包 ZIP/sidecar 为
对象执行一次独立交付前自检。生成前读过规则不能替代生成后的最终自检。

最终自检至少必须：

1. 在 package manifest/release report 中保存规则路径、current SHA-256、全部适用 rule
   ID 和 `current_match=true` 收据；`.agents/plan.md` 只作 mutable provenance，不作为
   永动追写门；
2. 由独立 validator 直接读取最终源测试包 ZIP、sidecar、最终 manifest、runner/runtime、
   return allowlist 与负控资产，禁止只信 builder 自报、解包目录或中间 validation；
3. 逐项核对本规则的完整重建、exact-set、bootstrap immutability、唯一入口、路径长度预算、
   runtime-D absent、默认问题定位、package-local HDL syntax/scope/name-resolution、
   observer 四向绑定、event qualification、canonical decision、动态联合门和 return
   allowlist；同时扫描 runner 不得含服务器既有
   RTL/TB/Makefile/filelist/Git/README/特定文件 SHA 的运行前门；不适用项必须给出明确理由；
4. 运行规则要求的所有定向负控，并保存命令、cwd、退出码、PASS/FAIL 与报告 SHA；
5. 若生成期间任何 active rule SHA 漂移，旧自检立即失效；责任会话必须复读新规则并对
   同一最终 ZIP 重新验证。若新规则要求改变 package payload、runner/runtime 行为、
   manifest 机器合同、负控或 return schema，旧包必须隔离并用新 identity 重建。
   若漂移经独立 validator 证明为内容中性——新规则对该包明确不适用，或最终 ZIP 已经
   逐项满足且无需改变任何包内字节/运行行为/验证资产——允许保留原 ZIP 身份并发布一份
   包外 `RULE_DRIFT_CONTENT_NEUTRAL_REVALIDATION_PASS` 收据，记录新旧规则 SHA、逐条适用性、
   final ZIP SHA、复验命令/退出码/报告 SHA。该收据不能修复实际缺失字段、验证器、负控
   或 runner 行为；任何一项需要改包时仍禁止仅追写 receipt 冒充通过。

只有 `FINAL_ZIP_RULE_SELF_AUDIT_PASS=true` 且 errors=0、所有必需负控 fail closed 时，
才能向主线交付路径/SHA/源测试包 sidecar/单命令。自检失败固定为
`PACKAGE_FINAL_RULE_SELF_AUDIT_FAILED`，不得上传、运行或称候选；必须先隔离并报告首个
失败 rule ID。主线接收包时再次机械核对该收据，缺失时不进入运行队列。

规则 ID：`CDA-SERVER-PACKAGE-BOOTSTRAP-IMMUTABILITY-001`

包内 Python runtime 在第一次 exact-set preflight 前不得改变 package tree。任何包内 Python 启动前必须同时：

- 在 shell 环境设置 `PYTHONDONTWRITEBYTECODE=1`；
- 在入口脚本导入其他包内模块前设置 `sys.dont_write_bytecode=True`；
- 从全新解压 ZIP 调用真实 `PREPARE_AND_RUN.sh`/runtime 入口，并核对执行前后 package
  tree 的 exact-set、size 和 SHA-256 完全不变。

不得把 `__pycache__/` 或 `.pyc` 加入 manifest/忽略列表来绕过此门；bootstrap 自生文件导致的 exact-set 失败分类为 `SERVER_TEST_INFRASTRUCTURE_PACKAGE_PREFLIGHT_FAILURE`，若 compile/install/sim 均未开始，则不计动态 attempt 或 E4/E5。

## 4. 唯一服务器入口
规则 ID：`CDA-SERVER-ONE-COMMAND-001`
用户操作最好一条、最多三行。默认唯一命令：
```bash
bash PREPARE_AND_RUN.sh /absolute/path/to/NDP_copyXX
```
入口脚本自行完成：
```text
参数/包身份预检 → pre-install 身份 → 全新 namespace 安装 → post-install 身份与 exact-set 校验
→ 全新隔离 RUN_DIR compile/sim → 结果分析 → post-run 身份 → allowlist return → return ZIP/sidecar 自检
```
其中package-owned安装与运行namespace必须服从
`CDA-SERVER-INSTALL-SUBTREE-RUNTIME-LAYOUT-001`；fixed simresult只承担最终原子return发布。

规则 ID：`CDA-SERVER-RUNNER-PREFLIGHT-TO-COMPILE-POSITIVE-CONTROL-001`

最终 ZIP 交付前，独立自检不得只分别验证 package preflight、installed preflight、
observer/辅助文件静态身份和 compile 参数文本。必须从 fresh extract 调用最终
`PREPARE_AND_RUN.sh` 的真实控制流，并用不会调用真实 VCS/仿真的安全 compile stub 做一次
正向启动链验证，证明 runner 按顺序：

1. 通过 package preflight；
2. 完成 fresh namespace 安装并通过 installed preflight；
3. 通过全部 precompile/observer/辅助文件 identity guard；
4. 实际到达 compile 调用点，并保存 compile stub 的唯一预期退出码与 actual compile argv；
5. compile stub 退出后实际走完 `EXIT` trap/finalizer，生成 manifest 声明的全部必需
   finalizer/return 产物，并证明 stderr 不含 `unbound variable` 或其他 shell diagnostic。
   若包声明 `HUP/INT/TERM` 与 `EXIT` 共用 finalizer，还必须以安全 signal-stub 证明该
   共用路径不会因变量作用域、未初始化状态或二次 trap 而中断。

同时至少执行一个错误 package-local identity/SHA 负控，证明它在 compile 前 fail closed。
这里的 identity 只指最终 ZIP、manifest、安装 payload、package-local observer/辅助文件，
不得把服务器功能 RTL 与本地 expected RTL 的差异纳入该 compile 前阻断负控。正控未到达
compile、guard 的 expected/actual SHA 不一致、guard 输出被重定向后静默退出，或只能从
脚本文本推断“应该到达”，均固定分类为
`PACKAGE_RUNNER_PREFLIGHT_TO_COMPILE_CHAIN_UNPROVEN`，不得报告 `PACKAGE_READY_NOT_RUN`。
只匹配 compile stub 的预期退出码或只证明 make/compile reachability，不足以证明正控；
缺任一声明的 finalizer artifact、finalizer stderr 含 shell diagnostic 或 trap 提前终止，
同样固定为 `PACKAGE_RUNNER_PREFLIGHT_TO_COMPILE_CHAIN_UNPROVEN`。
安全 stub 正控只证明包内 runner 控制流和 guard 绑定，不替代服务器上的真实
compile/elaboration，也不得据此升级 E3/E4/E5。

规则 ID：`CDA-SERVER-RUNNER-SET-U-DEFINITION-BEFORE-USE-001`

凡最终 runner 使用 `set -u`、`set -o nounset` 或等价严格未定义变量模式，所有
package-owned 变量都必须在其任何可达展开之前完成明确赋值或带默认值的安全初始化。该门
必须作用于 exact final `PREPARE_AND_RUN.sh`，不能只检查模板、helper 或把 compile 换成
安全 stub 后恰好未经过的分支。

1. 构包前廉价聚合检查必须枚举 normal、preflight-fail、compile-fail、`EXIT/HUP/INT/TERM`
   和 finalizer 路径中 package-owned 变量的首次定义与首次展开；首次不安全展开早于定义时
   映射 `server_start` 并阻断；
2. `${name:-default}`、`${name:=default}` 等确实能在 nounset 下安全求值的形式可作为显式
   默认值，但普通 `$name`、`${name}`、数组/路径拼接和函数实参不能据此豁免；
3. exact-runner 正控必须在只提供规则声明的最小服务器根时通过启动链并到达 compile stub；
   负控至少包含 `derived_log="$run_root/..."` 早于 `run_root=...`、只在后续函数内赋值、
   signal/finalizer 分支引用尚未建立的 attempt 变量；
4. validator 一次报告全部 definition-before-use 问题，不允许每修一个变量就重新压缩一次包。

冻结反例为 QLinearAdd v57d：runner 在第 18 行展开 `run_root` 构造日志路径，而该变量到第
31/181 行才赋值；`set -u` 使脚本在 package preflight、compile 和 simulation 前退出。该类
失败固定为 `PACKAGE_LOCAL_RUNNER_UNBOUND_VARIABLE_BEFORE_START`，不是 DUT、config、numeric
或服务器环境问题。

规则 ID：`CDA-SERVER-COMPILEFAIL-CORE-RETURN-ROOT-CAUSE-001`

production compile 可能非零退出的每个 next-fresh 包，都必须在首次调用 compile 之前，把
以下证据写入不依赖尚未建立 attempt/run root 的 bootstrap-safe return 区域，并由 core
finalizer 在 compile 失败时限量收回：

- exact compile argv（含 cwd、filelist/Make 目标和 package-local include/define），且必须从真正传给
  process spawn 的同一个 machine object生成，不得由family脚本重抄环境常量；
- 实际选择的 compile source/filelist 身份及可得的 path/bytes/SHA；
- compile exit code；
- `compile_driver.log` 的有界 head、tail 与机器提取的 first-error；first-error选择必须优先真实
  compiler `Error-*`、`Fatal-*`、syntax/unresolved diagnostic，禁止把更早的platform support prose
  或普通warning当成首错；
- 已完成的 root/layout/preflight receipt，以及缺失 `sim.log` 是 compile 未成功的下游结果。

上述 core evidence 必须在 optional plugin、run-root discovery 和结果分析之前进入 return
allowlist。即使 attempt 目录尚未创建、compile 自身返回 2、plugin 失败或 signal 到达，
finalizer 也必须发布原子 partial return；不得只留下 `compile=2` 与“sim.log 缺失”。日志
必须限量，默认不超过 manifest 声明的 head/tail/first-error 预算，既保留根因又不把完整
compile 树拖入返回包。

compile-not-started core至少必须包含actual compile/sim argv、simulation-started=false/exit sentinel、
compile exit+first true error、root/layout/preflight receipt及枚举上述exact returned member set和逐文件
bytes/SHA的core manifest。实际runner/compile log为全零wave dump时，任何手写收据仍声明
`DUMP_FSDB=1`等不一致值固定为`PACKAGE_LOCAL_COMPILE_CORE_ARGV_RECEIPT_STALE`；缺上述任一必需
member或manifest不能闭合exact-set时固定为`PACKAGE_LOCAL_COMPILE_FAIL_RETURN_CORE_INCOMPLETE`。

构包前同一个聚合 validator 必须同时检查 exact runner、core contract 和 return allowlist；
最终 ZIP 只复核一次 exact bytes。负控至少覆盖：compile argv 未落盘、source identity 缺失、
日志仅写入 attempt root、return 漏收 first-error、attempt root 不存在以及 compile exit 2。
任一失败分别映射 `server_start` 或 `return`，分类为
`PACKAGE_LOCAL_COMPILEFAIL_ROOT_CAUSE_EVIDENCE_INCOMPLETE`；额外格式、完整日志、可选统计仍为
`record_only`。本门不要求包预判真实 compiler 错误，也不把本地 safe compile stub 当作
production compile 成功证据。

冻结反例：native Conv p38 与 serialized Conv v84b 均只证明 compile stage exit 2；前者只
发布 3-member bootstrap partial return，后者虽然把输出重定向到
`compile/sim_results/compile_driver.log`，正式 return 仍缺 actual argv、source identity 与
first-error，因而一轮服务器结果无法裁决 compile 根因。native Conv p45进一步冻结两类实现逃逸：
其实际runner/compile log关闭全部wave dump，但返回argv收据写成`DUMP_FSDB=1`；同时缺
`ACTUAL_COMPILE_SIM_ARGV.json`、`SIM_EXIT_RECEIPT.json`、`COMPILE_CORE.json`及可闭合的core
manifest。GAP v60冻结“platform prose早于URMI”负控。

本两门共享机器实现固定为：

- `schemas/server_runner_return_resilience_v1.schema.json`
- `tools/validate_server_runner_return_resilience.py`
- `fixtures/server_runner_return_resilience_v1/`
- `tests/test_server_runner_return_resilience.py`

它们从发布后的 next-fresh 开始适用，不追溯重建正在运行、已返回或已经通过旧 epoch release
的包；但任何按新规则生成的第一份包必须执行独立 first-fresh exact-ZIP 复核。

规则 ID：`CDA-SERVER-USER-SUPPLIED-ROOT-NO-SOURCE-PREFLIGHT-001`
普通测试包默认采用本 profile：只接收一个用户提供的绝对根路径，不限制 basename；
禁止读取、遍历、哈希或比较服务器现有 `rtl/`、
Makefile、filelist、TB、support file、Git、README、全树身份及历史 SHA，也不逐项探测
固定服务器文件。实际 compile 缺入口或不兼容时自然失败并保存限量日志。包自身
manifest/exact-set/SHA、workload、SCA/SCA_D、golden、全新 namespace、绝对路径和
path traversal 仍须验证。服务器源码身份未绑定必须在结果中明确标注；它限制版本归属和
production release 声明，但不得阻止 compile/run 或抹除正式 D readback 所证明的本次
动态正确/错误事实。
不得把复杂参数、手工安装、日志筛选、readback 收集或压缩转嫁给用户。脚本必须拒绝：
- 非绝对、不可解析或不可进入的用户服务器根；
- 缺失或类型错误的预存`install`目录；`install/cfg_pkg`、`install/codex_runs`缺失不是
  用户错误，必须由package共享helper安全补建；但它们若为file/symlink，以及已存在的本包
  `install/cfg_pkg/<install_name>`或
  `install/codex_runs/<package>/<attempt>` fresh子目录；
- 不匹配的 package/manifest/self hash；
- 缺失运行命令、package-local SCA/payload；
- 路径越界、symlink 逃逸或从错误 cwd 解析的 workload 路径。

规则 ID：`CDA-SERVER-CLOUD-GITHUB-RTL-AUTHORITY-NONBLOCKING-DIFF-001`

服务器功能 RTL 的权威版本来源是用户指定的云端 GitHub 仓库及其当前批准
branch/commit，不是测试包生成时的本地 checkout、`repos.lock.json`、旧包 expected SHA，
也不是服务器目录中无法追溯到 GitHub 的孤立字节。普通测试包应直接使用服务器已安装 RTL
进入真实 compile/run；本地与服务器 RTL 身份不同本身不是禁止上机、终止 runner 或丢弃
动态结果的条件。

1. runner 可以在真实 compile 后收集实际参与编译的关键 RTL 路径、size/SHA 和 filelist
   收据，但该收集必须是 **非阻断** 的；只要 compile/elaboration 成功，就必须继续启动
   simulator。禁止在第一条 simulator 命令前因 `actual_sha != local_expected_sha` 退出；
2. return 发现身份差异时，分析 owner 必须优先读取云端 GitHub 当前批准 branch head，
   保存 repository/branch/commit，并比较本地 expected commit→云端 commit 的真实 changed
   files/commits。不得先把差异分类为服务器污染、未知 RTL、基础设施失败或要求重跑旧包；
3. 差异必须按 **实际受影响模块及算子消费路径** 分类：
   - 与当前算子 causal cone 无关：当前动态结果正常消费；差异仅作版本收据，不阻断该算子；
   - 影响当前算子：本次 compile/run/readback 仍继续并按 actual/cloud identity 解释；立即
     通知对应算子 owner，后续 package/config/observer 在本地同步云端版本后重新做受影响门；
   - 影响其它算子族：不阻断当前算子，同时主动通知那些算子 owner 做定向影响审计；
4. 只有 actual compile 自身不兼容、云端变更导致目标 package 的 XMR/ABI/config 无法执行，
   或真实仿真/结果门失败，才可终止并生成 successor。仅“3/8 SHA 不同”“本地 Git 历史无此
   blob”或“expected commit较旧”都不是终止理由；
5. 云端仓库暂时无法访问时，仍不得只因身份未解析而阻止 compile/run；return 标记
   `CLOUD_RTL_IMPACT_REVIEW_PENDING`，保留全部动态证据，待恢复访问后补做影响分类。未绑定
   云端 commit 时不得声称跨版本 E4/E5，但 E3、readback事实和首分歧仍可消费；
6. package manifest/release report 应把本地 expected RTL 记为 provenance hint，而不是
   runtime success predicate。final-ZIP 正控必须包含：compile成功、模拟的服务器叶SHA与
   本地expected不同、runner仍到达一次安全 simulator stub；负控必须证明package-local
   observer/manifest错误仍会在compile前fail closed，二者不得混淆；
7. 云端变更影响全网公共数据路时，主线负责一次性通知全部相关算子 owner，并更新本地 RTL
   基线；各owner只重验自身受影响的配置、observer和动态边界，不得无差别重做全部numeric、
   W3、golden或已冻结无关资产。

本规则不允许忽略真实 compile/runtime 错误，也不允许用云端“最新”字样替代精确 commit 和
差异审计；它只禁止把正常的持续硬件开发版本差异误作服务器测试的仿真前停止门。

## 5. SCA、SCA_D、execplan 和 payload
规则 ID：`CDA-SCA-D-TB-READBACK-LENGTH-001`
1. SCA 必须是当前 TB 逐行 loader 可读的 pretty JSON。现场压成单行、重排成 loader
   不识别结构或手填计数均禁止。
2. `Exec_Base`、`Exec_Length` 和 `Repeat_Num` 必须由本轮 execplan 派生；
   `Repeat_Num` 精确等于实际 `Start_Comp` 数量。
3. SCA/SCA_D 引用必须位于本轮 workload/install 命名空间，且从服务器
   `NDP_copyXX` 工作目录解析正确；读取类matrix/bitstream路径必须逐项解析到
   `$server_root/install/cfg_pkg/<install_name>`中的actual installed bytes，运行输出类
   路径必须解析到本轮`install/codex_runs/<package>/<attempt>`子树。
4. 每个 SCA_D 条目必须精确包含 `base_addr`、`path`、`length`；`length` 单位是
   128-bit word。缺失、类型错误、目标预先存在或目标越界均 fail closed。
5. 128-bit 文本 ABI：每行恰好 128 个 `0/1` 字符并以 LF 结束；禁止 CRLF、短行和额外空行。若出现 X/Z，须分报 binary-known、X/Z 行数与首行位置，分类为正式 D 部分未知/未覆盖，禁止用 `line_count=0` 或 parser failure 隐去覆盖事实。
6. 运行 argv 必须显式同时绑定：

   ```text
   +SCA_CFG=<本轮>/sca_cfg.json
   +SCA_CFG_D=<本轮>/sca_cfg_D.json
   ```

   两者必须属于同一 package。不得依赖或伪造 `sca_cfg_D_softmax.json` 默认回退。
7. 仿真启动后立即核对两条 `Using SCA cfg ... file` 回显、preload 数量和 D dump 数量。
   出现 `Cannot open`、`skip matrix readback`、错误 package 或 softmax 回退时立即失败。

规则 ID：`CDA-SERVER-RUNTIME-READBACK-TARGET-ABSENT-001`

正式 readback 的运行时目标路径必须与输入/preload/golden 命名空间隔离，并在以下两个
时间点证明不存在：

1. 最终 ZIP exact-set preflight；
2. 安装完成、simulation 启动前的 post-install preflight。

`readback_checks.runtime_path`、SCA_D dump target 或其等价目标不得随包预置，也不得由
安装步骤从 golden、参考输出或历史 run 复制。golden 必须位于独立只读 validation
命名空间；运行时只能由本轮 simulator/DUT 产生正式 readback。若目标在 simulation 前
已存在，立即分类为 `PACKAGE_PRESEEDED_READBACK_TARGET` 并 fail closed；即使其内容与
golden 逐 bit 相同，也不得计作动态 readback、E3、E4 或 E5。

## 6. stock RTL、TB 和 observer

默认规则：包内功能 RTL 文件数为 0，且不得创建、覆盖、patch、安装、恢复或以软链接/
临时副本替换服务器 `rtl/` 中任何文件。普通 profile 默认禁止采集或预检服务器实际
Make、TB、filelist、RTL tree、Git 与 focused RTL identity；直接进入真实 compile。
服务器源码身份审计是用户明确要求时才执行的独立可选任务，不得隐式并入每个算子包的
运行前门。

`rtl/` 外的 TB/observer 只有同时满足以下条件才允许：

- 用户任务确需、目标信号和 evidence budget 已声明；
- 只读，不驱动 DUT，不改变激励、反压、时序、完成或 timeout；
- preimage、安装 diff、post-run/final 身份逐文件记录；
- 新 compile 身份，不复用旧 simv；
- 优先将只读 observer 保持为 package-local source，并从隔离 `RUN_DIR` 显式传入其
  package-local include 目录；其路径和 SHA 在本地 final ZIP 及 package 安装 payload
  内按 manifest 验证，不要求服务器预先存在同名文件；
- 若用户明确授权事务式安装/修改服务器 TB，才按第 6 节专项目标规则校验该唯一目标；
  未授权时不得探测或要求服务器 TB/observer 文件。

若用户明确授权事务式修改服务器 TB/observer，身份收据只覆盖 package 实际安装/恢复的
唯一目标以保证原字节恢复；不得扫描、哈希或裁决其他服务器文件，也不得把收据当服务器
版本/RTL 身份。普通 package-local observer 不产生服务器既有文件 preimage 门。

规则 ID：`CDA-SERVER-TB-TARGET-DIRECTORY-ISOLATION-001`

若本轮获准修改、安装或恢复 TB，只能操作用户在唯一服务器命令中显式传入的 `NDP_copyXX`（本轮粘贴/目标目录）内、由 manifest 相对路径绑定的那一个 TB：

- 对命令参数和目标做 `realpath`/等价规范化；目标须严格位于该根内且等于 `<target_root>/<manifest_tb_relative_path>`。禁止用 basename、递归搜索、glob、`find`、`rglob` 或“第一个同名文件”选写入目标；
- 其他目录的同名 TB（本地参考副本、另一 `NDP_copyXX`、安装目录、`RUN_DIR`、归档或历史包）均不得修改、覆盖、备份后替换或恢复；
- 写入前收据记录目标根、唯一规范化路径和 preimage size/SHA-256，并证明候选写入路径数恰为 1；越界、歧义、symlink/junction 逃逸或路径不一致立即 fail closed；
- post-install、post-run、post-restore 只核验并恢复同一路径；对目标 TB 的授权不得外推给任何同名文件。

规则 ID：`CDA-SERVER-OBSERVER-XMR-ELABORATION-CONSTANT-001`

observer 对生成层级做 cross-module reference 时，实例数组的每一级下标都必须在 elaboration 阶段可确定：使用字面量，或在包围该引用的 `generate` 块中使用 `genvar`。禁止在 `always`/`initial` 等过程块里用运行期 `int sid/ch/lane` 作为 `slice_group_gen[sid]`、`MSE_INST[ch]` 一类实例路径下标；信号本身的 unpacked/packed 数组运行期索引不受此限制。

服务器交接前的单次完整自检必须扫描最终拼接后的 observer，而不是只验证尾文件存在、SHA 和安装/恢复成功。发现运行期实例路径下标立即停止封包；不得依赖 `-v2k_generate` 等编译器兼容开关代替 elaboration 常量。实际服务器编译仍是最终编译证据；若因此在仿真启动前编译失败，分类为服务器测试基础设施失败，不计动态 attempt，也不得从零条 checkpoint/write/readback 推断算子、配置或 RTL 语义。

规则 ID：`CDA-SERVER-PACKAGE-LOCAL-OBSERVER-HDL-SYNTAX-SCOPE-POSITIVE-001`

任何最终 ZIP 只要把 package-local `.sv/.svh/.v/.vh`、TB、observer、generated include
或其它 HDL support member 传入服务器 compile，就必须在标记
`PACKAGE_READY_NOT_RUN` 前，对 **fresh extract 后最终 ZIP 内的 exact bytes** 完成独立
syntax、scope/name-resolution 和必需诊断状态所有权正控。builder 模板、中间拼接目录、
旧 extract、token presence 或 generator 自报均不是验收对象。沿用 manifest/files 与
observer 四向绑定规则，精确绑定全部 package-local HDL member 的相对路径、大小/SHA
和实际 include/macro profile；本门不要求为了审计另加包内 inventory/contract，也不要求
在 manifest 穷举全部 observer state leaves。syntax/scope 收据和本轮必需 evidence leaf
ownership 可以保存在包外 final-audit/revalidation report，只要它绑定 exact ZIP/member
SHA 且服务器运行不依赖该外部报告。

本规则的实现还必须包含同一份 machine-readable **保留字声明名廉价硬门**。builder 在昂贵
压缩和 finalizer 前对完整 staging package root 的全部 `.sv/.svh/.v/.vh` 一次聚合扫描；
归档完成后，final-ZIP validator 再从 exact ZIP bytes 独立重算一次。两次都必须输出全部
命中而不是遇到首错停止，且 `reserved_identifier_violations=[]` 才能继续。扫描必须排除注释、
字符串和合法 escaped identifier，但必须拒绝把 SystemVerilog/Verilog 保留字用作普通
declaration/port/named-construct identifier；serialized Conv FSDB smoke s1 的
`integer sequence;` 是永久负控，修正后的 `integer event_seq_id;` 是正控。本廉价门只提前
阻断确定会影响 `server_start` 的错误；它不能替代下述 exact frontend、scope/name-resolution、
状态所有权和三类负控。staging 通过而 final ZIP 不通过时，以 final ZIP 为准并禁止发布；
工具缺失、未执行、报告身份未绑定 current staging/final ZIP 或两者结果漂移时同样 fail closed。
共享入口固定为 `tools/validate_server_package_local_hdl_lexical.py`、
`schemas/server_package_local_hdl_lexical_validation_v1.schema.json` 和
`contracts/server_package_local_hdl_lexical_gate_dispatch_v1.json`。

正控按以下顺序执行：

1. 若本地具备 production frontend 及完整依赖，使用实际 compile macro/include 顺序对
   exact package-local HDL 和所需依赖执行 syntax/elaboration/name-resolution；
2. 若完整 VCS/vendor/DUT 依赖本地不可用，允许使用兼容 SystemVerilog frontend 的
   focused harness，但必须同时满足：
   - frontend 实际解析/elaborate 本轮新增或修改的 declaration、reset/initialization、
     qualified update/assignment 和 consumer use；不得把目标语句改写成只含同名 token
     的替代实现；
   - 对 exact final HDL 中 **本轮新增/修改，或进入本轮必需 canonical/result
     decision 的 package-local identifier/state leaf** 另行机器推导 scoped closure：
     按角色闭合 declaration、兼容类型、需要时的 reset/初始化、qualified update/
     assignment 和 consumer use。未参与本轮必需裁决、未改动的历史 observer 状态不
     要求穷举；外部 DUT/XMR leaf、宏、system task/type 必须分类，不得误报为
     package-local unresolved；
   - focused wrapper/stub 只允许提供外部 DUT 层级、端口、类型、宏和 vendor primitive，
     不得声明、修复或覆盖 package-local 目标 identifier。frontend 不支持而必须对无关
     runtime selector/外部层级做 specialization 时，报告必须逐项记录原 span/hash、
     specialization、理由和影响边界，并证明本轮目标 declaration/update/use 未被替换；
3. 独立 final-ZIP validator 必须从最终 ZIP 重新计算上述 scoped closure，不能只消费
   builder 生成的“expected identifiers”列表。generator 内的同类检查只作早期预防，
   不能替代最终放行门；
4. 收据必须记录 frontend 名称/版本、命令、cwd、退出码、所有 exact member SHA、
   include/concatenation 顺序、focused wrapper/harness SHA、允许的 specialization、
   machine-closure 统计和明确 claim boundary。兼容前端通过只证明其覆盖的 package-local
   HDL 语法/名字闭合；服务器 production VCS 仍是全设计最终 compile/elaboration 证据；
5. 对本轮新增/修改或进入必需裁决的 leaf，至少执行以下三类独立负控，并由同一
   final-ZIP release validator fail closed：
   - 删除一个本轮必需 declaration；
   - 拼错一个真实必需 consumer use；
   - 删除一个影响本轮必需诊断的 reset/initialization 或 qualified state update。
   第三类即使仍可通过 HDL syntax，也必须由状态所有权/semantic closure 拒绝。若本轮
   HDL 没有 stateful leaf，必须给出机器可核验的 `not-applicable`，并改用删除必需
   continuous assignment/连接的等价负控；不得静默省略。

`RULE_DRIFT_CONTENT_NEUTRAL_REVALIDATION_PASS` 并恢复运行资格；任一失败或需要修改

fresh identity 重建；仅缺包外审计报告或非运行依赖的 inventory 时允许在 exact ZIP 不变

simulation 前命中本轮 package-local scoped 正控本应发现的 syntax/scope 错误，分类为

功能 RTL。缺失服务器专有依赖、production-only elaboration 差异或服务器现有源码错误，
仍按真实 compile 自然失败处理，不得倒逼增加服务器侧预检。

规则 ID：`CDA-SERVER-HDL-SCOPE-NEGATIVE-MUST-TARGET-ACTUAL-CONSUMER-001`

`CDA-SERVER-PACKAGE-LOCAL-OBSERVER-HDL-SYNTAX-SCOPE-POSITIVE-001` 的 scoped closure
和 consumer 拼写负控必须从 **fresh extract 后最终 ZIP 中实际进入 compile 的 exact HDL
消费者表达式** 推导，不得从 builder 的 expected-identifier inventory、生成器模板、
mock/focused wrapper 中的人造同名 use 或手写“应当存在”清单反推验收范围。适用范围只限
本轮新增/修改或进入本轮必需 canonical/result/progress/return 裁决的 package-local
diagnostic identifier/state leaf；不要求本地完成全设计 production elaboration，也不要求
穷举与本轮裁决无关的历史 observer 状态。

final-ZIP validator 必须：

1. 从实际 include/concatenation 顺序解析 exact final HDL，枚举范围内每个 consumer
   expression 的 member path、source span/line、expression SHA、被消费 identifier、
   预期 declaration/owner role，并将外部 DUT/XMR leaf、宏、system task/type 与
   package-local name 分开分类；
2. 对每个实际 consumer expression 验证其 package-local identifier 解析到 exact final
   declaration，且需要状态所有权时同时闭合 reset/initialization、qualified update/
   assignment 与 consumer；任一实际 consumer 未纳入枚举、unresolved、ownerless 或
   被 focused wrapper 补声明，立即 fail closed；
3. consumer 拼写负控必须直接复制该实际 source span 后只变异目标 identifier token。
   每个范围内实际 consumer expression 都必须被直接负控覆盖，或归入机器证明具有相同
   declaration/owner/解析路径的等价覆盖类并由该类中的实际 expression 变异覆盖；禁止
   变异未进入 compile 的 mock、expected inventory 或未被消费的占位 token；
4. 在负控变体上重跑与正控相同的 frontend/scoped semantic closure。变异后仍通过、
   负控没有触达实际 compiled member，或仅由正则“预期缺词”报错而未证明 name-resolution
   fail closed，均不得发布；
5. final audit 至少发布 actual-consumer 总数、逐表达式或等价类 coverage、uncovered=`0`、
   负控 source span/expression SHA、变异 token、frontend/semantic exit 与 exact ZIP/member
   SHA。该收据是本地放行证据，不增加服务器检查步骤。

本门的目标是把本地即可发现的 package-local 拼写/scope 错误挡在服务器之前；它不把
兼容 frontend 通过升级为 production full-design 证明，也不得因为服务器专有依赖在本地
不可用而过度拒绝能够正常进入服务器 compile 并暴露真实 DUT/工具差异的包。冻结反例：
GAP v36 的实际 consumer 使用 `return_obs_rd_spatial_mon`，而 expected inventory/其它
消费者只覆盖 `return_obs_rd_spatial_size_mon`；未从该实际 source span 推导 closure/负控，
使 compile 前可发现错误逃逸到服务器。此类结果固定为
`PACKAGE_LOCAL_DELIVERY_SELF_AUDIT_ESCAPE`，旧包隔离并使用 fresh identity 修正。

规则 ID：`CDA-SERVER-OBSERVER-PUBLIC-SURFACE-OR-XMR-PROOF-001`

package-local observer 对 DUT 的新增或修改引用，应优先使用同一证据含义的 module
port、interface、已导出的连接线或其它稳定公开表面。若公开表面已足以区分本轮候选根因，
不得为了读取便利把子模块 private reg/wire 作为进入仿真的必需 XMR；这类引用更容易因
production filelist、模块版本、generate 路径或可见性差异在真实 elaboration 前失败。

确实没有等价公开表面、且内部 leaf 对本轮判别矩阵不可替代时，final-ZIP 本地阻断门必须：

1. 从 exact observer 实际 consumer expression 枚举完整实例路径、目标 module、leaf、
   width/type、owner clock/reset、源文件路径与 SHA；不得只在 RTL tree 任意位置搜索同名
   token；
2. 使用 actual current 目标 module bytes 和实际层级/filelist 绑定证明 leaf 位于所引用的
   精确实例内且允许被当前 frontend 做跨模块解析。focused wrapper 可以 stub 祖先层级和
   无关端口，但不得声明、导出、移动或补造目标 private leaf；
3. 对“删除/改名目标 leaf”和“把实例路径改到同型错误 sibling”各执行一个负控；两者都必须
   在与正控相同的 scope/name-resolution 门 fail closed；
4. 若本地无法绑定 current 目标 module/filelist，private XMR 不得成为必需诊断项：应改用
   公开接口推导、降级为不参与 canonical/progress 的可选证据，或明确停止构包等待身份，
   不能把“服务器真实 compile 会发现”作为首选路径。

本门不要求本地运行 DUT 或全设计 production elaboration，也不增加服务器源码预检。它只
阻止本地可以通过公开接口规避、或 focused stub 人为放宽可见性的 XMR 交付错误。冻结反例：
native four-lane p5 的 focused 收据把
`u_Array_Request_Manager.buf2arm_valid_hold` 记为 hierarchy token 存在，但 production VCS
仍在仿真前报 XMRE；p6 用公开接口
`buf2arm_rvalid && !array2arm_bp_post` 表达相同 hold-set pressure，且不把该 level 计入
monotonic progress。规则发布前已冻结的 current 包不因格式本身追溯 hold；下一 fresh 包适用。

规则 ID：`CDA-SERVER-DIAGNOSTIC-PREDICATE-TRACE-UNIT-001`

新增或修改observer event qualifier、stage/terminal scope、progress counter、snapshot gate、
parser或canonical decision时，仅做syntax、token presence、declaration/use closure和一条
“正常事件”正控不足以发布。必须从 **final ZIP exact parser/collector逻辑与实际判据表达式**
生成本地、无DUT、低开销的事件序列trace单元测试，直接运行生产parser/canonical代码或与
exact表达式绑定的同源可执行函数；不得另写一个只返回预期答案的mock判据。

每个changed/required predicate至少覆盖：

1. 一个精确成立的正例，以及每个AND conjunct单独为假的近邻反例；
2. 边界前一周期、边界周期、边界后一周期，证明counter/reset/snapshot从正确epoch起算；
3. 协议允许同时发生的事件组合，例如push+pop、valid+ready、start+finish、写+读；不得
   默认这些事件互斥；
4. 持续高level、重复sample和无新transaction的窗口，证明level不会被逐cycle计为progress；
5. 跨stage inactive gap、reset/reconfigure或clock-domain ownership改变时的序列；
6. 最近一次同类服务器escape的最小raw trace。该trace必须在旧判据上重现错误，并在新判据
   上得到唯一正确结果；若本轮没有历史反例，保存`not_applicable`理由。

收据必须绑定final ZIP/parser/observer member SHA、predicate source span/expression SHA、
输入trace SHA、逐步期望/实际状态、退出码和claim boundary。允许按等价判据类合并测试，
但必须发布predicate总数、class数和uncovered=`0`。trace门只检查package-local诊断语义，
不要求真实DUT仿真、不替代formal D，也不增加服务器端检查。

冻结反例：

- QAdd跨stage计数只在active时更新，inactive gap后下一stage未重新编号；
- GAP/Conv把持续level当逐事务progress，或把snapshot挂在关闭的父feature下；
- Conv v40用`desc_pop && pre_count==1`表示final pop，在steady simultaneous
  push+pop时提前触发；正确边界还必须约束`!desc_push`并从下一周期起计。

这些都能由本地事件trace确定，若带到服务器固定为
`PACKAGE_LOCAL_DIAGNOSTIC_PREDICATE_SELF_AUDIT_ESCAPE`；不得用“真实编译已通过”或增加
服务器日志替代修正。与本轮observer/canonical无关的冻结predicate不重复跑全量trace，
只需byte-equality和current receipt。

规则 ID：`CDA-SERVER-DIAGNOSTIC-LOGGER-PARSER-EXACT-FORMAT-TRACE-001`

`CDA-SERVER-DIAGNOSTIC-PREDICATE-TRACE-UNIT-001`中的final-exact parser与事件判据绑定，
还必须覆盖其 **actual logger rendered bytes**。新增或修改任何参与canonical、progress、
首分歧或required return evidence的logger/parser对时，不能只用手写无填充字符串作正控；
必须从final ZIP exact logger格式表达式、实参类型/位宽/对齐规则生成记录，或直接消费由该
exact logger捕获的原始记录，再交给final exact parser。

1. 收据须同时绑定logger与parser的final ZIP member path/SHA、logger格式表达式source span、
   event token容器位宽/类型、对齐与padding规则、parser表达式source span，以及逐token
   rendered-record SHA；`%s/%0s`、packed-string宽度、右/左对齐、delimiter、LF/CRLF和转义
   均属于格式合同，不得由手写fixture隐去；
2. 合法闭合方式只有两种：parser直接消费exact rendered bytes，或先经过显式、确定且有界的
   normalization合同再送入parser。normalization必须声明精确位置、允许字符和最大长度，
   只改变格式padding而不改变token/payload/record边界；禁止无界`strip()`、全行空白折叠或
   把未知格式静默修成合法记录；
3. 每个必需event token至少一条exact logger正控；另须覆盖短token相对最长token产生的
   padding、无padding手写串、错误对齐、超宽padding、tab/NBSP/嵌入空白等变异。未由合同
   明确允许并规范化的变异必须fail closed；已声明的normalization必须证明raw→normalized→
   parsed token与payload逐项不变；
4. 机器报告须分别给出raw/rendered/normalized/parsed计数、逐token结果和mutation结果。
   只有exact renderer正控全部通过且uncovered token=`0`，该logger/parser格式面才能PASS；
   synthetic unpadded positive不能单独满足本门；
5. 本门只在logger/parser实际参与本轮canonical/progress/result裁决时映射`return`并阻断；
   可选、不参与裁决的诊断文本固定为`record_only`。失败分类为
   `PACKAGE_LOCAL_RETURN_EVIDENCE_FORMAT_COVERAGE_ESCAPE`，不得升级为DUT、CONFIG、numeric、
   RTL或硬件失败，也不替代natural terminal、正式D或E4/E5。

冻结反例：GAP v53的SystemVerilog logger以`event=%s`输出14字符容器；原始记录包含
`event=   FACTOR_EDGE`与`event=     HEARTBEAT`，package parser只接受`event=`后立即出现
token，导致raw分别为1/21而parsed为0/0；`QUALIFIED_EDGE`因刚好14字符仍可解析。旧自检
仅构造无padding字符串而误放行。共享永久正控必须重现14字符右对齐记录，legacy无
normalization parser为负控。v54已完成family-local修正并冻结，不因本公共门重建或替换。

共享机器合同固定为：

- `schemas/server_logger_parser_format_trace_v1.schema.json`
- `fixtures/server_logger_parser_format_v1/`
- `tools/validate_server_triggered_causal_observability.py validate-logger-parser-format`
- `tests/test_server_triggered_causal_observability.py`

规则 ID：`CDA-SERVER-DIAGNOSTIC-MULTICLASS-EDGE-NO-LOSS-001`

当一个observer在同一reporter sample中可能同时产生两个或更多required诊断edge class，且
通过priority arbiter只输出一个event label时，输出高优先级class不得静默确认、推进或抑制
未输出的低优先级class。`QUALIFIED_EDGE`、violation、factor、terminal或其它class的event
label、snapshot ownership与parser消费策略必须形成无丢失闭环。

合法实现至少满足以下两条路径之一：

1. **per-class pending/snapshot**：只有实际发出或明确排入有界pending queue的class才能推进
   自己的previous-state snapshot；未发出class保持pending，在后续sample仍可形成edge并被
   exact parser消费。允许同一sample输出多条不同class记录，但每类预算和顺序必须确定；
2. **monotonic sticky all-class parse**：如果priority emitter仍无条件推进全部snapshot，则
   每条exact record必须携带每个required class的同owner-clock、单调sticky state，exact
   parser必须不依赖当前event label地从每条记录消费全部required class。sticky恢复只提供
   class evidence，不得把violation/factor/state/heartbeat计入qualified progress。

final-ZIP trace门至少必须：

- 绑定exact observer/parser member SHA、arbiter与snapshot update source span、class priority、
  required/progress/sticky属性、每类独立预算和parser class-consumption表达式；
- 覆盖至少一个包含全部可同时成立required class的同sample改变；若协议不允许全类同现，
  则覆盖每个允许的同时组合；适用时还须覆盖高优先级预算已满而低优先级仍有余量，以及
  连续sticky稳定sample；
- 对每个sample发布changed classes、emitted/pending classes、snapshot before/after、parser
  consumed classes和progress delta；required class覆盖必须exact且uncovered=`0`；
- 负控必须包含“priority只发高类、却无条件推进所有snapshot、parser又只按event label消费”
  的历史机制，以及sticky回退、必需class字段缺失、把non-progress class计为progress；
- 本门只在相关class参与canonical/progress/first-divergence/required return时映射`return`
  阻断；纯可选诊断仍为`record_only`。失败分类为
  `PACKAGE_LOCAL_DIAGNOSTIC_MULTICLASS_EDGE_LOSS`，不得升级为DUT、CONFIG、numeric或RTL失败。

`VIOLATION_EDGE`下消费violation字段，故return evidence不完整。v54已经消费并进入

规则 ID：`CDA-SERVER-OBSERVER-EVIDENCE-DOMINANCE-001`

按数据通路排列多个只读 checkpoint 时，首分歧路由必须服从证据强弱，而不能在遇到
第一项零计数时立即停止：

- 若较早的可选 checkpoint 为 `raw=parsed=0`，但更下游边界已有完整、非零且逐 bit
  正确的 accepted/data 证据，则较早零计数只能登记为 observer-only gap，不得再称为
  功能首分歧；
- `LAST_PROVEN_GOOD` 必须取最下游的、语义边界明确且数据已核对的正证据；若其后若干
  checkpoint 未观测，而再下游边界已观测为全零或正式 D 错误，则结论只能是
  `LAST_PROVEN_GOOD → FIRST_UNOBSERVED → DOWNSTREAM_BAD` 的有界区间；
- 只有 `raw != parsed` 才优先判 parser divergence；零计数、部分覆盖、全零 payload
  必须继续保持三种不同证据状态；
- checkpoint 名称必须写清采样的是 input-side data/enable、寄存后 valid/data，还是
  accepted handshake。input-side enable 成立不能被改写成“寄存后数据已接受”；
 - 正式、唯一、未预置且完整覆盖的 D readback 继续独立裁决最终数值；observer 路由错误
  不得覆盖正式 D 的通过或失败。

规则 ID：`CDA-SERVER-OBSERVER-CAPTURE-EDGE-WITNESS-001`
posedge change-only observer 不能单独证明组合 valid/ready 在整个周期内从未断言。若 RTL 在使能条件下满足 `dst_valid <= src_valid`，且随后已经观测到寄存后的 `dst_valid=1`，则该下游寄存 witness 是 `src_valid` 在捕获边沿为真的正证据；同轮上游 change-only 日志为零只能登记为采样盲点，不得把首分歧退回上游。

需要裁决数值 payload 时，observer 必须在真实捕获使能下记录实际数据，或使用只读的 post-NBA/`$strobe`、shadow counter/FIFO、下游寄存值等能保留捕获事实的机制。仅把 opcode、enable、valid 等状态位拼成一个 `data` 字段，只能称为状态摘要，禁止当作数值 payload 或逐 bit golden 证据。

规则 ID：`CDA-SERVER-OBSERVER-EVENT-QUALIFICATION-001`
checkpoint 只有在 qualifier 已证明对每个真实接受/捕获事务恰好触发一次时，才允许绑定“预期事务数”并参与首分歧。`ready`、pipeline enable、comparator valid 等持续为高的 level 默认只是 observation sample，不是 transaction event：

- 优先用真实 consumer capture/handshake；没有单周期脉冲时，可用只读 rising/change witness、post-NBA/`$strobe`、shadow counter/FIFO 或有来源证明的稳定 transaction id 去重；
- 分栏记录 `raw_total`、`qualified_event_count`、`parseable_count`、`x_or_z/pre-valid_count`、`duplicate_sample_count`，不得用单一 raw/parsed 覆盖；
- 仅当全部 raw 都声明为完整 qualified event 而解析器漏读合法记录时，`raw != parsed` 才是 parser divergence；pre-valid、X/Z 或 level 重复采样须判 `OBSERVER_EVENT_QUALIFICATION_ERROR`，不得升级为 CONFIG、RTL 或硬件数值分歧；
 - 首分歧只消费 qualified event 与更下游 accepted/formal 证据；未限定 level sample 不得覆盖逐事务 bit-exact 正证据或重开已关闭边界。

规则 ID：`CDA-SERVER-GATED-DOMAIN-COUNTER-UNGATED-SNAPSHOT-001`

目标门控时钟域中的 qualified event counter 可以继续由其 source clock 所有，但诊断快照、
heartbeat 和 canonical progress record 必须由已证明在 Start_Comp 后持续存活的独立
observer clock 发出，并同时返回目标门控时钟的 qualified edge count/last-change witness。
禁止把另一个时钟域的 counter 直接拿到门控域中做 `% period == 0`、相等比较或唯一打印门：
门控时钟未启动、停止或跨域错过整点时，这会让整段诊断链静默，不能区分“功能链没有
进度”和“observer 没有采样”。

最终 ZIP 自检至少包含：

- source-domain qualified counter 前进、observer clock 持续时，快照可见；
- source-domain counter 不前进或门控时钟停止时，observer clock 仍按预算输出零增量与
  clock-edge 状态；
- 异域 modulo/equality 作为唯一 emitter 的负控必须 fail closed；
- snapshot 只读，不改变目标时钟、DUT ready/backpressure、timeout 或 qualified counter
  语义。

缺失时分类为 `PACKAGE_PROGRESS_DIAGNOSTIC_CLOCK_DOMAIN_BINDING_ERROR`，不得把零条内部链
日志升级为配置/RTL 根因，也不得仅延长 timeout。

规则 ID：`CDA-SERVER-DIAGNOSTIC-DECISION-CANONICAL-RECORD-001`

长任务 observer/runtime 只能向机器结果门发布一种 canonical decision record。该记录必须
同时含 schema/version、decision、`reason`、`boundary`、覆盖的 sample/window 范围、

  qualified transaction；
- summary-only 文本不得复用 canonical decision 的机器解析前缀。解析器必须按完整必需

  stage identity 配对每个 `EXEC_START` 与 `COMP_FINISH`。只有最后一个 expected stage
  自身完成且不存在其后的未完成 stage，才可发布 `natural_terminal=true`；任一早期
  `COMP_FINISH`、start/finish 数量不一致或后续 stage 已启动但未完成，均固定分类为
  `PACKAGE_DIAGNOSTIC_DECISION_FINAL_STAGE_SCOPE_ERROR`，不得把早期阶段完成升级为全任务
  natural terminal；
- 若存在两条以上 canonical 候选、字段冲突、`reason/boundary` 缺失或 summary 覆盖，

功能 RTL repair 是条件 profile，不是默认能力；见第 12 节。

### 7.1 分级波形单轮定位与本地可分析回传

规则 ID：`CDA-SERVER-TIERED-WAVEFORM-ONE-ROUND-LOCALIZATION-001`

波形是source-bound observer的补充诊断面，不是其替代。observer继续提供qualified event、
自然终态和正式D所需的确定性谓词；波形用于返回后追溯第一分歧和检查未预见机制。所有
next-fresh诊断包必须物化`server-waveform-observation-plan-v1`并按以下顺序选择模式：

1. **`TARGETED_CAUSAL_CONE`（首轮默认）**：覆盖候选判别矩阵需要的source、queue、consumer、
   internal match、output、terminal和formal-D边界，以exact hierarchy path和width列出信号；
   任意两个已知候选必须具有不同的实际波形signature。不得为追求小文件删除使候选重新同签名
   的边界。
2. **`ESCALATED_NEAR_FULL`（上一轮仍不能唯一定位）**：保留目标DUT及其上下游实际因果scope，
   只删除已有exact receipt证明与本轮输入、状态传播、输出和终态均无关的scope；每个删除项必须
   绑定证据SHA与理由。禁止沿用同一个不足的targeted计划后每轮只加一个信号。
3. **`FULL_HIERARCHY`（近全量仍不能保证一次区分）**：当层级未知、第一分歧不在既有catalog，
   或删除任一scope都会丢失候选完备性时，允许对声明TB top抓取全层级波形。`50%`只是不阻断
   的开销偏好；完成定位证据优先，但仍须限定本轮workload、起止条件、存储路径和exact预算。
4. **`NO_WAVE`（严格豁免）**：仅适用于不承担故障定位、已有相同动态身份通过且本轮只验证已知
   唯一根因修正的短包，或compile-only包；必须给出机器可审计理由。上一return为
   `INSUFFICIENT_DIAGNOSTIC_DISCRIMINATION`时不得使用。

每个非`NO_WAVE`计划还必须满足：

- exact final ZIP携带plan、共享工具、生成的UCLI、runner和post-sim return request；final-ZIP门
  从最终bytes复核`plan→dump commands→runner启用→raw/manifest/extracted三项required return`
  四向绑定。仅有`-debug_access+all/-kdb`或服务器上出现波形文件不等于完成该门；
- 当前next-fresh共享实现固定使用VCS/Verdi PLI生成package-owned attempt-local `.fsdb`：actual
  compile/sim argv必须精确绑定`DUMP_VCD=0 DUMP_FSDB=1 TB_DUMP_FSDB=0`，唯一写入路径为
  `$server_root/install/codex_runs/<package>/<attempt>/.../wave.fsdb`。禁止把NDP根已有的
  `inter.fsdb`/`novas.fsdb`或任意pre-existing文件冒充本次证据，也禁止testbench第二写入者；
  exact plan、runner、FSDB控制文件与final-ZIP门必须四向一致；
- `wave.fsdb`及全部实际shard必须作为显式required allowlist entries进入**同一正式return ZIP**，
  同时返回`WAVEFORM_RUNTIME_RECEIPT.json`和identity-bound的Verdi/WaveUtils查询收据或注册的完整
  signal-event收据。原始FSDB不得截断、采样或按大小删除；receipt绑定package/execution/plan、
  source path、bytes、SHA、format和complete/partial。查询/工具失败不得丢失raw FSDB或compile/
  sim/signal/core return，但必须标记`DIAGNOSTIC_EVIDENCE_INCOMPLETE`；自由文本不得冒充逐信号
  完整查询。历史VPD仅保留为旧return兼容输入，不再是next-fresh默认输出；
- 首个启用该实现的fresh包必须先做serialized Conv最小smoke，证明同一次attempt中compile/elaboration、
  time-0/progress marker、simulation time > 0、attempt-local FSDB、formal-return ZIP收集和本地查询
  收据均闭合；`simv exit 0`、空/header-only FSDB或根目录旧FSDB均不能通过。smoke正式return通过且
  本规则/共享门同步完成前，下一轮四个正式包不得发布；
- 波形预算使用计划声明的exact最大bytes并在返回后核验，不受普通16/32 MiB默认值硬截断。
  预算过小时在构包前调整计划；运行后超预算必须返回最小核心失败收据并保留原始文件供同一
  finalizer恢复，禁止静默截断、删除末段或用摘要冒充完整波形；
- 波形采集和抽取只能读取DUT，不得驱动input、ready/backpressure、clock/reset、timeout、
  terminal或workload；不得host replay内部tensor。波形有值不等于qualified transaction，
  不能单独提升natural terminal、正式D、E4/E5或授权RTL修改；
- 分级probe选择仍使用`schemas/server_waveform_observation_plan_v1.schema.json`与
  `tools/server_waveform_observation.py`；next-fresh raw FSDB回传门固定使用
  `schemas/server_waveform_mandatory_plan_v3.schema.json`、
  `schemas/server_waveform_runtime_receipt_v3.schema.json`、
  `contracts/server_waveform_mandatory_return_dispatch_v3.json`、
  `tools/server_waveform_mandatory_return.py`、`tools/server_post_sim_return.py`以及对应tests/fixtures。
  历史v2 VPD schema/tool入口只用于读取旧return，不得被新包选择。

阻断只映射到`server_start`、`actual_input`和`return`：计划/UCLI/runner没有实际启用请求波形、
原始波形或本地trace不能进入return、路径逃逸/覆盖服务器状态时blocking；估计slowdown、未知
vendor GUI可用性或纯展示字段只能`record_only`。该规则只约束next fresh，不追溯重建current包。

## 8. 外部信号和部分回传
规则 ID：`CDA-SERVER-SIGNAL-SAFE-PARTIAL-COLLECTION-001`
runner 必须区分 DUT 自然结束、仿真时间上限、runner timeout、`$fatal` 和外部
`SIGHUP/SIGINT/SIGTERM`。收到外部信号必须如实记录，不能在没有机制证据时直接写成
RTL 自行卡死；但这不解除下述“长时间卡死优先”调查门。

规则 ID：`CDA-SERVER-RETURN-TO-SUCCESSOR-CONTINUOUS-CLOSURE-001`

每一份通过外部传输入口提交给主线的正式 return，无论是自然完成、timeout/INT、compile
失败、formal D 缺失/错误、包诊断缺陷还是数值不匹配，都必须自动回到对应算子 owner，
在同一任务中完成 receipt-only 分析和 successor 裁决。不得把 return 只归档为
`ADJUDICATED / PACKAGE_RELEASE=NONE` 后等待用户再次授权本地生成。

1. 当前目标已经达到声明的 E4/E5/覆盖终点时可以 `CLOSED`；若目标还要求 E5，首次 E4
   通过后默认生成 fresh identity 独立重复包；
2. 根因已由同一 return、冻结 package/config/execplan/SCA、消费者或相关 RTL 唯一确定，
   且修复属于 config、runner、package-local observer、validator 或封包基础设施时，
   必须生成 fresh 修正包并重新证明所有受影响门；
3. 根因在穷尽只读证据后仍未唯一确定时，必须生成一个围绕
   `LAST_PROVEN_GOOD → FIRST_DIVERGENCE`、以最短 time-to-root-cause 和单次运行
   信息增益为优先的 fresh 精确诊断包；不得只提交 proposal，也不得机械拆成“一包只看
   一个信号”的串行试错；
4. 只有根因要求未授权的功能 RTL 修改、缺少真实硬件能力，或需要会实质改变任务功能
   范围/外部状态的用户选择时，才允许以 `WAIT_RTL_FIX`、
   `HARDWARE_CAPABILITY_BLOCKED` 或 `WAIT_USER_DECISION` 停止而不生成包；
5. 本地 successor 生成、确定性构建、final-ZIP 自检和安全 stub 正负控属于算子 owner
   默认权限；上传、服务器运行和功能 RTL repair 仍必须取得对应授权；
6. 历史源包、失败 return 和 extraction 永久只读。successor 必须使用全新
   package/install/run/return identity；对保留的 causal execution slice 冻结全部语义
   资产，对按下述规则裁掉的 stage/payload/readback/observer 则记录 exact keep/drop
   集合，不得用“冻结无关资产”强迫服务器继续执行无关工作。

owner 的结构化回传必须是 `PACKAGE_READY_NOT_RUN` 或上述明确终止状态之一。
`SUCCESSOR_PROPOSAL_OR_NONE` 只能说明设计选择，不能替代在默认权限范围内实际生成
successor。

规则 ID：`CDA-SERVER-DIAGNOSTIC-TIME-TO-ROOT-CAUSE-OPTIMIZATION-001`

诊断 successor 的优化目标是“用最少服务器墙钟唯一化根因”，不是“探针数量最少”、
“ZIP 最小”或“一次只推进一个叶子”。构包时必须同时执行：

1. 从 current return 列出仍存候选根因及其可区分事件，形成候选×观测结果判别矩阵；
   在 observer/log/compile 预算内能一次区分的低开销 qualified/edge 事件必须合并到
   同一包，不得为了形式上的“最窄”拆成多轮串行试错；
2. 建立复现 `LAST_PROVEN_GOOD → FIRST_DIVERGENCE` 的 causal execution slice。
   只保留到首分歧及其直接 consumer 所需的最短合法 stage prefix、slice、输入、地址、
   barrier 和生命周期；允许删除首分歧之后或与候选判别无关的 stage、formal readback、
   payload、observer、输出与返回项；
3. 独立 stage 的边界输入只能来自 graph external typed input、已验证硬件 checkpoint，
   或专项规则明确批准的冻结诊断 stimulus。没有合法逐字节边界合同就使用最短累计 prefix；
   禁止 host 预计算、回放或伪造 DUT 应生成的内部 tensor；
4. 裁剪不得改变 causal slice 内首分歧之前的 config、地址、请求顺序、ready/backpressure、
   时序、barrier、lifetime 或数据值。若候选根因依赖全链资源占用或跨 stage 遗留状态，
   对应前缀/状态必须保留，不能用裁剪消除待测现象；
5. manifest/machine report 必须声明 `diagnostic_execution_reduction`：kept/dropped
   exact-set、每项因果理由、边界输入来源、预期 stage/payload/墙钟缩减、判别矩阵和
   claim boundary。负控至少删除一个必需前缀/边界或篡改边界来源，并证明 fail closed；
6. 裁剪包固定为 `DIAGNOSTIC_ONLY_NOT_FUNCTIONAL_FIX`，只可关闭判别边界；最终 E4/E5
   仍需完整目标 stage/full-chain、正式 D 与自然终态。根因关闭后的修正包可复用同一
   加速诊断 slice 做快速正控，但不能替代后续完整回归；
7. 若裁剪不会实质减少执行量或会破坏复现条件，允许保留完整 workload，但必须在报告中
   给出不可裁剪证据；“沿用旧包方便”“所有资产已冻结”或“最窄探针”均不是理由。

规则 ID：`CDA-SERVER-PACKAGE-OR-RETURN-OWNER-COMPLETION-NOTIFY-RULE-FEEDBACK-001`

服务器包实际运行期间不要求主线或算子 owner 持续轮询、盯守或占用会话；用户提交正式
return 后，主线才按本节把它分发给对应持久 owner。本地服务器包生成任务与正式 return
分析任务的分发单都必须写入：

1. 派发时主线会话 ID（历史 provenance）、当前 owner `role_id/thread_id/owner_epoch`，以及
   `contracts/current_session_owner_registry_v1.json`的活动 receipt；
2. package owner 达到 `PACKAGE_READY_NOT_RUN` 或明确终止状态后、return owner 完成
   RETURN→successor 闭环后，都必须先执行`tools/session_handoff.py resolve-mainline`或等价
   exact registry解析，再主动向解析出的唯一current mainline发送完成通知；分支 UI 状态、磁盘产物
   或主线自行轮询发现结果均不能替代通知；
3. package 完成通知必须包含 `PACKAGE_RELEASE`、ZIP/sidecar 路径/bytes/SHA、唯一命令、
   预期 return、final-ZIP 自检、`BLOCKER_DELTA` 或明确终止状态；return 完成通知必须
   进一步包含 `RETURN_ANALYSIS`、`LAST_PROVEN_GOOD`、`FIRST_DIVERGENCE` 和
   `HANG_ROOT_CAUSE`。两类通知都必须包含下述规则反馈。

通知必须同时写明`dispatched_mainline_thread_id`、`resolved_mainline_thread_id`、
`registry_epoch_at_send`和owner的`role_id/thread_id/owner_epoch`。旧派发单、旧task record或
package-local脚本中的主线ID只作provenance；主线已经换代时不得继续向退休主线提交正式结论。
若owner自身已经换代，旧owner只能把迟到的原始return/用户消息转交current owner，不得继续
分析、生成successor或写本族资产。registry缺失或校验失败固定为
`SESSION_OWNER_POINTER_UNAVAILABLE`并停止正式回传，不得猜ID；完整语义见
`.agents/rules/会话转接与所有权规则.md`。

规则反馈必须二选一且有证据：

- `RULE_DELTA_PROPOSAL`：错误经验、audit escape、成功路径或新反例证明 current
  公共/专项规则缺少可执行门、表述歧义、范围过宽/过窄时，列出受影响规则、原始证据、
  建议规则 ID/原文、适用范围、claim boundary 与至少一个能防止同类逃逸的正/负控；
- `RULE_CONFIRMATION`：current 规则已充分覆盖时，列出被本轮错误或成功经验实际确证的
  rule ID、package/return/report 身份、通过或 fail-closed 证据、适用范围与 claim
  boundary。不得只写无证据的 `RULE_DELTA_PROPOSAL=NONE`。

算子 owner 只提交反馈，不得修改 `.agents/rules/**` 或 `.agents/plan.md`。主线收到完成
通知后必须对反馈作正式裁决：需要时修改对应公共/专项规则并保存正负控要求；规则已充分
时在 task record/history 中登记确证；同义、仅描述单次版本或过度严格的提案必须拒绝，
不得为“每包都有反馈”制造重复规则。

规则 ID：`CDA-SERVER-TIMEOUT-MANUAL-INTERRUPT-HANG-FIRST-001`

compile/elaboration 已通过且 simulation 已启动后，出现 runner timeout、仿真时间上限或
用户/外部信号中断，默认执行状态统一登记为：

```text
LONG_RUNNING_HANG_PENDING_ROOT_CAUSE
```

这里的“卡死”是执行层默认诊断状态，不自动把责任归给功能 RTL；根因可以位于配置计数器、
schedule/terminal、ready/backpressure、地址/生命周期、TB/runner、工具入口或 RTL。
收到这类 return 后必须按以下顺序处理：

1. 先只读分析同一 return、冻结源包、最终 JSON/execplan/SCA、活动入口和相关 RTL，
   重建最后一个已证明进展点与第一个不可达/不再前进的条件；
2. 优先检查 loop counter 的可达性和编码宽度、`last/last_index`、终止/完成传播、
   tag/FIFO/ready 环、地址覆盖与 lifetime、跨 stage barrier、累加 recurrence 以及
   loader/TB 的实际入口；
3. timeout 延长、重复运行或只增加日志/observer 均不能作为第一处置，也不能称为功能
   修复；若已存在只延长观察窗、未改变功能条件的包，必须先隔离；
4. 若现有证据能确定根因，必须生成对应的功能配置/runner/package 修复，并重新证明受
   影响的 occurrence、地址、coverage、terminal 和 golden；不得先发观察包；
5. 只有在上述证据穷尽后仍无法确定根因，才允许生成一个新的精确定位包。该包必须标记
   `DIAGNOSTIC_ONLY_NOT_FUNCTIONAL_FIX`，列出无法裁决的精确边界、候选×观测判别矩阵、
   需要观测的 qualified 信号/事件、执行载荷裁剪、限流与预算，以及不同结果分别排除/
   确认的候选原因；
6. 任务回传必须明确给出 `HANG_ROOT_CAUSE`；若为 `UNRESOLVED_AFTER_EXHAUSTIVE_AUDIT`，
   还必须列出已排除项、证据不足原因和下一诊断包锁定的唯一错误位置。仅写“可能较慢”
   “observer 缺失”或“继续等更久”不满足本门。

规则 ID：`CDA-SERVER-DEFAULT-PROGRESS-DIAGNOSTICS-001`

所有新生成的服务器测试包默认携带低开销、只读、限流、可部分回传的问题定位能力，
不再等首次卡死、timeout 或人工中断后补包。默认定位至少覆盖：

- compile/runtime 实际 argv 与 observer time-0 enable 收据；
- 当前 execplan/stage/Start_Comp、qualified request/data/accepted/completion；
- 输出 write-data、`last/last_index`、terminal/completion 与最后有效边界；
- host 单调墙钟、simulation time、声明的采样周期和 `stall_window`；
- `EXIT/HUP/INT/TERM` 下的进度摘要、canonical decision 与 allowlist return。

return 驱动的 successor 除上述通用项外，必须默认保留已证明有效的低开销 qualified
checkpoint，并在当前 `LAST_PROVEN_GOOD` 之后、`FIRST_DIVERGENCE` 之前及其直接 consumer
边界增加足以一次区分仍存候选根因的观测组合；“最小观测”是满足判别矩阵后的开销最小，
不是每轮只加一个 signal。已证明无关或高开销的旧探针应删除或进一步限流，并按
`CDA-SERVER-DIAGNOSTIC-TIME-TO-ROOT-CAUSE-OPTIMIZATION-001` 裁掉不参与复现/判别的
执行项，但不得移除首分歧两侧的定位能力。根因已知的修正包同样保留这些低开销边界，
以证明修复确实越过旧停点；不能只比较最终 terminal。

问题定位必须复用最终包的四向绑定、event qualification 与 canonical decision 规则。
对保留的 causal slice 不得改变 DUT input、ready/backpressure、时序或 timeout；诊断包
可按 time-to-root-cause 规则删除无关正式 D readback，但不得把局部 readback 冒充 E4。
只有算子 owner
在 package manifest 中给出“运行必然短、已有相同动态身份通过、无需新增定位”的明确
豁免依据，并由独立 validator 验证后，才允许关闭；仅以日志大小、实现麻烦或此前未卡死
为由不得豁免。

规则 ID：`CDA-SERVER-ALWAYS-ON-TRIGGERED-CAUSAL-OBSERVABILITY-001`

所有后续 fresh、会实际进入 DUT simulation 的常态包和诊断包，必须把低开销因果观测作为
默认运行能力，而不是等 timeout 后再追加单个信号。已冻结 current 包不因本规则单独重建；
发生其他原因的 fresh successor 时才迁移。compile-only 包不适用动态切面，但仍保留
compile/runtime identity、simulator-start 和 return 绑定收据。

每个适用包在 final ZIP 放行前必须物化一份机器可读的
`server_triggered_causal_observability_profiles_v1` 合同，并满足：

1. **单轮判别优先**：从当前候选根因集合生成
   `候选 × qualified causal boundary × canonical decision` 矩阵。每个候选至少绑定一个
   exact final-source 观测边界；两个候选不得只依赖完全相同的观测集合而没有额外裁决式。
   为满足开销数字而删除一个仍然必需的 source、queue、consumer、internal-match、
   output、terminal 或 formal-D 边界，固定为不合格。
2. **最小因果切面**：按适用性同时覆盖
   `source produce → queue enqueue/dequeue → consumer request/accept →
   internal match/compute → output accept → terminal propagation → formal D collection`。
   每个边界至少记录 qualified count、first/last simulation time，并按机制增加
   outstanding/max occupancy、first-full、stage/slice/pass、terminal/tag、byte mask 或
   ordered digest；稳定 level 只能进入快照，不能计为 progress。
3. **常态轻量、异常触发**：常态只更新定宽计数、时间戳、守恒状态和增量摘要；必须按
   target stage gating。禁止逐事务文本输出和未按分级波形计划启用的默认全量 VCD/FSDB。事件环形缓冲和日志必须
   声明有限预算，只在 time-0、首次 queue-full、首次 branch divergence、qualified
   no-progress、terminal gap、stage transition、signal/exit/final 时冻结或输出。
4. **只读与时序不扰动**：observer 不得驱动 DUT、改变输入、ready/backpressure、时序、
   timeout、完成条件或 workload provenance；不得引入 host 内部 tensor replay。owner
   clock、reset、actual consumer、public surface/private XMR、四向绑定和 event predicate
   仍按本文件既有阻断门逐项闭合。
5. **性能是偏好，不是删证据授权**：用同一事件序列的有/无 observer A/B 墙钟记录
   slowdown；优先把增量控制在 `50%` 以内，但该数字不是阻断上限。超过 `50%` 时必须报告
   exact 边界数、触发数、日志量、主要开销和优化建议；可以通过 stage gating、合并同义
   边界、减少文本 I/O 或压缩摘要优化，但不得删除单轮定位仍需的边界，也不得因此降低
   natural terminal、正式 D、E4/E5。没有可比动态 baseline 时明确记
   `PENDING_FRESH_BOUND_PROFILE`，不得伪造百分比。
6. **v1 no-progress 只触发快照**：`stall_window` 只能来自同一 signature 的 qualified
   measured rate；无合格速率时继续使用既有 timeout。第一版 no-progress 不自动提前终止
   simulation，只保存快照并继续现有 timeout；未来若要提前终止，必须另有不会误杀合法慢
   进展的正负控与规则裁决。
7. **统一返回分类**：canonical output 至少区分
   `TEST_INFRASTRUCTURE_FAILURE`、`SIM_NOT_STARTED`、`TARGET_STAGE_NOT_REACHED`、
   `DYNAMIC_FLOW_CONTROL_STALL`、`TERMINAL_PROPAGATION_FAILURE`、
   `RESULT_COLLECTION_FAILURE`、`NUMERIC_MISMATCH`、`NATURAL_SUCCESS` 和
   `EVIDENCE_INCOMPLETE`。formal D absent 时不得用默认 `mismatch=0` 覆盖前序失败。

公共设计入口为：

- `schemas/server_triggered_causal_observability_v1.schema.json`；
- `contracts/server_triggered_causal_observability_registry_v1.json`；
- `tools/validate_server_triggered_causal_observability.py`。

共享 current-five profile 只提供后续 fresh successor 的候选/边界设计，不授权复制旧 XMR、
不替代 family 对 exact final source span、owner clock、实际 consumer 和性能收据的绑定，
也不修改 current package。final ZIP validator 必须消费 materialized family profile；
只通过公共 design profile 不能发布 `PACKAGE_READY_NOT_RUN`。

规则 ID：`CDA-SERVER-DIAGNOSTIC-QUALIFIED-BUDGET-NOT-CONSUMED-BY-STATE-001`

多 stage/slice/lane observer 为目标 qualified event 声明有限 coverage budget 时，
heartbeat、level snapshot、occupancy/state transition 与其它 non-progress 记录必须使用
独立预算和独立计数器；这些记录无论发生多少次都不得消耗、递减或提前关闭 qualified-event
coverage budget。

1. machine profile 必须分别声明 `qualified_event_budget` 与
   `non_progress_state_budget`，固定
   `accounting_mode=SEPARATE_QUALIFIED_AND_NON_PROGRESS`、
   `state_activity_consumes_qualified_budget=false`。仅声明一个总记录数、共用 emit counter，
   或先记录任意 state 再用同一 `n<limit` 门控制 qualified target，均 fail closed。
2. state/heartbeat 预算耗尽后只允许 coalesce/drop state-only record，并保存 seen/retained/
   dropped 摘要；不得关闭 qualified emitter。后续真实 qualified target event 仍须按其自身
   预算正常进入 ring/summary/canonical consumer。
3. 本门不把 state edge 或 heartbeat 升级为 transaction/progress。qualified event 仍须满足
   owner clock、stage gate、actual consumer 与 event predicate；natural terminal、正式D、
   E4/E5不变。
4. final-ZIP validator 必须消费 exact materialized family profile，并覆盖反例：
   early slice/lane 的 state oscillation 次数超过 nominal state limit 后，later slice/lane 的
   首个 qualified target event 仍保留；把两类 counter 合并的 mutation 必须 fail closed。
   该负控可用合成 trace，不要求运行 DUT，也不得修改 current package。

历史冻结反例：GAP v50 在 slice0 state edge 上耗尽 256 条共用记录预算，晚于该时刻出现的
later-slice GA output 因而未被覆盖。该反例只证明 diagnostic coverage escape，不证明
配置、数值或 functional RTL 错误。

公共合同继续复用：

- `schemas/server_triggered_causal_observability_v1.schema.json`；
- `contracts/server_triggered_causal_observability_registry_v1.json`；
- `tools/validate_server_triggered_causal_observability.py`；
- `schemas/server_diagnostic_budget_trace_v1.schema.json`。

规则 ID：`CDA-SERVER-LONG-RUN-PROGRESS-LOCALIZATION-001`

预期可能长时间运行、曾发生 timeout/人工中断，或单节点规模足以让完成时间不可直接判断
的后续包，必须默认启用低开销、只读、可部分回传的进度定位功能，不能等失败后再补：

1. 至少记录 host 单调墙钟、simulation time、当前 execplan/stage/Start_Comp 序号、
   已完成 stage 数，以及一个与真实 accepted/completion 绑定的单调进度计数；
2. 对目标数据路由记录足以定位停点的累计摘要：request/data/accepted/finish、`last`/
   `last_index`、outstanding 或等价的 producer→consumer 边界；不得用未限定的 level
   sample 冒充事务；
3. manifest 必须声明正常情况下最小应前进事件、采样周期、`stall_window` 和日志预算。
   连续两个以上窗口单调计数前进可判“尚未跑完且仍前进”；超过窗口无任何限定进度可判
   `LONG_RUNNING_HANG_AT_<last_boundary>`；自然 terminal 才是完成；
4. `EXIT/HUP/INT/TERM` trap 必须回收最新进度摘要和最后边界，即使没有正式 D，也能区分
   “中断时仍在前进”“已超过 stall window 停滞”和“证据不足”；
5. observer/进度功能必须在实际 simulator argv 中启用，preflight 验证 compile/runtime
   binding，return allowlist 必须回收其日志；只编译未启用、只启用未回收或日志被预算
   截断到无法定位，均为包缺陷。若 TB 的 observer include/实例受编译宏保护，compile
   命令必须显式定义对应 enable macro（例如 `NATIVE_RETURN_OBSERVER_ENABLE`），并由
   preflight/compile receipt 证明实际选择了启用分支；仅把 observer 文件或 include
   目录放入包中不算 compile binding；
6. 进度功能不得驱动 DUT、改变 ready/backpressure/时序/timeout，也不得默认开启全量
   逐周期日志。结果只定位卡死边界，不能替代正式 D readback 或数值 golden。

规则 ID：`CDA-SERVER-OBSERVER-BINDING-FOUR-WAY-001`

任何依赖 package-local observer 的包，在标记 `PACKAGE_READY_NOT_RUN` 前必须由独立
validator 对最终 ZIP（不是 builder 模板或中间目录）机械闭合以下四向绑定：

1. **source**：最终 ZIP 内存在 manifest 指定的唯一 observer source，相对路径、大小和
   SHA-256 精确匹配，fresh extract 后可读；禁止只记录一个未入包的源路径；
2. **include**：最终 `PREPARE_AND_RUN.sh`/compile driver 的实际 compile 参数包含解析到
   该 source 所在目录的 package-local `+incdir`，且规范化后不得越出 package root；
3. **compile enable**：若 TB include/实例受宏保护，最终实际 compile 参数同时含精确的
   enable macro（例如 `+define+NATIVE_RETURN_OBSERVER_ENABLE`）；runtime plusarg 不能
   替代 compile-time macro；
4. **runtime/return**：最终 simulator argv 启用 observer，time 0 必须产生声明的
   enabled receipt，observer 日志/actual compile argv/actual simulator argv/进度摘要
   全部进入 return allowlist，并由 signal trap 回收。

release validator 必须直接解析最终 ZIP 中的脚本、manifest 和 allowlist，生成四向绑定
收据；不得相信 builder 自报字段。定向测试必须至少包含四个负控，分别删除 source、
`+incdir`、enable macro、runtime/return binding，并证明每项都会 fail closed。任一项
缺失时状态固定为 `PACKAGE_OBSERVER_BINDING_INCOMPLETE`，禁止发布、上传或运行；不得等
服务器 compile/timeout 后才发现。服务器 return 仍须用实际 compile log 与 time-0
enabled marker 复核，静态通过不能替代动态绑定收据。

规则 ID：`CDA-SERVER-DIAGNOSTIC-FEATURE-RUNTIME-ENABLE-END-TO-END-001`

observer 总体启用不代表其内部每个按 plusarg/runtime gate 控制的诊断功能已经启用。
任何包若依赖一个独立 gated feature 的计数器、snapshot 或 canonical boundary 来裁决
服务器结果，最终 ZIP 自检必须逐 feature 闭合：

1. manifest 声明 feature 名、runtime enable 参数、limit/budget 参数、time-0 marker、
   feature-specific returned binding receipt、预期记录 schema 和 return allowlist target；
2. 真实 `PREPARE_AND_RUN.sh` 到安全 simulator stub 的正控必须证明实际 simulator argv
   同时含 enable 与 limit 参数；generic `+RETURN_OBSERVER` 不能替代 feature 参数；
3. time-0 marker 必须明确报告该 feature `enabled=true` 及生效 limit；仅 observer 总体
   enabled、源码已打包或 compile macro 已定义均不够；
4. signal trap/finalizer 必须回收 feature-specific binding receipt 和记录；分析器只有在
   enable marker、binding receipt 与返回记录三者一致时，才能把记录中的0解释为“0次事务”；
   feature 未启用时的默认0固定分类为 `DISABLED_INSTRUMENTATION_ZERO`，不得作为功能证据；
5. final-ZIP validator 至少包含删除 enable、删除/篡改 limit、删除 time-0 marker 合同、
   删除 feature return target 四类负控，全部必须在服务器运行前 fail closed。

若 current return 已证明 feature 未启用，只允许 runner/runtime/receipt 的 fresh identity
最小修复；不得修改 observer 算法、DUT 配置或数值资产来掩盖绑定缺口。

`EXIT/HUP/INT/TERM` trap 应尽力保存：

- compile/simulator/runner 状态、signal 和实际 argv；
- 已完成的 pre/post 身份；
- `return_observer.log`；
- 限量 compile/sim 日志头尾；
- 已生成的正式 readback 和当前结果门。

部分回传仍须 allowlist-only。缺 observer 时不能猜内部 ready/valid 的具体值，但仍须
依据最终配置、计数器、终止方程、入口和 RTL 做卡死根因审计；不能把“缺 observer”
本身作为跳过分析或直接生成下一观察包的理由。截断日志、末行无 LF 或运行时手工打包
只表示采集时刻。

## 9. 动态结果门

计算自然完成只形成 E3。进入 E4 至少要求：

- package/workload/execplan/SCA/SCA_D 身份闭合；实际编译 RTL 精确绑定云端 GitHub 批准
  commit，或已按 `CDA-SERVER-CLOUD-GITHUB-RTL-AUTHORITY-NONBLOCKING-DIFF-001`
  完成内容与算子影响裁决。本地 expected SHA 不匹配本身不否定动态结果；
- 全部目标 stage/slice 完成且没有 timeout、signal 或未知错误；
- SCA_D exact-set、行数、字节数、LF 和地址覆盖符合算子合同；
- 正式 D readback 逐行/逐值匹配独立 golden；
- 算子专项的 FIFO、tag、lifetime、barrier、invalid-slot、跨 stage 可见性等门通过。

E5 必须使用全新身份独立重跑并满足稳定性和边界覆盖。一次成功不得直接升级 E5。启用
兼容 profile 的包因不绑定服务器源码身份，不得计入 E4/E5；其 D/observer 只定位首分歧。

规则 ID：`CDA-SERVER-RESULT-GATE-CONJUNCTION-001`

服务器 PASS 必须是以下条件的显式逻辑与，缺一即失败：

```text
compile_exit_status == 0
AND every required simulation/run exit status == 0
AND required terminal/natural-completion evidence is true
AND formal readback exact-set is complete
AND missing_count == 0
AND mismatch_count == 0
```

compile 非零、simulation 未启动、run 非零、terminal 缺失或正式 readback 为零时，禁止
仅凭目标路径存在、文件数量、旧文件 hash 或 golden equality 返回 PASS。结果报告必须
同时保存每个条件的原始状态与总门结果；不得用默认值、异常捕获后的 success、跳过分支
或 stale runtime 文件补齐。若 compile 失败发生在 simulation 前，动态证据固定为零，
只能分类 compile/package/server-source failure，不能裁决算子数值。

规则 ID：`CDA-SERVER-NO-DYNAMIC-BASELINE-001`

“回归”必须绑定一个通过相同动态门的 known-good package/result identity。没有该基线时，
服务器首次失败只能分类为 `FIRST_DYNAMIC_FAILURE` 或 `NO_DYNAMIC_BASELINE`。

## 10. 直接回传和预算
规则 ID：`CDA-SERVER-RETURN-RECEIPT-001`
脚本结束后直接生成：

```text
<install_name>_return.zip
<install_name>_return.zip.sha256
```

runner 仍应生成这两个文件并在服务器本地自检一致；用户默认只回传
`<install_name>_return.zip`，不再要求传回相邻 `.sha256`，也不得手工压缩 RUN_DIR。
若用户同时回传 sidecar，分析器必须校验；若未回传，不能仅因 sidecar 缺失判失败。

规则 ID：`CDA-SERVER-RETURN-TRANSPORT-USER-ATTESTED-NO-SIDECAR-001`

主线收到用户明确的传输身份担保后，回传 ZIP 的文件路径与本轮分发记录构成外部传输身份；
分析器必须自行计算并记录收到的 ZIP SHA-256，但相邻 return sidecar 为可选，不再是正式
结果门。该担保只替代外部 sidecar，不替代以下任何包内或源端检查：

- ZIP CRC、path safety、single root、duplicate/symlink 和预算；
- 内部 package/install/run/return identity 与本轮目标身份一致；
- `RETURN_MANIFEST.json`、return allowlist、exact-set、逐文件 size/SHA；
- returned package manifest 与本地冻结源测试包 manifest/identity 的绑定；
- package/install preflight、runtime-D absent、compile/run/signal/natural terminal、
  formal readback、missing/mismatch 和结果联合门。

若内部 identity、manifest、exact-set 或源包绑定不能建立，仍必须 fail closed；不得用用户的
传输担保补齐包内证据。没有用户明确担保的其它传输渠道仍按任务当时约定处理。

回传白名单通常只含：

- `RETURN_MANIFEST.json`、`SERVER_RESULT_GATE.json`；
- 运行 argv、各层退出状态和 signal；
- pre-install、post-install、post-run/final 身份；
- SCA/SCA_D 身份或受控副本；
- 正式 D readback；
- 限量 observer、compile/sim 和目标 local 日志。
- 适用`CDA-SERVER-TIERED-WAVEFORM-ONE-ROUND-LOCALIZATION-001`时，计划声明的单份原始
  waveform、`WAVEFORM_RETURN_MANIFEST.json`和本地可读目标trace。

默认禁止：

- `csrc/`、`simv`、`simv.daidir/`、`.sdb/.so/.a`；
- 完整 run/install/archive/sim_results tree；
- 未由分级波形计划声明/绑定的waveform、重复内容、非目标高频日志；
- 可由源包重建的矩阵/bitstream；
- 上传包、返回包自身或其他 nested archive。

规则 ID：`CDA-SERVER-RETURN-MANIFEST-ALLOWLIST-001`

return collector 必须从 package manifest 中声明的精确 allowlist 逐项收集，并在压缩后
重新验证 exact-set；禁止通过递归复制 run/install/compile 目录后再靠 ignore list
排除文件。allowlist 中每项必须声明来源、目标相对路径、是否必需、大小上限以及可选
缺失时的证据含义。`simv.daidir/`、`csrc/`、`simv`、完整 `sim_results/`、archive、
未声明waveform、nested ZIP 和未声明日志无论大小均不得进入 return；通过分级计划四向绑定的
单份raw waveform、manifest和extracted trace是唯一waveform例外。compile/simulation
失败仍应生成同一 schema 的最小 allowlist return，并保留退出状态和限量日志。

不含波形的普通诊断默认 ZIP≤16 MiB、解压≤32 MiB、单文本≤8 MiB。正式 readback或分级波形
超限时，分别按SCA_D exact-set或waveform plan的精确字节数上调，并在上传/返回manifest同时说明；
不得用普通预算截断波形。压缩后必须重新检查 path traversal、exact set、禁止项、重复内容、
身份和预算；服务器本地生成的 return sidecar 必须自检一致，用户未传回该 sidecar 时按
`CDA-SERVER-RETURN-TRANSPORT-USER-ATTESTED-NO-SIDECAR-001` 验收。

手工压缩完整 run tree 固定分类为 `RETURN_SNAPSHOT_NONAUTHORITATIVE`；即使包含
compile/sim.log，也不能替代标准回传收据。

## 11. 失败和交付报告

任一必需输入/身份/路径/格式/动态门缺失即失败，但 signal trap 应尽量生成可诊断的
最小回传。不得用 build tree、波形或旧日志补齐。

交付报告必须列出：

- ZIP 绝对/相对路径、bytes、分析端重算 SHA-256；源测试包 sidecar；return sidecar
  若用户实际回传则列出并验证，未回传时记录用户传输身份担保；
- release gate 和证据等级；
- 唯一服务器命令；
- 预期回传文件；
- 实际读取收据、规则 ID、完整重建链和两次确定性构建结果；
- 未解除 blocker。

## 12. 功能 RTL repair 条件 profile

只有用户本轮明确授权时才读取并启用目标 repair 专项规则。repair 必须使用精确 patch
allowlist、canonical preimage hash、逐字节 backup、install/restore receipt、
post-restore identity 和 EXIT trap transactional restore。缺任一恢复收据或恢复后身份
不一致时，即使数值正确也失败。

repair 授权不改变本地 `NDP_copy01` preimage，也不得外推到其他文件、算子或版本。

## 13. 大波形 return 的增量审查与三槽保留

规则 ID：`CDA-SERVER-RETURN-WAVEFORM-INCREMENTAL-REVIEW-RETENTION-001`

本规则只作用于**正式 return 已完整回到本地之后**的审查和存储生命周期。它不修改波形生成/
回传门：attempt-local raw FSDB 仍必须按声明 exact-set 完整进入 formal return，不设文件、ZIP、
事件或总字节硬上限，不得在服务器侧或 return collector 中截断、采样或按大小删除。只有完成
本节双消费与保留证据后，才允许淘汰本地旧重型 return。

### 13.1 分段审查，不按二进制字节盲切

family owner 不得把整个 FSDB、全部 transition 表或全部历史报告一次性塞入会话上下文，也不得
等全部信号/时间范围看完才首次落盘。审查单元固定为
`exact signal set × exact time window × candidate mechanism`：

1. 首先绑定 return ZIP、package/execution/attempt、raw waveform member path/bytes/SHA、format/
   completeness 和 decoder/query executable/version/argv/exit；
2. 按 `identity/completeness → existing observer/event receipt → LAST_PROVEN_GOOD 到
   FIRST_DIVERGENCE → direct source/queue/consumer/backpressure/terminal cone` 顺序查询；
3. 每完成一个查询立即写一个不可变 `chunks/<seq>.json`，包含 exact signals、scope、timescale、
   start/end、窗口内全部 0/1/X/Z transition 的工具收据、candidate open/closed、finding、下一查询、
   unreviewed scope 和 claim boundary；选定窗口内仍禁止 sampling/truncation；
4. `review_index.json` 只保存 current revision、下一序号、chunk path/bytes/SHA、open/closed candidates、
   terminal status 和 final pointer，使用临时文件 + atomic replace 更新。chunk 已存在、revision
   冲突、return/waveform identity 漂移或多 writer 争用时 fail closed；不能覆盖旧 chunk；
5. 新会话/上下文续接默认只读 `return_identity.json`、current `review_index.json`、最后一个相关
   chunk 和仍开放候选所需源码，不重读全部历史波形和报告；完整审计仍可按 index 重放全部 chunk。

### 13.2 唯一根因提前停止

同一 return 一旦同时具备 exact source/execution identity、LAST_PROVEN_GOOD、FIRST_DIVERGENCE、
声明窗口内完整 transition、其它主要候选显式关闭、unreviewed scope 和 claim boundary，可写
`ROOT_CAUSE_UNIQUE_STOP` 并停止继续扫描无关波形。terminal index 后不得再追加 chunk；需要扩大
claim 时必须新建 analysis epoch，不得改写旧结论。提前停止只关闭本轮“卡点根因定位”；未审查
范围仍列入 final adjudication，不能据此提升 natural terminal、正式 D、E3、E4 或 E5。未唯一化
时可显式 `INCONCLUSIVE_STOP`，但不得把最后观察到的事件冒充根因。

### 13.3 每族/测试轨三份重型 raw return

“版本”按同一 family + test track 的 distinct return ZIP SHA 计算；相同 SHA 的重复副本先做身份
去重，不重复占槽。含 raw FSDB/VPD/VCD/FST 的本地重型 return 默认最多保留三份，角色固定为：

- `CURRENT`：当前审查或最新尚未消费的 return；
- `BASELINE`：最后成功动态基线或 LAST_PROVEN_GOOD 锚点；
- `CAUSAL`：当前唯一首分歧/根因或必要独立复现锚点。

收到第四份后，在本轮本地接收/分析事务结束前恢复到三份。淘汰选择不是文件 mtime 的盲 FIFO：
先排除上述三类锚点和任何显式保护项，再从已完成 terminal review、family 与 mainline 均有 exact
消费收据、final adjudication 已落盘的候选中按登记顺序选择最老者。没有安全候选时必须 fail
closed 并由主线重分配三种角色或迁移到用户批准的冷归档；不得为满足数量删除唯一 known-good、
唯一首分歧、尚未消费或仍被 current plan/successor/RTL 裁决引用的 return。

### 13.4 删除前派生 core-only return

允许的删除对象只是一份 exact regular local return ZIP，且必须位于 manifest 声明的 storage root
内、非 symlink、当前 bytes/SHA 与登记值完全一致。删除前必须：

1. 生成确定性的 `<return-id>_core_return.zip`，保留原 return 中每个非 raw-waveform member；
2. 嵌入 `RAW_WAVEFORM_RETIREMENT_MANIFEST.json`，绑定原 ZIP、每个被淘汰 waveform 的 path/bytes/
   SHA、family/mainline 消费收据、final adjudication、删除理由和
   `RAW_WAVEFORM_NOT_LOCALLY_RECOVERABLE_AFTER_RETIREMENT`；
3. 重算 core ZIP CRC/exact-set/bytes/SHA，先原子写 prepared retirement receipt；
4. 只 unlink 该 exact ZIP 文件，再把 receipt 与 retention index 原子更新为
   `RAW_EVIDENCE_RETIRED`。不得递归删除、覆盖未知项或删除 package、task record、chunk、final
   report、core return、服务器状态；任一步失败保持原 raw ZIP 并 fail closed。

共享入口固定为 `tools/server_waveform_incremental_review_retention.py`、
`schemas/server_waveform_incremental_review_v1.schema.json`、
`schemas/server_waveform_return_retention_v1.schema.json` 和
`contracts/server_waveform_incremental_review_retention_dispatch_v1.json`。

正控必须覆盖分段续写、唯一根因停止、三锚点 + 一可淘汰旧 return、core-only 派生和 exact 单文件
删除。负控至少覆盖 return/waveform SHA 漂移、采样/截断查询、revision 冲突、terminal 后追加、
未双消费、保护槽删除、四份全受保护无安全候选、storage-root 逃逸/同名 symlink 以及 core/receipt
未闭合。该生命周期只减少本地重型历史存储与上下文压力，不改变 family 诊断所有权、服务器运行、
配置/数值/RTL、natural terminal、正式 D 或 E3/E4/E5 裁决。

## 14. FSDB simulator 进程树、仿真时间心跳与 writer 静止

规则 ID：`CDA-SERVER-FSDB-PROCESS-TREE-WRITER-QUIESCENCE-001`

serialized Conv FSDB smoke s2 已证明：`RETURN_ZIP_PUBLISHED=true`、simv root exit/sentinel 或外层
timeout 收到信号，都不能单独证明 simulator/FSDB writer 已终止。若 finalizer 在 writer 仍修改
`wave.fsdb/.chain/.slist/.xlist` 时归档，会产生 runtime/archive SHA 漂移，并可能把瞬态
`wave.fsdb.slock` 空文件误收为 shard。所有之后 next-fresh FSDB 包必须在 snapshot/archive 前闭合：

1. actual simulator 由 package-owned supervisor 作为直接 child 在 fresh Linux session/process
   group 中启动；supervisor 必须先启用 `PR_SET_CHILD_SUBREAPER`，记录 package/execution/attempt、
   attempt root、actual cwd/argv、root PID、PGID、subreaper receipt、owner session 与 start receipt，
   并把 heartbeat 源日志与输出的 exact path/bytes/SHA 纳入收据，使 double-fork/`setsid` 后的 writer
   也能被收养、追踪和回收；不得只包装外层 `timeout` 后猜测后代已退出；
2. runner 必须把声明的仿真墙钟预算作为 supervisor 内部 timeout，而不是只依赖外层 shell。收到
   INT/HUP/TERM 或内部 timeout 时，先枚举 root/owned PGID/subreaper-adopted 的完整 descendant
   closure，向 owned PGID 发送 TERM，同时对逃逸到其它 PGID 的已识别 descendant 单独发送 TERM；
   宽限到期只对仍存 owned PID 发送 KILL。supervisor 必须 `wait`/reap direct root 与 adopted child，
   并证明所有 owned PID/PGID member 均消失；禁止用 package name 的宽泛 `pkill` 影响其它运行；
3. supervisor 按固定 host interval 从 exact source-bound sim-time marker/log 中写 heartbeat JSONL，
   每行绑定连续 sequence、host monotonic time、simulation time 与 timescale。host PID/CPU/文件仍
   存活只证明 host liveness；至少一次 same-attempt simulation time 增加才可声明 simulation started/
   time progress。超过声明窗口不增加时分类 `HIGH_CPU_OR_HOST_LIVE_ZERO_SIM_TIME_PROGRESS`，从未增加
   固定 fail closed；不得继续写笼统“still running”；
4. 只有 process tree quiescent 后才允许做 waveform snapshot。对 `wave.fsdb` 和全部真实 shard 做
   两次间隔受控的 exact-set/path/bytes/SHA 观测；两次必须逐项相等。`.slock/.lock/.lck/.tmp/~`、
   空 member、symlink、两次间新增/消失/变化成员均固定为 writer 未静止并 fail closed；
5. quiescence 达不到时，finalizer 仍必须发布现有 PARTIAL raw FSDB、compile/sim/signal/core return、
   process/heartbeat/pre-post snapshot 收据，并标记 `DIAGNOSTIC_EVIDENCE_INCOMPLETE`。不得让查询/
   quiescence plugin 阻止 core publish，也不得把 PARTIAL 或不稳定 waveform 冒充 COMPLETE；
6. final-ZIP first-fresh gate 必须从 exact runner 验证 supervisor/heartbeat/quiescence helper 的真实
   调用、信号路径、receipt allowlist 与失败隔离；safe stub、token presence 或 root PID 单测不能
   替代 process-tree escape、writer mutating、stale lock 和 no-sim-time-progress 负控。

共享入口固定为 `tools/server_fsdb_runtime_quiescence.py`、
`schemas/server_fsdb_runtime_quiescence_v1.schema.json` 与
`contracts/server_fsdb_process_tree_quiescence_dispatch_v1.json`。本门只证明运行生命周期、仿真时间
进展分类和稳定 snapshot；不裁决 plateau 的 DUT/RTL/config 根因，也不提升 natural terminal、
正式 D、E3、E4 或 E5。current/tested return 不追溯改写；之后 fresh 包必须应用。
