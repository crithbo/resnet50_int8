# 生成前必读索引

最后更新：2026-08-18（补丁优先与新会话路由）

本文件只负责“读什么、谁拥有语义、何时停止”。字段公式、服务器实现、算子细节和版本
结果分别由其唯一 owner 文件、plan 与 task record 保存，不在这里复写。

## 1. 固定入口与读取收据

每个会话首次工作必须完整读取 `.agents/agent.md`、本文件和 current `.agents/plan.md`。
随后只按本轮 changed surface 选择下表规则。活动规则 exact-set 与职责以
`contracts/active_rule_registry_v1.json` 为准；`.agents/history/rules/` 默认禁止作为输入。

同一轮同一文件只读一次，并记录path、reason和read time；SHA只在actual input consumer需要时记录。规则、活动源码、
机器合同或原始回传冲突时立即停止并报告，不选择“最方便”的值。

| 只消费已冻结 byte-equal 资产 | `算子配置规则.md` 的 reuse/provenance 门与资产 manifest | 只有 changed leaf 才读取对应硬件/族规则 |
| 生成或修改服务器测试包、runner、observer、return | `服务器测试包生成规则.md`、项目 Skill `resnet50-server-package-flow`、服务器入口 README、目标族动态门 | 未执行包优先patch当前revision；workload/config改变时才叠加配置规则并重建其依赖链；触发诊断时读取current gate registry绑定的schema/tool；服务器端只做启动、实际输入、状态安全和return所需最小检查并执行真实命令；本地一次聚合廉价错误，只重跑changed-surface门，冻结后对final ZIP复核一次；正式失败后比较原生`ndp-sim`路径，未知服务器状态标UNKNOWN |

## 4. 原生文件选择

按实际调用路径选读：

- tensor/golden/relayout：目标生成脚本、正式输入和其直接 README；
- graph/地址/execplan/SCA：目标 op_json、handler、planner、output writer 和 pipeline；
- mapping/bitstream：目标 mapper、encoder 和最终 consumer；
- 服务器包：活动 Makefile/TB/filelist、`NDP_copy01/README_HARDWARE_SIM_ENTRY.md`；
- 隔离适配：绑定 manifest、被替换源码及 changed-surface consumer。

未被命令调用、未影响最终字段、也不参与验收的文档不列入必读，但需在 receipt 中说明
为何不适用。活动 `ndp-sim`、RTL、ISA 默认只读。

## 5. 公共停止门

出现任一项必须停止当前生成/发布，并报告最后可信边界：

1. target exact stage、typed request、qparam、layout、workload 或输入 identity 不完整；
2. final leaf 无唯一 owner，source absent 被隐式补零，handler 对 changed axis 无能力，或
   composite boundary 仍 unresolved；
3. 计划从历史失败包、服务器残留、停用规则或来源不明产物补文件；
4. final JSON 无法反解到实际 RTL/mapper/encoder consumer，或地址、transaction、bank/row、
   lifetime、terminal、formal D coverage 未闭合；
5. 把本地 E0/E1/E2、schema pass、自然完成或内部 write 当作 E4/E5；
6. 准备改 RTL/ISA/硬件、执行服务器或改变外部状态，但没有本轮用户授权；
7. 生成服务器包却未完整读取 current `服务器测试包生成规则.md`，或 shared gate 发现会
   影响 server start、actual input、state safety、return 的问题；所有廉价错误必须一次
   聚合，record-only 项不得阻断；package-local HDL staging/final ZIP 的共享保留字声明名
   报告缺失、非空或身份漂移属于 `server_start` 阻断，不能等服务器 compile 才发现；
   actual compile argv显式引用的external toolchain dependency未在已arm finalizer后完成聚合证明，
   或已有同host/compiler/dependency projection失败收据却仍重复运行其它family包，同样阻断；
8. next-fresh 诊断包未满足 current mode selector、source-bound catalog、candidate×boundary、
   logger/parser、qualified event、return 和 first-use audit 门；默认 observer-only，只有主线显式选择
   时使用 package-local TB bounded-causal VCD，VPD/FSDB/UCLI direct-VCD 不得恢复。同包重复执行必须
   重置本包 exact-owned attempt 并以唯一 return 名保留历史；不能区分候选时优先同轮扩大真实因果面，
   不得每轮只加一个信号；observer同时满足
   `CDA-SERVER-SOURCE-BOUND-GENERATED-OBSERVER-001`与
   `CDA-SERVER-ALWAYS-ON-TRIGGERED-CAUSAL-OBSERVABILITY-001`；同一采样多类边沿按
   `CDA-SERVER-DIAGNOSTIC-MULTICLASS-EDGE-NO-LOSS-001`保留每类pending/snapshot或sticky解析；
   logger/parser exact格式按`CDA-SERVER-DIAGNOSTIC-LOGGER-PARSER-EXACT-FORMAT-TRACE-001`从真实logger输出回放；
9. 正式 return 尚未闭合目标，又未进入 `CLOSED`、`WAIT_RTL_FIX`、
   `HARDWARE_CAPABILITY_BLOCKED` 或 `WAIT_USER_DECISION`，却准备无 successor 结束；
10. 会话换代无合法 capsule/acceptance/单 role activation，出现重复 ACTIVE owner，或正式
    return 仍硬编码旧 mainline thread 而未动态解析 registry；
11. package/return/规则任务结束前未向 current mainline 回传结构化结果、claim boundary 与
    有证据的 `RULE_DELTA_PROPOSAL` 或 `RULE_CONFIRMATION`；
12. 活动规则集合、职责、SHA 或唯一 `CDA-*` owner 不通过
    `tools/audit_active_rule_registry.py`。
13. 含 raw waveform 的同 family/test-track 本地 return 在一次接收/分析事务结束后仍超过三份，
    或准备按 mtime/FIFO 删除尚未双消费、唯一 BASELINE/CAUSAL/CURRENT 锚点、identity 漂移对象，
    或未先生成 core-only return 与 retirement receipt；这些情形必须停止轮转，不能以磁盘压力
    绕过证据生命周期。
14. next-fresh runner 未用 Linux child-subreaper + fresh session/process group + 内部 timeout 监督完整
    simulator/evidence-writer tree，未把仿真时间心跳与 host liveness 分离，或在 owned descendants
    未终止回收、same-attempt time progress 未证、所选 evidence 尚未 close/flush/stable 时归档；失败时
    必须保留 PARTIAL raw/core return 并标记 `DIAGNOSTIC_EVIDENCE_INCOMPLETE`，不得以 ZIP 已发布或
    simv root exit 代替。

详细阻断条件只在其 owner 规则中定义；本节不复制实现清单。旧/current package 是否追溯
适用、shadow/blocking disposition 和 first-fresh 附加查验，全部按 current server rule。

## 6. 证据等级与回归分类

这是 E0–E5 的唯一公共定义：

- E0：静态可解析/可编码；
- E1：来源、结构、mapping、bitstream、execplan、地址和确定性闭合；
- E2：独立软件公式、layout、golden 和最终物化回环闭合；
- E3：绑定身份的服务器运行自然完成；
- E4：正式 readback 与独立 golden 一致；
- E5：全新身份重复运行并覆盖专项边界，可推广。

`REUSE_ACCEPTED_FOR_INTEGRATION` 只是免复测装配状态，不属于 E0–E5。

回归分类唯一口径：有同门 known-good 才称 `REGRESSION`；只有本地/静态基线称
`NO_DYNAMIC_BASELINE`；首次服务器失败称 `FIRST_DYNAMIC_FAILURE`。
