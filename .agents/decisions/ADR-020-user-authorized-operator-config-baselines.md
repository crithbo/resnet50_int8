# ADR-020：接受两个配置目录为用户授权的正确算子基线

日期：2026-07-23

状态：superseded by ADR-021；保留本文件作为用户授权演进记录。

## 1. 用户授权

用户明确说明：DeepSeek 算子一般均经过硬件测试，配置证据力度较高。随后进一步澄清：

- 根仓 `jsons` 中可识别的参考算子配置可作为正确配置；
- `ndp-sim/jsons` 中只有云端仓库固定版本原生自带、且当前内容仍与该提交一致的配置，
  才可作为正确并经过测试的配置；
- 后来加入的算子（明确示例为 `node0004`）没有因此获得“经过测试并正确”的授权。

当前活动仓库固定为 `uSFrances/ndp-sim@ec12424516ae0304228dd2321d4e604fe225e04e`。
Git 逐文件核验结果为：

- `ndp-sim/jsons` 共 55 份 JSON；
- 53 份由该提交跟踪且工作树与提交一致，接受为上游已测试正确基线；
- `node0004_accumulate_wave0.json` 与
  `node0004_accumulate_wave0_nopp_r1.json` 是提交之外的项目新增文件，不在授权内；
- 根仓 `jsons` 中 12 份可识别算子配置继续按用户提供的正确参考配置处理。

因此当前 67 份库存中共有 65 份授权正确参考、2 份项目新增未授权候选。分类依据必须是
固定提交中的路径和 Git 内容身份，不能根据文件位于 `ndp-sim/jsons`、文件名像正式
算子或能被工具解析就自动认定。

65 份授权配置可用于字段语义、LC/PE/stream/buffer/SA/GA 拓扑、同族 ScheduleIR、
规则提炼、已知配置反向复现和新候选种子，不再要求先找到逐文件原始服务器日志。
两份项目新增配置只能用于身份审计、失败分析和显式标界的静态假设；在独立验证通过前，
不得用于解除配置正确性 blocker。

## 2. 与运行证据的区分

“参考配置正确”不自动等于：

- 本项目重新封装的某个目录已经被服务器正确加载；
- 某次运行已经自然完成；
- 某次运行已经取得 readback；
- 新 shape、新地址、新常量或新拓扑已经正确；
- ResNet50 派生配置已经获得 E4/E5。

因此原始日志、缺文件、停滞、readback 和数值比较继续单独记录。若一个已授权正确的参考
配置在本项目包中没有完成，优先把它记作该次封装、地址、数据、控制链、RTL 环境或运行
流程问题；除非出现能够直接绑定配置语义错误的反证，不得仅凭该次失败撤销参考配置
正确性。该保护不适用于未获授权的 `node0004*` 项目新增配置；它们现有的硬件负证据和
无效尝试必须原样保留。

## 3. 生成边界

使用正确参考配置生成新候选时必须继续：

1. 绑定源配置路径与 SHA-256；
2. 区分原样复用字段、shape 派生字段、地址后绑定字段和 typed qparam；
3. 通过严格 schema、RTL/encoder 字段、terminal、SA/GA、padding/tailing、
   mapping、bitstream、execplan 和逐请求地址校验；
4. 把新生成物标为 candidate；
5. 通过独立 golden 和服务器 E4/E5 后，才能提升为正式 ResNet50 target config。

本授权提高上游原生及用户提供参考语料的证据级别并解除相应规则提炼阻塞，但不允许把
项目新增配置或未经验证的派生变化冒充为上游原生参考配置。
