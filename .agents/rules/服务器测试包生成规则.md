# 服务器测试包快速闭环规则

最后更新：2026-08-18

本文件只定义跨族稳定的服务器包语义。机器字段、适用性和实现细节由
`contracts/server_package_build_gate_registry_v1.json`、对应 schema/tool/test 唯一拥有；算子
公式属于族规则，current identity 与 blocker 属于 `.agents/plan.md`。旧实现和事故原文只在
`.agents/history/`、task record 与 fixture 中保留。

总目标是尽快得到可裁决的服务器证据，而不是让本地证明替代服务器测试。只有能直接导致
`server_start`、`actual_input`、`state_safety` 或 `return` 失败的检查可以阻断发布；其它检查
只能 warning/record-only。

## 1. 权限与生命周期

规则 ID：`CDA-SERVER-SCOPE-AUTHORIZATION-001`

- 构包不授权上传、运行、lease、服务器连接、功能 RTL、config、numeric 或 workload 修改。
- tested、已执行或已绑定正式 return 的 package identity 不可覆盖；若要改变必须生成 successor。
- 尚未执行且未绑定正式 return 的本地/pending candidate 优先在原 revision 上修补。只有身份合同
  无法保持、已进入 managed tested/run 状态或用户要求时才 fresh rebuild。
- 修补只重跑 changed surface 的 applicable gate；未变且已有 PASS 的门必须复用，禁止逐错误完整
  重建或重复已通过的昂贵检查。

规则 ID：`CDA-SERVER-PATCH-FIRST-CHANGED-SURFACE-001`

每次修补先登记 changed surfaces、直接消费者和生命周期：

```text
blocking_applicable  changed且会影响四类因果结果，必须新跑
receipt_reuse        surface/消费者/规则语义未变，复用PASS
record_only          只影响可读性、provenance、性能估计或传输身份
not_applicable       本包不经过该机制
```

SHA/bytes 可作缓存和审计 provenance，但本地到服务器的传输不以 SHA/byte receipt 漂移为阻断条件；
实际文件缺失、不可读或直接消费者改变仍按因果类处理。

## 2. 唯一正式构包入口

规则 ID：`CDA-SERVER-CAUSAL-RELEASE-ADMISSION-001`

构包必须调用项目 Skill，并通过同一工具的两个阶段：

```powershell
python tools/server_package_pipeline.py prepare --spec <spec.json> --output <profile.json>
python tools/server_package_pipeline.py admit --profile <profile.json> --gate-results <results.json> --zip <candidate.zip> --output <admission.json>
```

- `prepare` 一次聚合所有廉价问题，不 fail-fast；同一批问题修完后再物化/修补一次。
- family builder 只生成或修补 profile 指定的 changed surface，不得重新生成未变资产。
- `admit` 对最终 ZIP 只做一次 CRC/非空复核并消费聚合 gate results；所有
  `blocking_applicable` 必须 PASS，`receipt_reuse` 不要求重跑，record-only 失败只告警。
- 没有 `server-package-release-admission-v1` 的 `PACKAGE_READY_NOT_RUN` 不得发布到 pending。
- 规则/validator 首次启用不触发全套重放；只有其 changed surface 会影响四类因果结果时才阻断。

## 3. 原生运行路径与 actual input

规则 ID：`CDA-SERVER-NATIVE-FLOW-001`

runner 必须从 `NDP_copy0x` 的原生入口、Makefile 和 README 推导，保留 production compile/sim argv。
本地不得因服务器工具、license、预装绝对路径、服务器输入文件或目录当前不存在而阻断；这些由
原生命令在服务器运行时解析。只有 package 自带文件缺失、相对路径自相矛盾、shell/HDL/Python
不能解析，或明确会让原生命令打不开 package-owned 输入时才阻断。

服务器 root 直接 name+type 集合不得改变。package-owned cfg/run/evidence 位于已存在的 real
`install/` 下；package 可安全创建 `install/cfg_pkg`、`install/codex_runs` 及自己的 fresh 子目录，
不得要求用户预建二级目录，不得删除或覆盖 foreign sibling。

规则 ID：`CDA-SERVER-ACTUAL-INPUT-CONSUMER-001`

最终 staging tree 与 ZIP 必须证明：

- runner、SCA、matrix/bitstream/config 的相对路径在 TB cwd 下解析到同一 package-owned 文件；
- actual compile/sim argv、source/define/parameter 与 target consumer 一致；
- workload provenance 合法，禁止 host tensor replay、precompute、跨仿真 dump/reload；
- manifest 与 runner 所称 target/stage/config 是实际消费者，不以占位文件或 expected equation 代替。

## 4. runner、重复运行与 package-local 源码

规则 ID：`CDA-SERVER-RUNNER-REPEAT-SAFE-001`

唯一用户命令保持 `bash PREPARE_AND_RUN.sh <NDP_copy0x>`。runner 必须：

- 在任何编译前 arm finalizer；所有非零出口输出 package/gate/exit 单行并留下 compile-not-started core；
- normal、compilefail、nonzero、timeout、HUP、INT、TERM 都走同一 return finalizer；
- 同一个测试包可重复执行：只清理/覆盖 exact-owned install 子树中的本 attempt 文件，不碰 foreign
  sibling；正式 return 使用新的唯一文件名，旧 return 不删除、不覆盖；
- 监督完整进程树，TERM→bounded wait→KILL→fresh reap deadline；监控器自身枚举进程不算 DUT child，
  PID reuse 用 PID+start-time 区分；异常仍发布 emergency receipt；
- durable return 成功前不 cleanup，cleanup 后仍能证明正式 return 已持久化。

规则 ID：`CDA-SERVER-PACKAGE-LOCAL-HDL-001`

所有 package-local `.py` 必须 exact-set `py_compile`；所有 package-local HDL 必须做 lexical、实际
frontend 和 source-bound hierarchy/signal检查。生成 heredoc、signal fallback、parser 与 exact runner
必须走真实语法路径。jsonschema 被合同声明为必需时，runtime 缺失必须 fail closed。检查只覆盖
package-local 源码，不因服务器 vendor 文件当前不可见而失败。

## 5. 诊断模式

规则 ID：`CDA-SERVER-DIAGNOSTIC-MODE-001`

每个 package 精确选择一个 bulk evidence mode：

- `TB_VCD_BOUNDED_CAUSAL_CONE`：后续新动态 successor 的默认模式。只允许 package-local TB 标准
  `$dumpfile/$dumpvars/$dumpon/$dumpoff/$dumpflush`；禁止 VPD/FSDB/UCLI direct-VCD。首轮覆盖所有
  HIGH 候选的 source-bound driver、当前边界、上下游一层、状态保持/clear 与 terminal；计数只是
  soft reference。后续可按 evidence 删除低相关信号，但记录 reason/confidence/affected candidates。
- `OBSERVER_ONLY_WIDE_CAUSAL`：dispatch 明确选择时使用。事件必须是 actual compiled RTL net，按
  owner clock 记录 time/seq/width/0/1/X/Z、heartbeat、partial-exit live state，并让开放候选两两可分。

两模式均不得驱动 DUT、改变激励/握手/完成条件。100,000,000 bytes 只是 observer evidence 的软
告警，不是 hard cap；不得采样、截断或按大小删除。诊断不完整可阻断诊断 claim，但只要 compile、
actual input、状态安全与 durable return 仍成立，不自动把 DUT execution 判失败。

## 6. runtime 安全与 return

规则 ID：`CDA-SERVER-RUNTIME-SAFETY-001`

runtime supervisor 必须区分 host liveness、sim-time progress、target progress 和真实 plateau。只有
sim-time/owner-clock、全部 qualified progress、完整 source-bound causal state 和 global witness 同时
不推进且无未决 X/Z，才可判 causal plateau；global witness 仍推进时不得因局部静止提前停止。
wall、磁盘剩余、证据增长和 projected peak 是独立 operational boundary：触发时停止整个 attempt、
完整保留已写 evidence、标记 `DIAGNOSTIC_EVIDENCE_INCOMPLETE`，而不是静默截断。

规则 ID：`CDA-SERVER-SIGNAL-SAFE-PARTIAL-COLLECTION-001`

partial exit 必须从 live causal records 或 signal-safe persisted equivalent 收集，不能只依赖 simulator
final block。多类 edge 同时发生时不得因优先级丢失低优先级 sticky state；state heartbeat 不消耗
qualified-event coverage budget。parser 必须消费 exact logger 格式，包括显式空白/padding 合同。

规则 ID：`CDA-SERVER-RETURN-RECEIPT-001`

正式 return 唯一原子发布到服务器 `/home/panqs/ndp/simresult`，至少包含：package/attempt identity、
compile/sim argv+exit、actual input、signal/core evidence、stop reason、process-tree reap、natural/partial
状态、decision receipts 与必要日志。compile 未启动可没有动态证据；simulation_started 后缺 required
evidence 必须标 `DIAGNOSTIC_EVIDENCE_INCOMPLETE`。return ZIP 发布不等于自然终止或 E4/E5。

## 7. 结果裁决与连续闭环

规则 ID：`CDA-SERVER-NO-DYNAMIC-BASELINE-001`

没有合法动态 baseline 时只归类 compile/launch/target-not-reached/diagnostic-incomplete，不能裁决功能
回归。无 target stage、无 qualified accepted progress 或无合法 checkpoint 时，不重复跑同一长前缀；
successor 必须一次覆盖所有同轮候选和最近合法 checkpoint。

规则 ID：`CDA-SERVER-FORMAL-RESULT-CONJUNCTION-001`

正式通过必须同时满足：production compile、simulation、目标 stage、natural terminal、合法 workload、
formal-D 全 conjunction、runtime-D 未缺失、E4 与 E5。任何 focused simulation、observer expected、
host replay 或 partial return 都不能代替。actual/local/cloud RTL identity 差异在 compile 成功后仅记录并
做 target causal-cone 审计，不因 identity 不同自动阻断 simulation。

规则 ID：`CDA-SERVER-CONTINUOUS-CLOSURE-001`

return 到达后先流式读取、小步写 checkpoint/report，发现唯一根因即可停止；未定位时继续消费剩余
证据。下一 successor 必须批量区分所有开放候选，关闭 stage-local 后立即提升到 full-chain natural、
formal-D、E4/E5。pending 每族最多一个 ZIP；tested/superseded 只作历史和 receipt reuse。原始大型
evidence 每族最多保留 `MAX_PROGRESS + LATEST_1 + LATEST_2` 三组，只有分析完成、family+mainline
已消费、core evidence 可复现且 protected-set audit 通过后才删除其它组。

## 8. 发布前最小清单

1. Skill 已调用；lifecycle 与 changed surfaces 已登记。
2. `prepare` 一次聚合完成；只修补 changed surface。
3. runner/actual input/package-local source/runtime/return 四类 applicable gate 已 PASS 或合法复用。
4. 选定诊断模式与候选矩阵已绑定；record-only 告警不冒充失败。
5. 最终 ZIP 完成一次 `admit`，状态为 `PACKAGE_READY_NOT_RUN`。
6. 未经用户授权不上传、不运行、不取 lease。
