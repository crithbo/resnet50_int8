# 生成前必读索引

最后更新：2026-08-04（服务器包路由加入内层路径长度预算门）

本文件只负责“读什么”和“何时停止”，不重复算子字段语义、服务器封包细节或版本历史。
创建、修改、派生、重建或发布算子 JSON、bitstream、execplan、SCA/SCA_D、服务器测试包
前，先完整阅读本文件，再按下表选择本轮真正相关的文件。已经熟悉、只改一个字段、沿用
旧包或通用 validator 通过，都不能替代本轮阅读。

## 1. 读取原则

1. 同一轮内同一文件只需完整阅读一次；记录相对路径、SHA-256、适用原因和读取时刻。
2. “相关”由本轮会改变或验证的最终消费字段决定，不由文件名或算子名称猜测。
3. 公共规则只读一次；专项规则只保存增量，不再重复公共规则。
4. `.agents/plan.md` 只读目标任务的当前状态、blocker 和下一步；不得把整份历史计划列为
   必读。已结束版本从 `.agents/task_records/` 或 `.agents/history.md` 按需取证。
5. 原生文档只读目标路径实际调用的入口及直接消费者；不要求阅读无关算子的全部 README。
6. 规则、活动源码、机器合同或原始回传冲突时立即停止，先记录冲突和证据，不选择方便值。

## 4. 生成前停止门

出现任一情况不得开始生成：

- 不知道最终 JSON 字段的语义所有者或 RTL/encoder 消费者；
- 开发/绕行模式下专项规则缺失、冲突，或状态仍为 `CONTRADICTED/TEST_REQUIRED`；
  复用优先模式可把已有 blocker 明确标记为 `DEFERRED_TO_INTEGRATION` 后装配，但不得
  关闭 blocker 或声明正式通过；
- typed request、qparam、layout、tail、地址生命周期或输入身份缺失；
- 需要从旧失败包、服务器残留、禁用参考仓或来源不明产物补文件；
- 将本地 E0/E1/E2、结构 valid 或自然完成误作 E4/E5；
- 计划修改任何 `rtl/` 文件但没有本轮用户明确授权；
- 没有通过相同动态门的 known-good 身份却准备声明“回归”。
- fresh 服务器包准备标记为 `PACKAGE_READY_NOT_RUN`，但 final ZIP 尚未声明并通过
  `CDA-SERVER-PACKAGE-INTERNAL-PATH-LENGTH-BUDGET-001` 的内层缩写映射、最长
  package-controlled projected absolute path、层级/component 预算和三类负控；
  已冻结现有包不因本门单独重建，发生其他 fresh 重建时才适用。
- 准备把含 package-local HDL/TB/observer/support member 的最终 ZIP 标记为
  `PACKAGE_READY_NOT_RUN`，但 exact final bytes 尚未通过
  `CDA-SERVER-PACKAGE-LOCAL-OBSERVER-HDL-SYNTAX-SCOPE-POSITIVE-001` 的兼容 frontend
  正控，以及本轮新增/修改或进入必需结果裁决的 identifier/state scoped closure 与相关
  负控；不要求穷举无关历史 observer state 或完整本地 full-design elaboration。safe
  stub、token presence、XMR 扫描或 source/include/macro/runtime 绑定均不能替代。
- 正式 return 未闭合当前目标、又未命中 `CLOSED`、`WAIT_RTL_FIX`、
  `HARDWARE_CAPABILITY_BLOCKED` 或 `WAIT_USER_DECISION`，却准备以
  `ADJUDICATED / PACKAGE_RELEASE=NONE` 结束而不生成 fresh successor。
- package/return owner 准备结束任务，但尚未向派发单绑定的当前主线发送结构化完成
  通知，或规则反馈只有无证据的 `RULE_DELTA_PROPOSAL=NONE`，没有
  `RULE_DELTA_PROPOSAL`/`RULE_CONFIRMATION` 的证据、适用范围和 claim boundary。

证据等级的唯一公共定义：

- E0：静态可解析/可编码；
- E1：来源、结构、mapping、bitstream、execplan、地址和确定性闭合；
- E2：独立软件公式、layout、golden 和最终物化回环闭合；
- E3：绑定身份的服务器运行自然完成；
- E4：正式 readback 与独立 golden 一致；
- E5：全新身份重复运行并覆盖专项边界，可推广。

低等级、结构 valid、自然完成或内部 write 不能替代更高等级。

`REUSE_ACCEPTED_FOR_INTEGRATION` 只是免复测装配状态，不属于 E0～E5。它表示已有资产
可直接进入整网，只有整网首分歧命中时才回查；它本身不增加正式证据计数。

回归分类的唯一公共定义：

- 有同门 known-good：才可使用 `REGRESSION`；
- 只有本地/静态基线：使用 `NO_DYNAMIC_BASELINE`；
- 首次服务器失败：使用 `FIRST_DYNAMIC_FAILURE`。

## 5. 读取收据

生成记录必须至少包含：

```json
{
  "read_receipt": [
    {
      "path": ".agents/rules/生成前必读索引.md",
      "sha256": "<sha256>",
      "reason": "routing"
    }
  ],
  "rule_ids": [],
  "known_counterexamples": [],
  "open_dynamic_gates": [],
  "omitted_files": [
    {
      "path": "<not-read>",
      "reason": "not consumed and no affected field"
    }
  ]
}
```

收据证明读取范围和身份，不证明语义正确。最终放行仍由目标 validator、独立 golden 和
对应 E4/E5 动态门决定。
