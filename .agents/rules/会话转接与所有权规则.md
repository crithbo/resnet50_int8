# 会话转接与所有权规则

最后更新：2026-08-18

本规则只负责“谁拥有哪个稳定角色、当前事实从哪里读、如何无重叠换届”。它不授权构包、服务器、
config、numeric、workload 或 RTL 动作，也不保存算子技术语义。

## 1. 唯一 current 控制面

规则 ID：`CDA-SESSION-STABLE-ROLE-UNIQUE-ACTIVE-OWNER-001`

`contracts/current_session_owner_registry_v1.json` 是稳定 `role_id`→唯一 ACTIVE task 的机器入口；
`.agents/plan.md` 是当前状态和下一步；storage index/latest task record 仅为 plan 与 registry 提供事实。
thread ID 只是当前承载者，不是权限来源。一个 task 不能同时拥有多个 ACTIVE 角色，一个角色也不能
同时有两个 ACTIVE task。

current registry 日常只需 path receipt；文件存在与 pending exact-set 是接手硬门。bytes/SHA 是可选
provenance，不因传输 digest 漂移阻断接手。只有真正的并发 ownership CAS 切换才使用完整 registry/
capsule digest，避免两个 writer 同时生效。

## 2. 新会话/新模型接手

规则 ID：`CDA-SESSION-CURRENT-DISK-TAKEOVER-001`

接手者固定执行：

1. 读 `.agents/agent.md`、current `.agents/plan.md`、本规则和生成前索引；
2. 从 current owner registry 找到自己的 role、mainline、write/forbidden scope 与 in-flight pointer；
3. 按 `agent.md` 角色矩阵只读相关规则，不默认读历史；命中服务器包动作时调用项目 Skill；
4. 运行 `tools/validate_project_takeover_readiness.py`。它必须证明 registry、plan、pending storage 和
   active patch-first admission 一致；synthetic fixture PASS 不能代替 current-disk PASS；
5. 先回报 previous proven progress、current purpose、write scope、forbidden actions、conflicts，再写入。

环境不支持 Skill 时，显式完整读取 Skill 文件并执行其中同一 prepare/admit 命令；不得把“模型不同”
当作跳过 control plane 的理由。

## 3. 派发与通信

规则 ID：`CDA-SESSION-REGISTERED-FAMILY-DISPATCH-001`

主线向算子族派发时必须发给 registry 中持久 family owner。临时子代理可以承担独立只读研究，但
不能替代 family owner、改变 current pointer、发布 package 或消费正式 return。派发必须包含：
role/owner epoch、previous progress、current purpose、exact input pointer、write scope、forbidden scope、
first action、return target 与是否授权服务器动作。

所有 owner 的正式回传动态解析 registry 中 current mainline，不硬编码历史主线。非本会话正在处理的
内容不向本会话持续同步；只有改变其方法、权限、input 或 blocker 时才发送直接相关消息。

## 4. 原子换届

规则 ID：`CDA-SESSION-HANDOFF-CAPSULE-CAS-001`

需要更换 task 时：

1. old owner 生成 handoff request/capsule，冻结写入，只传 current 指针、未消费消息和首动作；
2. new task 完整读取并返回 acceptance；
3. `tools/session_handoff.py` 用 registry-before、capsule、acceptance 做 CAS，生成 registry-after；
4. mainline 原子发布 registry-after 后新 owner 才能写；old owner 此后只读并可归档。

换届期间 plan/package/storage/服务器状态不并行修改。主线先换，再换 family；optimizer 若仍有未完成的
共享任务可保持原 task。失败时 current registry 不变，不用半生效 capsule 继续工作。

## 5. 状态闭合

规则 ID：`CDA-SESSION-CURRENT-STATE-COHERENCE-001`

- owner registry、plan、storage index 对 role、in-flight state、pending package 必须一致；漂移先修
  current pointer，不从历史猜 current。
- task 完成后主动向动态 mainline 回传 machine report/task record/claim boundary；只有 mainline 消费并
  更新 current pointer 后才算控制面闭合。
- 没有新输入时 WAIT_RETURN/WAIT_USER_DECISION/WAIT_RTL_FIX 是合法状态，不因换会话自动重建或重跑。
- 历史 task record、旧 thread 或 archived rule 不得重新获得 current 权威。

## 6. 权限边界

规则 ID：`CDA-SESSION-NO-AUTHORITY-ESCALATION-001`

handoff 只转移既有权限。没有用户明确授权时，任何会话都不得上传/运行服务器、取 lease、修改功能
RTL、跨族 config/numeric/workload、覆盖 tested package/return，或把 read-only audit 扩张为实现。
遇到需要用户决定的语义/硬件选择时保存当前成果并停在明确 blocker。
