## 1. 结论先行

当前仓库体现出的真实工作规则不是“把模型 shape 填进一个 JSON”这么简单，而是下面这条链：

```text
模型/ONNX 算子语义
  -> 拆成硬件能执行的原子计算
  -> 建立 ONNX 节点、硬件原子算子和 tensor 的稳定 manifest
  -> 生成 raw golden input/output 与必要的硬件子步骤 golden
  -> 明确 dtype、量化公式、广播/归约轴和 tensor layout
  -> 决定 slice 划分、local/ring 通信及 tile
  -> 设计循环控制、stream、buffer 和 PE 数据流
  -> 对 raw tensor 做 partition、padding、relayout、packing、remapping
  -> 形成静态单算子 jsons/<op_type>.json
  -> 生成并检查 placement、mapping 和 bitstream
  -> 在 operator_base_info + control_registers 中补齐 shape 参数化规则
  -> 用目标 JSON/bitstream emulator 执行并导出结果
  -> 由 model_execplan 规划地址、patch JSON、逐实例重生成 bitstream 和网络指令
  -> 加载同一份配置/数据/execplan 到 RTL 或硬件并导出结果
  -> inverse-relayout 后比较 golden / simulator / hardware
```

必须区分五种“完成”：

1. **静态模板完成**：某一个固定 shape 的 JSON 能生成 bitstream。
2. **参数化完成**：改变 shape、dtype、广播或 slice 数后，`model_execplan` 能正确 patch 所有相关寄存器并重新生成 bitstream。
3. **模拟器数值完成**：目标 JSON/bitstream emulator 的输出经过逆变换后与 golden 一致。
4. **硬件数值完成**：同一配置和数据在 RTL/硬件上的输出与 golden、simulator 一致。
5. **网络闭环完成**：从正式 ONNX 自动生成完整 execplan，逐验收点和最终输出三方一致且可重现。

前面的完成层级不能替代后面的层级。当前DeepSeek资料对静态模板的覆盖最好，对参数化只覆盖一部分；目标硬件执行既有DeepSeek JSON的能力已由操作者确认。`NDPFuncModel/conv_func`已能读取并严格校验首个1×1 target JSON语义合同，单坐标走DRAM/Buffer/SpecialPEA/ActivationUnit/DRAM组件路径，首tile和全算子走同入口的physical-DRAM批量等价核。v14服务器诊断只到preflight，v18进入真实仿真后停在首个accumulate，v19目前只完成本地包审计；三者均没有成功的完整服务器自然退出和硬件数值证据，不能升级为G6/G8。配置工作无需重新证明DeepSeek通用入口本身可用。

### 2.1 已确定的目标硬件基线：28个slice

## 3. 两层 JSON 不能混淆

### 3.1 单算子硬件 JSON

位置：`ndp-sim-ref/jsons/<op_type>.json`。

它描述一个固定基准 shape 下的硬件配置，主要包含：

- `CONFIG`
- `dram_loop_configs`
- `lc_pe_configs`
- `buffer_loop_configs`
- `stream_engine`
- `buffer_config`
- 可选的 `n2n`
- `special_array`
- `general_array`
- 可选的 `gemm_shape`、`gemv_shape`、`mul_shape` 等说明性 shape

它的直接消费者是 `bitstream/main.py`。

### 3.2 网络/子图 execution-plan JSON

它描述算子依赖、逻辑 shape、dtype、slice 掩码和 tensor 来源，主要字段为：

```json
{
  "params": {},
  "used_slices": "0b...",
  "operators": [
    {
      "id": "op0",
      "type": "<与 jsons 文件名一致>",
      "used_slices": "0b...",
      "inputs": {
        "A": {
          "shape": [1, 32, 32],
          "dtype": "fp32",
          "source": {"type": "external"},
          "remapping": null
        }
      },
      "output": {
        "shape": [1, 1, 32],
        "dtype": "fp32",
        "remapping": null
      }
    }
  ]
}
```

它的 shape 必须是三维 `[K,M,N]`。表达式只允许引用 `params` 中的整数，并使用受限的 `+ - * // %` 运算。当前 schema 没有 operator attributes/constants；`params` 中的浮点值会被忽略，不能用它传 scale、zero point 或其他 GA/SA 常量。

**强制规则：**

- `operators[*].type` 必须能找到 `jsons/<type>.json`。
- 在 schema/handler 扩展前，不得把逐层量化参数写入顶层 `params` 后假定它们会自动 patch；必须明确采用 constant patch、tensor stream 或逐层静态 JSON 中的一种协议。
- 输入端口只使用 `A`、`B`、`B'`、`C`，输出为 `D`。
- dtype 必须显式填写；解析器虽然默认 `fp32`，但 INT8 工程禁止依赖默认值。
- 当前loader要求`used_slices`写成28-bit二进制掩码字符串。正式ResNet整网继承已完成DeepSeek工程的启动方式：一个网络算子统一使用28个1的全slice mask，同时启动七个独立HIGH-4组；`local`、`HIGH-4`和`LOW-28`描述算子内部通信域，不再用4-bit mask把整网算子缩成单个小环。只有未来存在原始正式配置证据、并在独立算子合同中明确要求局部启动时，才允许生成非全mask。不要用整数表示“slice个数”；解析器会把整数当成位掩码，例如整数`16`只启用bit4，整数`28`只启用3个slice。
- 上游来源必须引用已经存在的算子；外部数据使用 `{"type":"external"}`。
- 所有 `//` 切分在生成前必须验证可整除，或明确 padding/tailing 规则；禁止静默截断。

## 4. 先固定模型语义，再谈配置

### 4.1 必须写清的语义清单

为一个模型算子选模板前，先固定以下信息：

1. 精确公式和舍入方式。
2. 每个输入/输出的逻辑 shape、dtype 和量化参数。
3. 广播轴、归约轴、卷积 stride/padding/dilation/group。
4. 中间累加 dtype，以及是否包含 bias、scale、zero point、激活或 requant。
5. 逻辑 layout 与物理 layout。
6. tensor 在 slice 间是切分、复制、聚合还是环传。
7. 尾块不足 tile 时采用 padding、tailing 还是单独模板。

### 4.2 ResNet50 INT8 需要遵守的基本公式

量化：

```text
q_y = clip(round_to_even(x / s_y) + z_y, qmin, qmax)
```

反量化：

```text
y = (q_x - z_x) * s_x
```

QLinearAdd：

```text
q_y = clip(round_to_even(
        ((q_a-z_a)*s_a + (q_b-z_b)*s_b) / s_y
      ) + z_y)
```

QLinearConv / QLinearMatMul 的目标语义：

```text
acc = sum((q_x-z_x) * (q_w-z_w)) + bias_int32
q_y = clip(round_to_even(acc * (s_x*s_w/s_y)) + z_y)
```

其中 per-channel `s_w`、`z_w`、bias 和输出通道必须按相同物理顺序分发。是否把 bias/requant/激活融合为一个 JSON，必须由硬件数据流确定，不能只按 ONNX 节点名决定。

## 5. 模板选择规则

选择模板至少匹配“计算 + dtype + 数据流”三项，不能只匹配算子名字。

| 模型特征 | 优先模板族 | 关键判断 |
|---|---|---|
| M>1 的矩阵乘 | `prefill_gemm_*` | local 还是 ring、K 如何切 slice、是否需要 B' 双读 |
| M=1 的矩阵向量乘 | `decode_gemv_*` | local/ring、权重双 bank 视图、跨 slice 聚合 |
| 同 shape 逐元素 | `prefill/decode_{add,mul,mac}_*` | 两输入 dtype、输出 dtype、是否转换 |
| M 或 N 方向广播 | 名称带 `fp32M` / `fp32N` 的 add/mul | 广播输入的 stream stride 应为 0 或使用 keep，而不是重复存储 |
| 单 slice 内归约 | `max` / `summac` / `sum_rec` | 归约轴、每 lane 元素数、输出 shape |
| 跨 slice 归约 | `remote_sum/max` | slice 数、每 slice 输入位置、remote 地址跨度 |
| 指数、倒数、倒数平方根、SiLU | 名称带 `SFU` 或 `silu` | SFU 类型和系数文件必须匹配 |
| GEMM/GEMV 主计算 | `special_array` | SA mode、dtype、K 完成时刻、输出行/列主序 |
| 逐元素/归约/量化/池化 | `general_array` | GA PE opcode、转换开关、mask 和拓扑 |
| 邻居环通信 | `n2n` + neighbor buffer | `mem_loop`、slice 跳转、buffer_nbr_cnt 一致 |

### 5.1 local 与 ring

- **local**：当前 slice 所需输入已经本地可读，不需要跨 slice 汇集主计算数据。
- **ring**：K 分块或权重/部分和需要沿 slice 环传；JSON 必须同时配置 `n2n`、neighbor-enabled buffer 和对应 SA/GA 输入。
- 顶层/算子`used_slices`是28-bit启用掩码，不能写成通信组大小N；当前首例保持28 slice全掩码。`n2n.mem_loop`才等于内部通信组大小N；`buffer_nbr_cnt`是NRM终止下标，必须显式写成N-1，不能依赖encoder默认值27。`neighbor_streami`固定消费`buffer(2i)`/`buffer(2i+1)`，这两个buffer必须同时`nbr_enable=1`；只打开偶数buffer会让NSE切换到奇数buffer后无法完成READ环。`ping_pong`当前没有接入NSE RTL端口，不作为该问题的修复字段。
- 4-slice小环和28-slice大环不是只改一个数字；还会影响`src_slice_sel`、`dst_slice_sel`、地址跨度和buffer生命周期。目标必须使用ADR-007从RTL冻结的七条HIGH小环和一条LOW大环，不能用数值连续或modulo公式代替物理映射。

### 5.2 prefill 与 decode

- prefill 通常保留 M、N 两个非平凡维度，使用 8/16 lane 向量化和二维 tile。
- decode 常见 M=1，模板会收缩一层循环，并把 fp32 向量按 4 元素、fp16 按 2/8 元素等硬件粒度读取。
- 不允许把 prefill 配置仅把 M 改成 1 后当成 decode 配置；stream、buffer、GA/SA 模式可能不同。

## 6. 单算子 JSON 各字段的工作规则

### 6.1 `CONFIG`

当前模板的常见值：

- GA 算子：`11011101`，前四位为 `IGA=1, LSU=1, SA=0, GA=1`。
- SA GEMM/GEMV：`11101110`，前四位为 `IGA=1, LSU=1, SA=1, GA=0`。
- SA+GA 混合：`11111111`。

`bitstream/parse.py` 当前只用前四位决定 IGA、LSU、SA、GA 模块是否写入，完整 8 位仍被写到 bitstream。现有模板通常让后四位重复前四位，代码注释称为 `use + update`，但当前生成器没有解释或执行后四位的 update 行为。

**规则：**单算子冷启动模板暂时保持前后四位一致；若存在连续算子复用、局部更新或 clock/config reuse，必须先确认 8 bit 的准确高低位顺序和 update 状态机，不能根据现有常量猜测。

### 6.2 `dram_loop_configs`

- LC 通过 `src_id` 串成嵌套循环树；最外层 `src_id=null` 且 `outmost_loop=1`。JSON 先写逻辑节点名，物理 `src_id` 由 mapper 根据连接拓扑换算。
- `start/end/stride` 按 Python `range(start,end,stride)` 式的 **end-exclusive** 范围填写。`CGRA_SIM/cgra_python/slice/README.md` 明确说明循环到达或越过 `end` 即停止，`slice/node.py::Iteration.compute()` 也直接调用 `range(start,end,step)`；现有 JSON/handler 与此一致。
- 操作者已确认：LC 用于控制循环进行，`last_index` 表示循环层级。仓库中的旧 IGA 原型也按外层 0、向内逐层递增的方式赋值，并在内层完成时传播外层层级；同一逻辑层并行推进的多个 LC 可以共享同一个 `last_index`。
- `keep_last_index`、`pingpong_last_index`、`buf_full_last_index` 和 `transout_last_index` 都是在引用“哪一层循环结束”：分别控制输入何时换新值、何时切换 ping-pong、何时认为 buffer 满，以及何时允许 PE 输出。它们不是各自独立的编号体系。
- 当前新增配置只使用正 `stride`；`stride=0` 不作为循环配置，广播应在 stream stride 或 keep 语义中表达。仓库没有足够用例证明负 stride 的目标用法，当前也不需要为 ResNet 正向计算引入它。
- 一个模型维度可能拆成多个硬件循环，例如通道块、lane 内元素、kernel H/W、输出 H/W。
- loop end 中的 `/8`、`/16`、`/32` 必须来自 tile/lane/字节组织，不允许照抄另一 dtype 的除数。
- 非整除尺寸必须显式选择 tail LC、`tailing_enable`、padding 或单独尾块配置；不能只用整数除法缩小 `end`。

### 6.3 `lc_pe_configs`

LC PE 主要用于地址索引、计数或辅助算术，也可为 stream 提供 index：

- `alu_opcode` 常见 `add/mul/mac/max`。
- `mode=buffer` 表示每次接收新值。
- `mode=keep` 表示值保持到 `keep_last_index` 对应循环完成。
- `mode=constant` 时使用 `constant`。
- `src_id` 必须构成硬件允许的 LC/PE 拓扑；能解析不代表 placement 一定可行。
- LC PE 的作用是把循环变量组合成 stream 所需的仿射索引。先写出 `idx = c0*i0 + c1*i1 + ... + bias`，再用 `mul/add/mac + constant/keep` 实现；没有索引公式时不能从 tensor shape 唯一推出 LC-PE 连接。

### 6.4 `buffer_loop_configs`

- 每个 GROUP 绑定目标 tensor（`A/B/B'/C/D`）。
- ROW_LC/COL_LC 把 DRAM 循环坐标变成 buffer 的 row/col 坐标。
- `end` 和 `stride` 必须与 `buf_spatial_stride`、mask 及实际一行承载的数据一致。
- layout 重排不仅改变数据文件，也可能要求修改 COL_LC 和 stream spatial stride；已有 `write_reg_hint` 规则就是这一类联动。

### 6.5 `stream_engine`

每个 stream 需要同时回答“从哪里取、如何寻址、如何装入 buffer、何时切换”：

- `target`：逻辑 tensor 端口。
- `mode`：`read` 或 `write`。当前 mapper 按 4 read + 1 write 放置，但参数镜像是 3 read + 1 write；在目标版本确认前，不得设计必须同时使用第 4 个 read stream 的新算子。
- `base_addr`：静态 JSON 中是占位地址；进入 `model_execplan` 后必须由地址规划 patch。
- `idx`：来自哪一级 DRAM LC / LC PE。
- `mem_idx_mode`：3 项按 `[port2,port1,port0]` 填写，每个地址维使用 buffer、keep、null 或 constant；对应的 `idx`、constant、keep index 也必须固定为 3 项。
- `idx_size`：3 项编码每个 transaction 维的真实长度减 1，即 `idx_size[i]=transaction_dim[i]-1`，不是直接写 tensor shape。编码器据此自动计算 `total_size=dim0*dim1*dim2` 和 `idx_size_log`。
- `dim_stride`：字节 stride；必须使用该 stream 实际 dtype 的字节数和物理 layout。证据是 `add_dequant_uint8CWH_uint8CWH_fp32CWH.json` 对同一逻辑布局的 uint8 输入写 `[16,64,256]`，fp32 输出正好写四倍的 `[64,256,1024]`。
- `padding_enable/range/value`：卷积或池化边界补值。MaxPool 模板把 padding 后的原始有效区写成 low=1、up=H/W，说明 low/up 是 **包含端点的有效范围**，范围外才补值。INT8 MaxPool 的 padding 值仍必须符合量化域最小值/zero-point 语义。
- `tailing_enable/range`：最后不足 tile 的有效范围。
- `address_remapping`：必须是 26 个 `[0,25]` 的整数；低位到高位按每项 5 bit 打包。
- `buf_spatial_stride`：16 路 buffer 展开 offset，不是普通 tensor stride。
- `buf_spatial_size`：展开路数；要和 buffer/GA mask 匹配。
- `ping_pong` 和 `pingpong_last_index`：只在确实存在双缓冲生命周期时开启。

当前 `idx_size_log` 用 `int(log2(...))` 计算，`total_size` 只有 8 bit。对 `jsons/*.json` 的 111 个 stream 实例复核后，所有 transaction 维长度都是 2 次幂，三维乘积最大为 128。因而新增 ResNet 配置采用更保守、已被仓库实例覆盖的规则：**每维取 2 次幂，单次 transaction 总量不超过 128**；不足部分用 padding/tailing 或外层 LC 分块，不依赖编码器截断。

### 6.6 `buffer_config`

- buffer 行列尺寸必须与 ROW/COL LC、stream `buf_spatial_size/stride` 和实际 transaction 总量同时一致。
- ping-pong 只有在 producer/consumer 生命周期确实重叠时开启；切换事件由批准的 `pingpong_last_index` 驱动，不能只因模板中默认开启就照抄。
- neighbor/N2N enable、邻居次数和源/目的选择只用于明确的跨slice数据流。当前HIGH小环完整遍历为4步/3次传递，LOW大环为28步/27次传递；方向和物理slice顺序必须来自ADR-007/RTL map，不能只写次数。
- branch、valid、padding 和 tail mask 是不同语义：valid决定lane是否参与，padding注入算子规定值，tail屏蔽末块无效元素，branch用于数据依赖/旁路；不得合并成一个“无效”标志。
- source/destination ID 必须按目标寄存器表映射物理端口。不同旧版本的逻辑名称相同不代表数值ID相同。
- `dst_port`描述的是**向该buffer生产数据的计算阵列**，不是stream目标、逻辑tensor端口或下游消费者：目标寄存器和RTL一致规定`0=SpecArray`、`1=GeneArray`。禁止把模板默认值1理解成“输出端口1”。
- 生成器必须先声明该阶段的预期生产者，再写`dst_port`：SA-only accumulate写0，GA-only requant写1；SA+GA混合阶段必须根据最后写入该buffer的实际数据流显式裁决，不能只根据两个模块都存在就猜值。
- 被选择的生产者配置对象必须真实存在且属于当前阶段；`CONFIG` mask、encoder可接受或bitstream可生成都不能替代这项检查。选择缺失的GeneArray会让SA结果无法进入buffer并把MSE写数据链永久卡在prepared门之前。
- 每份配置在进入encoder、typed request、freeze和execplan之前必须运行route invariant；当前统一入口为`validate_buffer5_output_route`，全量已生成Conv审计入口为`tools/audit_operator_output_routes.py`。历史v1/v2/v3 freeze只读排除，当前模板和可重生配置必须全部通过。

### 6.7 `special_array`

- 正式`ndp-sim-ref/jsons`目录内的既有SA JSON仍均为FP16且`bias_enable=0`；本项目新增的`conv_1x1_real.json`是经伪代码裁决产生的项目级INT8+bias配置，并已由正式encoder两次编码。不得把“项目候选已编码”改写成“上游正式目录原有INT8 Conv模板”。
- C6已把6个SA模板全部逐项锁定：3个GEMM、3个GEMV，只有两个decode GEMV通过buffer5进入GA `sum`后转成FP16 D；其余模板由SA直接写D。5个动态handler虽存在，但源码docstring均明确为`Placeholder`，handler存在不能替代完整规则证明。
- 正式ResNet dense形状为`M/N/K=16/1000/2048`；现有local GEMM handler按32分块会得到`M//32=0`且N余8。未定义tail前必须拒绝，禁止用整数除法静默漏算。
- ResNet模型现已确认53层Conv语义为 **UINT8 activation × INT8 weight + INT32 bias**，weight zero point全为0，weight scale按输出通道；这是软件计算真值。A/B物理端口、lane顺序和寄存器datatype仍需目标架构contract确认。
- Conv/MatMul沿K tile累加时，首tile装载bias或初始psum，中间tile读取/写回int32 psum，末tile执行requant；每个阶段是否拆成独立JSON由目标配置状态保存能力决定。
- SA的row/col mask、输入端口、output transout last-index、bias enable和psum位置必须能够反查 `hw_op_id` 与tensor端口。
- INT8路径不允许使用FP16 packing或float32中转int32 psum；中间位宽、overflow、rounding、saturation和可选ReLU顺序写入quantization contract。

### 6.8 `general_array`

- GA负责max、sum、加减、乘常量、类型转换、rounding和saturation等逐元素/归约后处理；选择opcode前必须先写出完整数学式和输入/输出dtype。
- 多版资料存在3-bit/5-bit opcode冲突；未冻结目标寄存器表时，只能保存逻辑operation name和candidate opcode，不能把旧数值当批准值。
- UINT8 MaxPool、QLinearAdd、AvgPool requant和Dequantize必须确认GA比较/转换是否按unsigned解释；用signed `int8_max` 代替UINT8 max是不成立的。
- constant应记录来源tensor、原始float值、派生定点表示、bit pattern和适用版本；禁止只在handler里保留不可追溯整数。
- mask、输入路由、输出路由和GA PE空间展开必须与buffer layout一致，不能靠默认全开掩盖tail或广播。
- C6的11个sum族模板均只配置GA/stream/buffer，没有任何N2N或neighbor；名称中的`remote`只表示输入已经被外部阶段放入A流，不能据此宣称JSON自身完成跨slice传输。
- sum族归约PE的`transout_last_index=1`及input/output full/row/col的2/3/4引用链只能证明静态字段关系，不等于硬件start/done/interrupt或跨slice完成协议已经验证。
- `summac`模板是mul结果同时进入summac两端形成平方累加，服务RMSNorm；`sum_rec`是sum后接REC/SFU，服务softmax。二者均不能代替GAP除法、qparams和UINT8 requant。

### 6.9 列表顺序、默认值和越界规则

- JSON数组顺序是硬件端口顺序，不是可任意排序的集合；每项必须有唯一逻辑ID和物理slot。
- 缺失必需项、列表长度错误、字段越界、负stride、非整数地址或unknown opcode必须使生成失败。
- 默认值只适用于寄存器表明确声明的reset/default；不得用0静默替代缺失shape、qparams、地址或source。
- 所有整数编码前检查范围，禁止Python截断、负数无说明补码化或高位静默丢弃。
- 生成后用mapping review/decoder反解并与目标字段逐项round-trip；只比较最终bitstream长度不够。

## 7. 从 DeepSeek 算法反推出的复合规则

DeepSeek资料用于学习“模型计算如何拆成原子配置”；虽然其execplan同样使用28个slice，但不能把LLM shape、按数值编号的隐式routing或FP16数据类型直接移植到ResNet。

### 7.1 RMSNorm

- 语义链为平方/累加→均值与epsilon→rsqrt→原输入乘归一化因子→乘gamma。
- sum、rsqrt和逐元素乘可能由多个GA/stream阶段组成；中间tensor、dtype和layout必须显式进入manifest。
- handler必须同时联动hidden size、归约长度、stream stride、buffer full index和constant；只改顶层shape不够。

### 7.2 Softmax

- 稳定softmax拆为max→减max→exp→sum→除法/倒数乘。
- max与sum归约的loop/last事件不同于逐元素阶段；中间max/sum需要明确广播路径。
- 现有复合模板可证明多JSON串联方式，但不能证明GA exp/div opcode和数值误差已经与目标RTL闭环。

### 7.3 RoPE

- RoPE依赖偶/奇通道配对、sin/cos表和旋转后的重排；配置与relayout共同决定配对关系。
- table地址、position offset和通道stride必须作为参数，而不是依赖文件名或固定layer0。

### 7.4 GEMM/GEMV

- 统一计算视图是 `A[M,K] × B[K,N]`，但local/ring、prefill/decode和不同物理layout会改变K分片、N/M分片与N2N次数。
- local适合数据在单slice闭合；ring通过邻居传递完成跨slice归约。选择依据是tensor归属和通信，不是算子名称。
- 现有FP16 GEMM/GEMV可用于LC/AG/Buffer/PE/ring结构参考；ResNet INT8 MatMul仍需独立bias/psum/requant和1000类tail设计。
- ring模板证明的是SA操作数沿N2N传输；没有显式INT32 psum stream，不能把操作数广播误写成跨slice psum归约。
- ResNet QLinearMatMul本身没有bias输入，模型中的dense bias位于后继QLinearAdd；`bias_enable=0`与这一模型拓扑一致，但不证明硬件bias融合或psum入口可用。

## 8. Shape参数化和 `model_execplan` 集成规则

静态JSON只是模板；每个网络实例必须由manifest生成独立patched JSON、bitstream和配置记录。

### 8.1 动态handler必须覆盖什么

- 所有由shape变化引起的LC start/end/stride、LC-PE constant、stream idx/size/stride、padding/tail、buffer full index、SA/GA mask和N2N次数。
- 所有由dtype/layout变化引起的byte stride、transaction packing、address remapping和输出行宽。
- 所有逐层qparams、bias和派生constant。当前 `OperatorSpec/TensorSpec` 对数值attributes承载不足，是必须补的schema缺口。
- handler输出字段级provenance：来源tensor/attribute、公式、目标字段、范围和测试ID。
- 未解析字段必须失败；不得打印unresolved warning后继续生成execplan。

### 8.2 地址规则

- base address由统一memory planner分配，模板中的地址只作占位；JSON、cfg_pkg、Bank_data和execplan引用相同地址计划hash。
- 地址记录byte/word单位、alignment、slice/bank、`[base,end)`、live range和复用来源；验证无越界、无非法重叠、无读取已释放/未初始化区域。
- producer D与consumer A只有在layout contract完全相同时才能zero-copy；否则由write remap、read remap或显式relayout承担转换。
- 目标使用完整28-bit指令mask；每条命令的mask必须由profile和实际物理slice集合生成，并验证未选slice不执行。旧“只开低16位、高12位为0”规则已废止。

## 9. 数据布局和relayout是配置的一部分

- 每个tensor分别声明logical shape/order、partition轴、padding/tail、tile顺序、lane packing、128-bit行内端序、bank/interleave和address remapping。
- 每个变换必须提供 `forward(raw)->physical`、`inverse(physical)->raw`、`explain_coordinate()` 和 `validate()`。
- 整数raw→physical→raw必须bit-exact；失败时先修layout，不进入JSON数值调试。
- activation、weight、bias/qparams、psum和D不能假设使用同一轴序；复合算子拆分后的中间tensor也必须有layout记录。
- DeepSeek的28-slice relayout脚本只会拼装已有数据，不能推导ResNet布局；`conv_layout.py`的im2col `KH,KW,C`、M/K/N对齐16/8/16和4×INT8小端lane是候选参考。

## 10. 验收规则

### 10.1 静态JSON验收

- 严格schema、列表长度、字段范围、source存在性和目标架构版本检查。
- 固定seed生成bitstream并保存mapping review；decoder逐字段round-trip。
- placement失败、unknown field、unresolved constant和silent truncation均判失败。

### 10.2 参数化验收

- 每个算子族至少覆盖微型shape、真实ResNet shape和tail shape。
- 改变shape/qparams时，所有相关loop/stride/constant/mask/address字段必须联动；无关字段保持稳定。
- 相同模板的多个实例各自保存patched JSON和hash，禁止运行时共享被修改的单文件。

### 10.3 数值验收

- 同一physical input分别进入软件subop golden、目标simulator和硬件；输出先保存physical D，再inverse为logical D。
- UINT8/INT8/INT32默认bit-exact；FP16/FP32在manifest声明tolerance。
- 报告首错node/hw_op/slice/逻辑坐标/物理地址和值；上游失败后停止给下游独立归因。
- bitstream生成成功不属于数值验收。

- layer0别名引用24个复合模板，但目录仅有3个，默认完整生成无法完成。
- 28 slice导致hidden size静默整除截断风险；GA constant存在unresolved告警。
- 上游`ndp-sim-ref`的relayout仍只覆盖LLM，emulator导出只写输入包；但根集成层已在W4补齐ResNet七族28-slice正逆变换，不能再把“缺ResNet relayout”列为项目现行阻塞。
- 缺硬件结果、逐算子inverse和三方报告，因此不能证明DeepSeek已有工作达到最终闭环。

## 12. 应用于ResNet50 INT8的具体判断

### 12.1 已从旧ResNet计划确认的调度骨架

- 模型共有77个模型级原语：2 Quantize、53 Conv、1 MaxPool、17 Add、1 AvgPool、1 MatMul、2 Dequantize；Flatten/View不搬数据。
- Conv首/中/末K tile分别执行bias初始化、int32 psum累加和末次requant；MatMul bias由后继Add处理。
- 77原语不是最终JSON实例数；一个模型节点可lower成多个 `hw_op_id`。

### 12.2 从正式模型和QNN源码补出的计算与候选布局

- 当前暂定模型hash见 `contracts/model_baseline.json`；算子数量与旧计划完全一致。
- 53层Conv均为UINT8 activation、INT8 weight、INT32 bias、per-output-channel weight scale，weight zero point全0；input/output zero point并非全0。
- QLinearConv软件式为 `sum((x-x_zp)*(w-w_zp))+bias` 后按 `x_scale*w_scale/y_scale` requant；bias实数scale为 `x_scale*w_scale`。
- SA采用8×8、K步长8；Conv物理视图为im2col A[M,K]×B[K,N]。W4合同已批准HIGH-4物理布局，首个真实1×1又验证了该布局下的配置绑定P/D；其他shape与3×3仍需逐实例验证，不能从首例外推。

### 12.3 不能直接复用的地方

- ADR-008确认DeepSeek工具所在固定commit就是正式硬件配置来源，因此JSON字段、当前编码器和execplan框架不再只是“相似参考”；但现有模板主要服务FP16/FP32 LLM，不能把其shape、数据类型、常量或调度直接复制为ResNet实例。
- ADR-008原始库存中的6个SA JSON均为FP16且bias关闭，当时没有可直接复制的INT8 Conv/MatMul模板；项目现已从语义合同派生首个1×1累加与requant配置，但原始库存事实不因此被改写。
- Pool族三个正式静态模板以及Quant/Add-Dequant两个GA模板的结构、寄存器、确定性、差分敏感性和溢出前置拒绝已经通过；但AvgPool模板只到int32 sum，MaxPool unsigned语义仍未闭环。Quant只确认到INT32 requant魔数配方和RTL静态clamp，Add-Dequant只到两路FP32仿射和；正式qparams transport、目标rounding执行、完整QLinearAdd/AvgPool requant仍需继续闭环。
- C6进一步确认6个SA GEMM/GEMV与11个sum族模板都能由正式编码器确定复现，但这只证明配置编码与零违规placement。MatMul仍缺INT8/tail/qparams/zero-point correction/INT32 psum/requant；sum仍缺真实跨slice传输、硬件完成协议和输出requant。
- `sum_config_32_32`是唯一共享/ResNet候选sum模板，但只到假定FP32 local sum，既无base-info也无handler；`prefill_remote_sum_4slice_fp16MN_fp32MN`的base-info又与只流A/D的JSON及4→1归约意图冲突。冲突未解决前不得进入正式实例生成。

### 12.4 Pool族三个模板确认的形状联动

- 三个模板共用`shape→DRAM LC/LC-PE→read/write stream→ROW/COL LC与buffer→GA`五段链。shape先决定循环范围、归约长度、tile和padding；LC/LC-PE再产生仿射索引和完成事件；stream据此给出transaction、byte stride、有效范围和lane展开；buffer必须引用同一完成事件；GA最后选择lane、dtype转换、opcode和输出时机。
- 两个MaxPool模板除地址外有16个shape/调度叶字段变化，全部已经逐项解释；另有2个`base_addr`变化属于统一memory planner，不是shape公式，禁止由文件名或tensor大小自行猜地址。
- 当前MaxPool精确证据只覆盖`C=16`、`K=3/S=2/P=1`、`W%16=0`的两个非tail模板：`LC0.end=C/4`，`LC1=[0,H) step 2`，`LC2.end=W/16`，`LC3/LC4.end=3`，`LC5=[0,16) step 2`，`LC6.end=Hout`，`LC7.end=Wout/8`；read byte stride为`[4,4W,4HW]`，write为`[4HoutWout,4Wout,32]`。
- MaxPool的LC-PE把输入坐标组成`row=LC1+LC3`、`col=LC2*16+LC4+LC5`。`low/up`表示包含端点的原始有效区；当前模板把高/宽有效范围写成`[1,W]`和`[1,H]`，范围外才padding。
- `W/16`从7变成1时，A-buffer完成事件会从last-index 6前移到5；`GROUP0.ROW_LC`源、ROW/COL last-index、read stream的`buf_full_last_index`/`buf_idx_keep_last_index`和`buffer0.buf_full_last_index`必须整体联动，禁止只改LC end。
- AvgPool模板确认`C=2048,H=W=7`时`LC0.end=C/8`、49个空间元素padding到56、read transaction为8×4且byte stride为`[49*8,8]`、有效范围为包含端点的`[0,48]`。输入GA先做`uint8toint32`，八个PE执行`int32_sum`，输出仍为int32。
- AvgPool的`round_up(H*W,8)`目前只有一个shape样例，属于待第二shape验证的候选参数化公式；不得直接推广到其他H/W或tail。
- AvgPool现有JSON没有除以`H*W`、`x_scale/y_scale` requant、nearest-even和uint8 saturation，因此只批准“uint8输入到int32空间和”的静态配置链，不是完整`QLinearGlobalAveragePool`。
- UINT8 MaxPool padding和`int8_max`符号解释仍必须由目标数值模拟/硬件语义批准，不能因bitstream能生成就默认正确。

### 12.5 Quant与Add-Dequant模板确认的GA规则

- `quant_from_buffer_int32MN_uint8MN`输入是INT32 buffer，不是ONNX `QuantizeLinear`的FP32输入。GA先做`int32tofp32`，八路MAC把输入乘以固定0.06375并加入FP32舍入魔数，八路`int32_sub`再减raw `0x4b400000`，末端`int32touint8`输出UINT8。
- JSON字面量`12582975.75`编码成FP32后实际为`12582976.0/0x4b400040`；与魔数`12582912.0/0x4b400000`相差64，因此静态样例把输出zero point 64藏在魔数加数中。正式配置必须把每个tile的multiplier复制到八个MAC multiplier constant，把`fp32(12582912+y_zero_point)`复制到八个MAC addend，八个SUB constant保持raw `0x4b400000`。
- RTL静态证据确认`int32touint8`只负责clamp：负值到0，高于8位到255，否则取低8位；它不做scale、zero point或rounding。首个真实1×1的8份requant配置已由NDP config-bound功能路径对全算子P验证，与nearest-even golden逐元素一致，状态更新为`config_bound_functional_passed_hardware_unvalidated`；该证据不外推到其他算子，也不证明逐周期或硬件执行。
- `add_dequant_uint8CWH_uint8CWH_fp32CWH`两路都做`uint8tofp32`，四组lane分别执行两支MAC再ADD，静态常量给出`(A*1+1)+(B*1+1)`，D保持FP32。正式两支反量化常量应分别为`a_scale/-a_zero_point*a_scale`和`b_scale/-b_zero_point*b_scale`。
- Add-Dequant模板没有`y_scale/y_zero_point`、rounding或UINT8 saturation，不能直接当作QLinearAdd，也不能把“先QLinearAdd再Dequantize”的量化误差/夹断静默融合掉。需要UINT8 D时必须有经过数值验证的额外requant序列或新模板。
- 锁定ONNX内2个Quantize、2个Dequantize、17个QLinearAdd的scalar qparams均与上述静态样例不直接匹配。模板常量只能由模型qparams派生并逐实例/逐通道tile patch，禁止作为默认值复制。
- 历史`e299b28...`的两个execplan handler只修改LC end与stream stride，旧`OperatorSpec`没有typed qparams/attributes。当前`056b1c3...`已经扩展schema，显式保留initializer/tensor ID、dtype、shape、值/hash、派生公式和目标写入位置；Conv adapter不得退回从文件名推断或把FP32 scale塞进整数`params`。Quant/Add-Dequant等其他算子handler仍须逐族实现字段消费。

### 12.6 ResNet50各阶段开工前的决策门

- 开始layout实现前：确认或版本化tensor物理合同；candidate实现必须可替换。
- 开始配置规则分析前：固定ADR-008来源并通过字段/范围/资源/确定性审计；这部分现在可以继续。
- 生成正式W5 bitstream前：G4已授权，目标物理layout/profile已经批准；首个真实1×1的累加与64通道requant实例已经冻结并通过正式编码和config-bound P/D。后续从第二个1×1开始仍须逐实例闭合typed qparams、INT8 SA/psum/requant字段和范围；在shape-family与真实3×3代表例通过前不得批量生成整网。
- 开始硬件前：simulator logical D已通过，load/start/wait/dump协议已冻结。

## 14. 首个真实1×1 Conv反向修订出的规则

本节来自`conv_full.json/.txt`、正式encoder、`conv_1x1_real.json`和NDP request实测，优先于本文前面从DeepSeek模板概括但未被新证据覆盖的表述。完整逐LC/PE/stream表见`contracts/conv_1x1_lc_pe_stream_semantics.{json,md}`。

### 14.1 伪代码不能按注释名直接抄写

- 同一个循环必须同时核对符号、range、source/last-index、下游PE公式和stream stride。旧TXT/早期JSON中的名称只作反例；v19 compute链固定为`LC0 Kblock → LC1 H → LC2 Qblock → LC3 activation Cquartet`。
- weight支路使用`LC6 HIGH-4 step → LC7 local Cquartet`；P写回placement replica为`LC13 Kblock → LC14 H → LC15 Qblock`，`LC9`展开Q8 lane。
- v18证明辅助tensor不能复用主compute触发链的简化假设；bias必须由独立`LC10 Kblock → LC11 H → LC12 Qblock`逐tile触发。
- 仿射式`a*x+b`必须使用能表达加法的`mac`。正式encoder接受字段只证明可编码，不能替代PE公式和consumer语义审计。

### 14.2 target字母是配置端口，不保证等于项目逻辑角色

历史学长伪代码曾把target A解释为weight、target B解释为activation；该映射已经被当前physical合同否定，只能作为负向样本。v19配置与项目逻辑端口一致：A/stream0=UINT8 activation，B/stream1=INT8 weight，C/stream3=INT32 bias，D/stream2=INT32 accumulator P。adapter仍必须显式校验port-role map，不能靠字母猜测。UINT8逻辑D不在SA-only累加JSON中编码，而由8份绑定的requant JSON产生。

### 14.3 stream轴序必须用stride反证

`idx`、`idx_size`和`dim_stride`必须作为一组审计。v19四个stream均为32 B事务：activation为`idx=[LC3,LC2,LC1], stride=[32,128,896]`；weight为`[PE0,LC0], [64,32]`；P写回为`[LC13,PE1,LC14], [32,64,3584]`；bias为`[LC10,LC11,LC12], [32,0,0]`。bias的零stride不是“不循环”，而是H/Qblock继续触发、地址保持同一K8行。旧`[12544,4,224]`和stream3 128 B描述只属于已撤销候选，不能再作为current裁决。

### 14.4 正式encoder和数值adapter各证明什么

- v19正式encoder两次证明：33条连接、16/20 LC、2个实际使用LC-PE可零违规placement；字段、资源、位宽和bitstream确定性成立。旧46连接/7个LC-PE属于被后续physical合同替换的历史候选。
- target request schema 0.3重新读取累加JSON、语义合同、requant manifest和8份requant JSON原文，校验各自SHA-256；累加侧逐LC range、逐PE source/constant/opcode、逐stream target/idx/size/stride及N2N `mem_loop/src_slice_sel/dst_slice_sel`，requant侧逐64通道覆盖、GA常量、HIGH-ring slice、16B地址、LC `1/9408/2352`和唯一flush；任一漂移必须在执行前失败。
- 单坐标走真实`SpecialPEA`组件，首tile和全算子因规模采用NDP入口内的physical-DRAM批量INT8等价核。二者必须分开标注；批量等价通过不能宣称逐周期LC/stream/buffer解释通过。
- 当前首例实测范围依次为1、150528和3211264个P/D元素，均与W3 bit-exact；E1/E2也完成同样三档门。28个slice的staging D均inverse回canonical D；它解除“shape lowering未完成”“没有config→request adapter”、`B_REQUANT_TARGET_NUMERICS`和`B_EXECPLAN_TYPED_TRANSPORT`。v19已从新candidate/preflight/freeze生成freeze-bound单算子服务器包；剩余工作是目标服务器自然执行与原始P/D证据、其他shape/算子handler和整网闭环。
- N2N不能只验证字段范围。HIGH-4规则固定为`mem_loop=4, src/dst selector=1`，LOW-28规则固定为`mem_loop=28, selector=0`；register/execplan把1绑定到jump-4/HIGH路径。当前真实1×1已编码为`1/1/0/00011`，逻辑字段串`11000011`；旧`mem_loop=4, selector=0`组合必须在NDP计算前失败。`ping_pong=0`未随selector机械修改，仍由Conv buffer生命周期另行裁决。

### 14.5 LC-PE opcode冲突的处理

正式consumer `bitstream/config/loop.py`把`add/mul/mac`编码为`0/1/2`；CSV备注仍写`add/mul/max`。新增配置以实际consumer为编码权威并使用`mac=2`，但`inport0*inport1+inport2`算术公式仍作为adapter语义合同保存，不能仅由encoder源码冒充RTL逐周期证明。规则文档遇到“CSV注释”和“实际消费代码”冲突时，必须同时记录编码裁决与未证明的运行语义，不能二选一后删除边界。

### 14.6 输出生产者路由必须先于编码冻结

- v3在170/170预装回读、56/56次旧P确定性读取均正确后仍出现56个写地址、0个写数据和0个slice完成；源码审查发现SA-only accumulate把`buffer5.dst_port`写成1，错误选择了当前阶段不存在的GeneArray结果。这是必须修复的配置错误，但v4受控反事实已证明它不是解除当前停顿的充分条件，不得继续写成已证明的唯一根因。
- 此类错误不会改变Conv数学，配置绑定功能模型也可能因为直接执行数学而漏检；因此必须在数值执行前单独验证“配置阶段→真实阵列对象→buffer producer选择→写stream”路由链。
- 受控源模板`conv_full.json`、首例和所有已生成accumulate必须统一为0；所有GA requant shard必须为1。生成器不得只在最终首例上覆写模板错误，否则新实例仍会继承隐患。
- v4的配置beat已在服务器Bank写入、MC读回和全部28个slice的gconfig广播中从`fa...`变为`f2...`，而runtime trace与v3逐字节相同。以后配置根因必须经过这种单变量硬件反事实验证：字段已到达内部消费点且预期下游行为发生变化，才可称为直接根因；否则只能称必要修复或候选原因。
- 最低验收顺序固定为：route invariant通过→正式encoder双跑一致→decoded字段命中预期producer→config-bound P/D通过→freeze/package新身份→硬件内部寄存器命中→RTL write-data/slice-complete。前一门失败不得继续打包。

### 14.7 SA outport主序必须以RTL位义为准

- RTL `SA_Outport_Connect.sv`规定`sa_outport_major=0`为row-major、1为col-major；正式JSON encoder当前却把标签`col`编码为0、`row`编码为1，`excel_config.py`的说明又与RTL一致。标签存在实证冲突时禁止按英文名直接推导，必须同时记录JSON标签、编码bit和RTL数值语义。
- 当前上游可执行GEMM样例使用JSON `col`/编码0，GEMV样例使用JSON `row`/编码1；项目Conv原先为GEMM却使用JSON `row`/编码1。现行生成器和消费前不变量已经统一要求GEMM使用JSON `col`，并补了把它改回`row`即失败的负向测试；正式encoder确认v4→v5的128-bit配置只改变这一位且编码为RTL row-major=0。
- 在v5反事实或内部波形证明前，不能把主序位写成已确认根因；它可能导致次序、backpressure或tag组合错误，也可能只是重排。必须观察SA output valid、SpecArray到buffer5 valid和MSE prepared链来裁决。当前只把规则用于首算子`node-0004`与未来生成器；首算子硬件跑通和稳定复跑前，不批量刷新或新生成其他ResNet50算子。
## 15. 距离“从计算流程直接写出每项配置”还缺什么

### 15.1 当前已经能直接决定的内容

- 模型算子组成、shape/attributes/initializer/qparams和软件数学公式。
- LC采用 `[start,end)`、LC控制循环、`last_index`引用循环层级结束事件。
- stream `idx_size=dim-1`、`dim_stride`按byte、padding low/up包含端点、transaction保守不超过128。
- 4个INT8按低字节到高字节装入32-bit lane，128-bit物理行和address remapping的基本组织。
- 旧ResNet首/中/末K tile顺序和77原语拓扑。

### 16.1 旧ResNet50计划可以精确还原为77个原语调用

| 网络段 | Quantize | Conv | MaxPool | Add | AvgPool | Dequantize | MatMul | 合计 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| stem | 1 | 1 | 1 | 0 | 0 | 0 | 0 | 3 |
| stage1，3个残差块 | 0 | 10 | 0 | 3 | 0 | 0 | 0 | 13 |
| stage2，4个残差块 | 0 | 13 | 0 | 4 | 0 | 0 | 0 | 17 |
| stage3，6个残差块 | 0 | 19 | 0 | 6 | 0 | 0 | 0 | 25 |
| stage4，3个残差块 | 0 | 10 | 0 | 3 | 0 | 0 | 0 | 13 |
| head | 1 | 0 | 0 | 1 | 1 | 2 | 1 | 6 |
| **总计** | **2** | **53** | **1** | **17** | **1** | **2** | **1** | **77** |

其中16个residual add各消费6个量化initializer，最终FC bias add消费bias加6个量化initializer。旧脚本按字典插入顺序消费327个参数项并把最后一项作为input0，即至少依赖328个有序项；正式实现必须改成稳定tensor ID映射。

旧计划还确认：

- Conv有27种shape/tile组合，不是53套不同算法。
- stem Conv padding value为模型input zero point 114；后续padding必须按各层输入zero point/layout规则生成，不能统一写0。
- batch固定16且旧计划按一张样本一个slice调度；这只是历史16-slice合同。当前RTL28主profile固定七个HIGH小环，batch样本分组为`[3,3,2,2,2,2,2]`，环内再按C/K owner分片，禁止把旧调度机械扩成28。
- Flatten/View不搬数据；新执行计划只有在上下游layout合同相同才允许zero-copy。

### 16.2 旧 QNN 预处理器的适用条件已经能从代码判断

- Conv：`scale_eff=x_scale*w_scale/y_scale`，`bias_eff=bias-x_zp*sum(w)`；代码删除了 `w_zp`，所以完整成立依赖 `w_zp=0`。
- MatMul：同样计算 `x_scale*w_scale/y_scale`，但直接删除输入和权重 zero point，没有任何补偿；只有相关输入和权重 zero point 都为 0 时才与一般 QLinearMatMul 等价。
- AvgPool：只保留 `x_scale/y_scale`，软件算子明确限定 `x_zp=y_zp=0`。
- Dequantize：可折成 `y=x*scale-scale*zp`。

这些是旧实现的前提，不应被默认为目标模型必然满足；应从正式 ONNX initializer 批量验证，而不是再向学长询问数学公式。

### 17.4 Partition、relayout 和 packing 规则

每个物理变换必须成对提供：

```text
forward(raw tensor) -> per-slice physical bytes
inverse(per-slice physical bytes) -> raw tensor
```

- 模型batch固定16；RTL28主profile按七个HIGH小环分配`[3,3,2,2,2,2,2]`个样本，环内activation/weight/bias/qparams/psum/D再按算子端口声明owner。旧“一张样本一个slice”仅属legacy16回归，不得作为current默认。
- activation、weight、bias/scale/zp、psum、D 分别声明 layout，不能假设同一轴顺序。
- padding 值来自算子语义：Conv activation 通常用输入 zero point，uint8 MaxPool 软件基线为 0，weight/tail 需单独定义。
- 128-bit 行内 packing、buffer lane、bank/interleave 和 address remapping 必须分层描述，避免把 relayout 和 remapping 混成一个不可逆脚本。
- raw→physical→raw 对整数必须 bit-exact；失败时先修数据链，不进入 JSON 数值调试。
- 上游 D 到下游 A 的物理 layout 不一致时，明确由 producer write remap、consumer read remap 或显式转换解决。

#### 17.4.1 RTL28 C1公共布局冻结规则【2026-07-13已完成】

- current代码必须显式使用`TARGET_DRAM_GEOMETRY28`；legacy16回归必须显式使用`LEGACY_DRAM_GEOMETRY16`。禁止恢复无参数`DramGeometry()`默认值。当前DRAM geometry与address order已经由ADR-009的DeepSeek公共物理合同批准用于W4；这不自动批准W7整网地址分配或W8板级物理映射。
- `w4_group4x7_batch_channel28_candidate_v1`按七个RTL HIGH环分配固定样本区间`[3,3,2,2,2,2,2]`，每环严格按`HIGH_RING_OWNERS`的四个owner切分F/C轴；每owner保留3个sample存储槽，2-sample组的第3槽是显式inactive tail。
- `w4_global_ring28_candidate_v1`保持16个样本本地，严格按`LOW_RING_OWNERS`的28-owner顺序切分F/C轴。两个profile都不得用数值slice相邻或`%28`推导owner。
- 逻辑`N,F,...`在本地物理区写成`N,...,F-local`；元素小端，端口区16-byte对齐。Quantize的FP32 A tail为`0.0`、UINT8 D tail为输出zero point；Dequantize的UINT8 A tail为输入zero point、FP32 D tail为`0.0`。
- 标量scale和zero point在全部28个slice逐字节复制；任一副本不同必须fail-closed。每个端口必须保留独立placement、region、base address、payload和padding来源，后续算子不得假定qparams与data同分片。
- Flatten/View仅在`axis=1`且输入为`[N,F,1,...,1]`时允许零拷贝；输出与源tensor共享全部28个base address和physical bytes，只改变逻辑shape。其余View必须拒绝或走未来显式relayout。
- current公共入口为`resnet50_pipeline.layout`/`simple_layout.py`；旧16实现只在`simple16_layout.py`供legacy测试直接导入。group4x7 simple/view布局已由混合profile选中并获得W4批准；对应LOW-28布局仍是gate-ineligible替代。

#### 17.4.2 ResNet50 逐算子 relayout 必做清单

以下均为**需完成**，必须提供 forward、inverse、manifest 和 round-trip 单测：

| 算子族 | 必须覆盖的数据 | 状态 |
|---|---|---|
| QuantizeLinear | FP32 A、scale/zp、UINT8 D | W4 group4x7布局已批准；数值字段在W5 |
| QLinearConv | activation A、OIHW weight B/B'、bias/qparams C、int32 psum、UINT8 D | W4布局已批准；逐tile/数值配置在W5 |
| MaxPool | activation A、padding/tail、D | W4布局已批准；目标执行语义在W5/W6 |
| QLinearAdd | 两路分支 A/B、各自 qparams、广播/对齐、D | W4双分支布局/alias已批准；requant在W5 |
| QLinearGlobalAveragePool | A、int32 sum/中间值、requant 参数、D | W4布局已批准；除法/requant在W5 |
| QLinearMatMul / dense Add | feature A、weight B/B'、bias/qparams、psum、D | W4布局已批准；INT8/psum/requant在W5 |
| DequantizeLinear | UINT8 A、scale/zp、FP32 D | W4 group4x7布局已批准；数值字段在W5 |
| Flatten/View | 证明物理零拷贝，或实现显式 forward/inverse 重排 | W4 singleton-spatial零拷贝已批准 |

复合算子拆成多个硬件原子算子时，relayout 任务随 `hw_op_id` 拆分；中间 psum/sum 也必须有明确 layout。即使上游输出可直接被下游消费，也要把共址条件、兼容 layout 和不搬运依据写入 manifest。

### 17.5 目标模拟器规则

- 目标模拟器必须执行当前 JSON/bitstream 所描述的 LC、stream、buffer、SA/GA 数据流；旧 `.cu` 功能模拟器只能作为额外软件参考。
- `NDPFuncModel/conv_func@cb262bb9...`已对首个真实1×1完成manifest/JSON参数化、28-slice ingress、int32 ring reduction、64通道requant、双staging写回/inverse和唯一flush校验。由于首tile/全算子仍使用physical-DRAM批量等价核，而非逐周期LC/stream/buffer或bitstream解释器，该结果只标`config_bound_functional_passed`，不能升级G6。
- Conv JSON adapter对首例已经建立逐字段语义合同与port-role map；后续每个shape仍必须让loop/last-index、RDAG/WRAG维度/stride/padding、buffer/ping-pong、PEA dot/psum、ring和writeback反查到JSON字段与manifest tensor，不能把旧Python main常量当隐式配置。
- 首例已经完成单坐标、首tile和全算子QNN/W3 golden对config-bound NDP P/D的bit-exact差分。第二个1×1、真实3×3和tail shape必须重复该三档测试，不能从首例机械外推。
- `write_emulator_bundle()` 生成输入包不等于模拟执行完成；必须有实际 runner、退出码、超时、日志和 D dump。
- simulator 必须使用与硬件相同的 physical input/config；不得用 raw tensor 绕开 relayout。
- 输出先按物理地址提取，再 inverse-relayout；保存 physical D 和 logical D 两份文件。
- 单算子只有在 logical simulator D 与对应 subop/ONNX golden 通过后，才允许进入网络 execplan。

### 17.6 Execplan 生成规则

- 网络级 JSON 必须从 lowering manifest 生成，不手写完整 ResNet op/source/shape 顺序。
- 所有slice逻辑统一到目标28；execplan必须生成完整28-bit mask、per-slice WREG和ADR-007真实HIGH/LOW routing，并测试七组3/2样本调度。
- execution-plan schema 必须能承载或引用逐层 qparams/attributes，不能把浮点 scale 放入会被忽略的顶层 `params`。
- 每个实例都要得到独立 patched JSON、bitstream、配置地址和 control write；相同 op type 的共享必须有常量/shape 完全相同的证据。
- bitstream 失败、缺模板、缺数据、缺 handler、字段越界和 unresolved control 一律使流水线失败；不得打印后继续生成貌似完整的 execplan。
- execplan、cfg_pkg、Bank_data、sca_cfg 和 emulator bundle 必须引用同一 manifest 和文件 hash。

### 17.7 RTL/硬件运行规则

- hardware runner 记录 RTL/板卡/固件/ISA 版本、时钟、配置 hash、输入 hash和命令日志。
- 明确 byte/word 地址单位、端序、slice/bank 编号、config/data 装载顺序、start、完成判定和超时。
- 优先使用单算子 execplan 验证；若支持逐层 checkpoint，再扩展到子图/整网中间 dump。
- hardware physical D 必须原样保存，不能只保存人工转换后的文本。
- 同一运行包必须以两个不同的正式run ID（当前固定`run1`、`run2`）各执行一次，分别保留回传ZIP；回传验收先对两轮执行完整身份/合同门，再逐region比较路径、行数、大小和SHA完全相同，只有稳定性门通过后才允许进入三方比较。

### 17.8 三方比较规则

三组比较都必须执行：

```text
golden vs simulator
golden vs hardware
simulator vs hardware
```

- 比较前统一恢复为逻辑 tensor shape/order；同时保留物理文件的 byte-level 比较用于定位 packing 问题。
- UINT8/INT8/INT32 默认 bit-exact；FP32/FP16 必须在 manifest 中声明 `atol/rtol`。
- 报告第一处错误的 `onnx_node_id`、`hw_op_id`、slice、逻辑坐标、物理地址和三方数值。
- 整网失败时按拓扑顺序定位第一处错误，不对被污染的下游节点分别猜因。
- 比较报告必须同时给出 missing、shape mismatch、dtype mismatch、layout/inverse failure 和 value mismatch，不能把缺文件当数值失败。

### 17.9 最终完成判据

只有同时满足以下条件，才能宣布 ResNet50 INT8 完成：

1. 从正式 ONNX 和固定输入可一键重建 manifest、golden、physical data、JSON/bitstream、execplan 和 Bank_data。
2. 每个验收原子算子的 input/output、qparams、layout、地址和配置可追溯。
3. 所有目标 JSON 通过目标 emulator 数值验证。
4. 同一配置包通过 RTL/硬件运行并可导出结果。
5. 整数中间结果三方 bit-exact，批准的浮点结果在 tolerance 内。
6. 完整网络最终 logits/分类结果三方一致。

静态 bitstream、单个最终输出、旧 `.cu` simulator 通过、只比较两个物理文件，或缺少 inverse-relayout 的“相等”，都不满足最终完成定义。

### 17.10 Conv per-channel requant新实测规则（2026-07-15）

- DeepSeek `quant_from_buffer_int32MN_uint8MN.json`的GA由8条`mac→int32_sub`链组成；真实Conv的64个float32 multiplier全部不同，必须按8 lane拆成8个channel-disjoint shard，不能用一个标量机械复制。
- HIGH-4每个owner step对应7个slice；同一shard只作用于`[ring[owner_step] for ring in HIGH_RING_OWNERS]`，四个owner step各拆local K `[0,8)`和`[8,16)`，64个global K必须恰好覆盖一次。
- stream `base_addr`编码低4位不保存。正式encoder可能接受非16B对齐整数并静默丢低位，因此生成器/validator必须在编码前显式要求16B对齐，不能把“encoder exit 0”当作地址正确证明。
- canonical D的local K半块偏移8B不能直接作为第二个shard base。首例使用两个16B对齐的8-channel UINT8 staging区，硬件/模拟器先写staging，再以显式inverse把两个`[spatial,8]`半块交织回canonical NHWK `[spatial,16]`；原始staging与canonical D都必须保留比较。
- 当前实测round路径为float32乘法，加`0x4b400000`对应magic，再做`int32_sub 0x4b400000`并`int32touint8`饱和；必须对真实全算子P验证与nearest-even golden逐元素相同。

### 17.11 Conv SA mask、零点与batch波次规则（2026-07-16）

- SA-only accumulate必须生成`CONFIG=11101110`；`11111111`仅适用于同时存在SA和GA的程序。该mask差异不是v1～v4首轮停顿的已证明根因，但必须消除解析器静默丢弃无GA字段造成的歧义。
- 当前SA微程序直接执行有符号weight×无符号activation，没有实现`(A-xzp)*(W-wzp)`的显式中心化。硬件preflight和freeze因此必须要求`x_zero_point=0`且所有`w_zero_point=0`；不满足时拒绝生成，直到实现activation中心化或修正bias运输。
- 静态Conv JSON只执行一个local sample slot。batch16按七个HIGH环的`[3,3,2,2,2,2,2]`分配，必须调度三轮accumulate：前两轮启用28 slice，第三轮只启用前两个HIGH环的8 slice；逻辑样本分别为`[0,3,6,8,10,12,14]`、`[1,4,7,9,11,13,15]`和`[2,5]`。
- 每轮A基址增加一个UINT8槽，P基址增加一个INT32槽；node-0004槽长分别为50176 B和200704 B。三轮全部完成后才能启动requant。8个语义requant shard中，最终shard为适配固定observer拆成`non_observer_slices`与`finish_slice_only`两个运行阶段，因此固定序列是3 accumulate + 9 requant runtime stage = 12 stage。
- 目标RTL的Neighbor Stream Engine端口当前未消费JSON `n2n.ping_pong`字段；该字段只保留为来源信息，不能作为正确性或卡点修复证据。
- 首算子通过并稳定复跑前，只把这些规则写入公共生成器和测试，不批量改写现有其他Conv candidate；后续批量重生必须统一应用本节。

### 17.12 无RTL修改条件下的诊断版本规则（2026-07-17）

- 服务器禁止修改`.v/.sv`时，允许由运行包增加UCLI/TCL、runner、安装态配置和结果打包逻辑；overlay必须机器检查`rtl_files_included=0`，且合并现有`NDP_copy01/`而不是替换整个源码树。
- 真实返回若只有Start_Comp/地址请求而没有write-data、slice completion和post-run P/D，不得继续凭猜测改数值字段。下一诊断版本可以保持配置、bitstream、Bank_data和execplan逐文件不变，但必须建立新freeze/package/overlay身份，并把“数值不变、观测改变”的范围写入manifest和交付说明。
- 大范围FSDB会显著拖慢仿真且产生超大结果；卡点已收敛到少量内部链路时，默认使用`DUMP_FSDB=0`加UCLI定向VPD/VCD。信号集至少覆盖producer输入token/tag/backpressure、producer输出valid/data/tag、目标buffer写入/ready以及consumer prepared/data valid和最终write-data valid/ready。
- 定向诊断必须设置明确仿真截止并在运行前清理旧结果。截止时间只表示观测窗口结束，不能等价为卡死、stage完成或数值通过；完整12-stage、28份post-run Bank和P/D三方比较仍需后续完整运行单独证明。
- `process_exit_status=124`只证明外层墙钟命中；必须结合最后合法stage/事务判断停滞位置。若仿真命令已明确`DUMP_VCD=0`、`DUMP_FSDB=0`和`TB_DUMP_FSDB=0`，不得把长运行或高CPU归因于波形；也不得用延长墙钟替代已经可静态确认的配置身份修复。
- runner回传包只包含当轮console/exit status、当前trace、配置身份以及定向VPD/VCD，不携带`simv.daidir`、旧FSDB或历史结果。原始返回ZIP保持只读，确需展开时在完成机器报告后删除展开副本。

### 17.13 Stream有效字节、buffer完成与physical布局规则（v8实测）

- read stream的事务有效字节数以正式encoder计算的`total_size=product(idx_size+1)`和RTL valid mask为准，不能用DDR/MC monitor打印的128-bit beat宽度代替。生成器必须把每个stream的`idx_size`作为shape派生字段显式重写，禁止从参考skeleton隐式继承。
- 在首个NRM读屏障前，producer的有效字节总数必须覆盖buffer地址循环所需的全部向量：`transaction_count × total_size == address_vector_count × buf_spatial_size`；若允许分阶段或padding，必须另行证明每个地址向量的数据、valid mask和tag一一对应。最后一个向量必须可达且携带能满足`buf_full_last_index`的terminal tag。
- preflight必须跨模块比较physical packer与stream：冻结tensor的axis order、dtype itemsize、每维byte stride、base和tail必须与`idx/dim_stride/address_remapping`一致；输出还必须用同一合同inverse回canonical。直接调用NumPy数学核而未执行stream/buffer寻址，只能证明数学配置绑定，不能让该门通过。
- Conv激活/输出只能选定一套合同并端到端实现，例如C4HW4/K4PQ4或NHWC/NHWK；禁止freeze使用后一套而stream沿用前一套。布局变更必须同时覆盖输入、INT32 P写回、requant staging和inverse。
- bias及其他per-channel数据的stream transaction、LC循环和buffer shape必须从每slice `k_tile`派生。局部`k_tile=16`的INT32 bias payload为64B，不能继承全局K32模板的2×128B读取范围；地址审计必须证明读取区间不越入w_scale、zero-point或相邻region。
- 真实硬件已出现确定性配置死锁时，先用encoder/RTL静态不变量闭环。能够证明terminal事件不可达后，不再为同一首因反复生成观察包；修复所有已知的输入、输出和辅助tensor合同并通过静态回归后，下一次仿真直接承担完成与数值证明。

### 17.14 Conv SA统一physical合同（v9采用）

- 首例和后续同族生成器统一使用以下轴序：A=`[storage_sample,H,Qblock,Cquartet,Q8,C4]`，B=`[R,S,ring_PREV_step,Cquartet,Kblock,K8,C4]`，bias=`[Kblock,K8]`，P/D=`[storage_sample,H,Qblock,Q8,Kblock,K8]`。任一端口改变轴序时必须同时修改forward、inverse、stream stride、execplan shape和数值探针，禁止兼容性猜测。
- SA group0为activation row、group1为local weight column、group2为K8 bias column broadcast。activation绑定stream0并在HIGH-4上沿PREV邻居环流；weight绑定stream1且按destination相对PREV顺序预排布在本地；bias绑定stream3并保持local；P由stream2写回。
- A/B/bias/P的单次事务均为32 B。GROUP0和GROUP1各消费8个16B buffer向量=128 B，GROUP2消费2个16B向量=32 B。buffer0/1是activation ping-pong pair且都允许neighbor；其余buffer保持local。生成器和静态validator必须从SA lane数推导这些常量，不能继承DeepSeek实例的旧`idx_size`。
- node-0004每slice的local K为16，因此bias物理区严格为64 B，包含两个不同地址的K8事务；`bias_offset + 64`必须不超过bias region，也不能落入w_scale、zero-point或其他邻接区。这里的“两种地址”不是“两次运行期读取”：同一K8 bias行必须按每个Q8×K8输出matrix tile的消费节拍重复送入SA。
- terminal-tag必须与producer最内层完成事件一致：stream0由activation Cquartet末项释放，stream1由weight Cquartet/relative-ring组合末项释放；bias stream必须由覆盖`Kblock→H→Qblock`的tile事件释放，不能只由Kblock末项释放。静态测试必须证明最后事务地址可达、有效字节完整、每个输出tile都取得一行32 B bias，且对应buffer循环和生命周期恰好闭合。
- execplan端口ABI固定为A→activation/READ_STREAM0、B→weight/READ_STREAM1、C→bias/READ_STREAM3；manifest中的可读标签和实际`io_map`必须一致。旧A/B交叉ABI属于负向回归，不能因数学einsum仍可运行而接受。
- 首算子真实硬件通过前，公共公式和fail-closed测试可以维护，但不批量改写其他Conv候选产物。v14诊断性run1止于preflight；v18进入真实仿真后停在首个accumulate stage并已撤权。v19已按本节修复bias tile节拍并建立全新candidate/preflight/freeze/package身份，静态门和两轮本地审计均通过；下一步直接执行v19完整run1，不再为同一已确认错误生成观察性仿真。

### 17.15 配置JSON到最终bitstream的身份绑定（v10r3实测）

- v10r3最终服务器回传证明：新版`conv_1x1_real.json`、Q8/K8 physical staging和旧e0 accumulate bitstream可以在manifest内部保持哈希自洽，却会重新表现为v8的旧事务节拍并在首stage发生确定性功能停滞。因此“JSON通过preflight”“bitstream能解析”和“package等于freeze”都不能单独证明配置身份一致。
- v10r3服务器实际在三个accumulate wave地址`0x00101c00`、`0x00102000`和`0x00102400`各加载35行×128-bit；安装文件LF规范化身份为4515字节、SHA-256=`4dabcb3879fe4968019ee0c7e5461dfb5892ac4e6aaef4a1e3d69ec9e69361a2`，与`e0-rebuild/modules_dump_128b.bin`规范化内容完全相同。当时用于修复混装的`rebuild-v9`历史身份为28行、SHA-256=`44fb091f0013dbccfc376154ea53d074d08bc945e3d276810579766e8c45fa8f`，但它后来因v18揭示的bias节拍错误撤权；v19正式身份为29行、LF规范化SHA-256=`7d85938215a1d5a5622c38938b5adb64b982c631170604a4ba8285fb5397b255`。三处安装地址、当前freeze和official encoder证据必须命中同一revision声明的身份。

### 17.16 Conv bias握手与SA outbuffer完整初始化规则（v18实测，2026-07-21）

- v18真实运行完成全部preload并进入首个accumulate stage，随后长期停在fixed observer `0/5`；这是计算阶段停滞，不是JSON语法、runner、barrier、readback或4 KiB preload错误。原始停止返回`sim_results_v18_run1.zip`与补充诊断`v18_run1_deadlock_extra_1784611151.zip`分别为86,794 B/SHA-256 `2f33f34f626b2b1fe71502da5fe10e87eb67fb21d3a13404c528fbc130dbfeca`和217,860 B/SHA-256 `6b833a69ae92e9fb9c9147d783d01ece803e7c4f98c3c0d62721b8824c574dc7`；它们是手工终止后的失败证据，不得标为自然完成run1。
- 目标RTL `SA_PE_Outbuffer`在初始bias阶段按内部指针0、1、2、3依次写入一组16项psum；只有指针3握手后才切换内部组。计算读指针又从0顺序前进，并要求对应psum tag有效。少于四次bias握手会留下指针2/3对应项无效，随后在`alu2ob_bp_pre_unmasked`门停住，不能到达SA transout、buffer5写入或MSE4 write-data。
