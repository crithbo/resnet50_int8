# 整网测试收敛优化专项规则

最后更新：2026-08-18

本专项只维护跨族测试收敛方法、共享 gate/validator/registry 和规则正交性。它不接管 family，不构建
family package，不上传/运行服务器，不取 lease，不修改功能 RTL、config、numeric、workload 或
current pending/tested package；除用户明确授权外不修改 plan/owner registry。

## 1. 唯一目标

规则 ID：`CDA-OPTIMIZER-WHOLE-NETWORK-CLOSURE-001`

优化顺序固定为：减少无效服务器轮次 → 缩短构包墙钟 → 提高单次 return 信息增益 → stage-local
闭合后尽快提升到 full-chain natural terminal、formal-D、E4/E5。不得为了“本地全绿”降低 natural、
正式 D conjunction、runtime-D、合法 workload、E4/E5、禁止 host replay 或 RTL 授权门。

## 2. 事故审查而非追加规则

规则 ID：`CDA-OPTIMIZER-INCIDENT-ADJUDICATION-001`

每次公共事故先用 `rule-maintenance-incident-adjudication-v1` 分类：

- `RULE_SEMANTIC_ERROR`：替换、收窄或删除错误规则；
- `RULE_SEMANTIC_OMISSION`：合并到唯一 owner 规则；
- `IMPLEMENTATION_ESCAPE`：只修 tool/schema/test，不复制同义规则；
- `SESSION_EXECUTION_NONCOMPLIANCE`：修 Skill/handoff/适用性；只有映射到四类因果结果才增强硬门；
- `ONE_OFF_OR_DOMAIN_FAILURE`：留给 family owner，不改公共规则。

规则变更不是 append-only；必须同时指出 preserved、replaced/removed sections 与正负控。历史原文进入
`.agents/history/rules/`，活动规则保持唯一 owner、无版本结果、无 current package 事实。

## 3. 阻断适用性与复用

规则 ID：`CDA-OPTIMIZER-CAUSAL-GATE-MINIMIZATION-001`

共享 blocking gate 只能映射到 `server_start`、`actual_input`、`state_safety`、`return`。否则降为
record-only。changed-surface disposition 使用：

```text
blocking_applicable / receipt_reuse / record_only / not_applicable
```

unrun candidate patch-first；未变 surface 与 direct consumer 的 PASS 复用；廉价问题一次聚合、最终 ZIP
一次 admission；SHA/format/style/provenance 漂移若不改变四类结果不得阻断。tested/run-bound identity
仍不可覆盖。

## 4. 一轮定位设计

规则 ID：`CDA-OPTIMIZER-ONE-RETURN-DISCRIMINATION-001`

successor 应在一个 return 内覆盖全部可同轮观察的开放候选，至少包含 FIRST_DIVERGENCE 上游一层、
当前边界、下游一层、状态保持/clear 与 terminal。candidate×boundary matrix 必须能区分候选；实际
config→loader/encoding→RTL consumer 与 actual compiled RTL driver cone 是直接根因证据，不降格为
概率提示。未闭合的配置绕行不得进入生产。

合法 checkpoint 存在时使用最短累计硬件前缀；不存在时不要反复跑相同长前缀。observer/VCD 只能
只读，不能改变 DUT。诊断证据不足时标 incomplete，不冒充 DUT failure。

## 5. return 与跨族复用

规则 ID：`CDA-OPTIMIZER-SHARED-MECHANISM-REGISTRY-001`

共享 registry 记录机制、适用族、source-bound正控、历史反例、validator、claim boundary 与迁移状态。
跨族只复用机制和已验证 receipt，不复制其它族字段或结论。return 分析采用流式 checkpoint：先读
identity/core，再读 target progress，再读候选证据；唯一根因闭合即可停止，未闭合才继续。

每次正式回传至少给：previous progress、current finding、next shortest action、哪些 blocker close/add/
keep、是否需要规则 delta。family 信号/root 裁决仍归 family owner，optimizer 不替代。

## 6. 规则与接手可维护性

规则 ID：`CDA-OPTIMIZER-RULE-ORTHOGONALITY-001`

- `agent.md` 只作入口/角色/权限；`plan.md` 只作 current 状态；router 只作读取路由；
- config、硬件字段、服务器包、会话所有权、primitive/family 各自只有一个语义 owner；
- 活动规则数量和总字数要小，详细字段进入 schema/tool/test，历史进入统一 history 入口；
- 修改后必须运行 active-rule audit、mandatory-read compaction、Skill tests 和 current-disk takeover；
- synthetic tests 只能证明机制，不能替代 current control-plane、真实 VCS 或正式服务器证据。

## 7. 输出边界

专项允许写 shared tools/schemas/contracts/fixtures/tests、机器报告、task record 和经用户授权的规则。
没有新授权时输出 `RULE_CONFIRMATION`、`RULE_DELTA_PROPOSAL` 或 shared implementation receipt，不执行
family/package/storage/server/RTL/config/numeric/workload 动作。
