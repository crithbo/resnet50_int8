# 整网测试收敛优化专项规则

最后更新：2026-08-14（observer 默认与可选 TB VCD 全因果锥并存）

本规则只约束“整网测试方法优化”专用会话。该会话不接管任何算子族，不上传或运行服务器，
不修改功能 RTL，不覆盖现有测试包，也不直接修改 `.agents/plan.md` 或其他公共/专项规则。
它通过只读审计本地规则、生成器、validator、机器报告、task record 与当前可运行包，向主线提出
可执行的收敛优化建议。主线是规则发布、测试顺序和跨族变更的唯一裁决者。

## 1. 目标与不可降低的证据门

优化目标按优先级依次为：

1. 在服务器开始 compile 前尽量消除 package/config/address/observer 可本地发现的错误；
2. 在必须运行服务器时，使一次运行覆盖当前首分歧处所有低开销、可区分的候选；
3. 复用未受影响的已验证证据，减少无因果价值的重建、重算和负控；
4. 在阶段局部闭合后尽快进入合法的累计前缀或整网链路，避免反复验证已闭合阶段；
5. 用服务器墙钟时间、目标 stage 到达率和 blocker 收敛量评价方法，而不是用检查项数量评价。

任何优化不得降低以下门：production compile/elaboration 可执行、DUT natural terminal、正式 D
完整性与独立 golden 一致、E4/E5、runtime D pre-run absent、合法 workload provenance、禁止 host
内部 tensor replay、功能 RTL 修改授权、云端 RTL 影响审计。省略的只能是与本轮 changed surface、
服务器可执行性或结果可判定性没有因果关系的检查。

## 2. 专用 owner 边界

规则 ID：`CDA-WHOLE-NET-CONVERGENCE-OPTIMIZER-OWNER-001`

- 专用会话只做跨族方法审计、规则语义整理、共享 validator 设计、测试顺序建议和成本分析。
- 它可以在自己的报告、工具、测试和本专项规则的提案区写入；不得修改算子 owner 的 package、
  config、golden、observer、runner 或 return 结论。
- 对其他规则的修改默认只能以 `RULE_DELTA_PROPOSAL` 提交主线；用户或主线在本轮明确
  接受并授权实施后，才可窄幅写入已裁决的对应公共规则/schema/tool/test，且不得顺带
  改动未授权语义、current package、算子资产、plan 或功能 RTL。
- 每轮结束必须主动通知主线，提交 `OPTIMIZATION_FINDINGS`、`TEST_ORDER_PROPOSAL`、
  `RULE_DELTA_PROPOSAL` 或有证据的 `RULE_CONFIRMATION`，并写明 claim boundary。

规则 ID：`CDA-WHOLE-NET-CONVERGENCE-OPTIMIZER-COMMUNICATION-BOUNDARY-001`

- 本专项是主线的独立方法优化分支，不承担主线常规通信、状态镜像或进度广播职责。
- 主线不得向本专项发送一般性主线进度、测试包存储更新、其它family状态、无关return消费
  回执或仅供知悉的通知。
- 只有满足以下至少一项时才可向本专项派发：信息直接涉及本专项当前处理事项；需要本专项
  执行或裁决；改变本专项输入、授权或claim boundary；构成本专项的明确阻塞。
- 本专项向主线提交自身结果的主动完成通知不受本条限制；通信边界不得被解释为允许专项
  省略其正式交付或阻塞上报。

## 3. 服务器轮次成本账本

规则 ID：`CDA-WHOLE-NET-SERVER-ROUND-COST-ACCOUNTING-001`

必须按正式 return 的首分歧把每次服务器轮次归入且只归入一个主类：

1. `LOCAL_ESCAPE_PACKAGE_OR_OBSERVER`：exact-set、路径、runner、HDL/XMR、时钟/复位或诊断谓词错误；
2. `LOCAL_ESCAPE_CONFIG_OR_ADDRESS`：事务供应、物理 bank/row、地址生命周期或 materialized consumer
   不一致；
3. `COMPILE_ONLY_PRODUCTION`：只有真实服务器 frontend/filelist 才可获得的新证据；
4. `SIM_TARGET_NOT_REACHED`：前缀过长、手动中断或目标 stage 未到达；
5. `SIM_USEFUL_BOUNDARY_PROGRESS`：至少关闭一个 blocker 或把首分歧收窄到新边界；
6. `NATURAL_AND_RESULT_GATE`：自然终态与正式 D 联合门可裁决。

每类至少记录 package family/version、compile/run/host wall time、目标 stage 是否到达、关闭/打开的
blocker、是否本可由 current local bytes 发现。无精确时间时可给出有来源的区间或 `UNKNOWN`，不得
伪造精度。优化优先级以“可避免服务器墙钟 × 重复频率 × 影响算子族数”排序。

## 4. 按失败机制复用，而不是按包版本堆规则

规则 ID：`CDA-WHOLE-NET-FAILURE-MECHANISM-REUSE-001`

- 维护跨族反例登记表，key 是失败机制和最终消费者，不是 token、版本号或单个算子名。
- 同一机制优先强化一个共享 validator/生成器门和一组代表性正负控；不得为每个版本追加同义规则。
- 当前至少覆盖：actual-consumer HDL scope/XMR、public surface 与 owner clock、level-as-event、诊断
  predicate/gating、32B 事务供应守恒、物理 bank/row、路径预算、install子树runtime、
  SCA/TB-cwd actual open-path、shared-finalizer early-arm/partial return、exact-runner非零早退
  stderr可见性、extraction tree、
  云端 RTL nonblocking identity、formal-D conjunction。
- 若原则已存在但 final bytes 仍逃逸，首先判定为实现/适用性/consumer coverage 缺口；只有现有规则
  确实无法表达该机制时才提出新语义规则。
- 共享门本身造成服务器前置失败时，必须区分“运行所需不变量”和“工具偏好”。install子树只要求
  NDP根已有real/non-symlink `install`；`cfg_pkg/codex_runs`由package安全创建，不得转嫁给用户。
  共享validator只阻断会影响compile/simulation启动、actual input open、已有项安全或return的
  条件，并在一次廉价遍历中聚合全部错误；环境备注、目录创建者和非因果优化偏好只能
  `record_only`，不得形成逐项修复、反复重构包的迭代。
- final release共享复用必须闭合manifest最终状态：状态晋升后在final staging与clean exact-ZIP
  extraction运行同一package-specific preflight，pending中间态负控必须精确拒绝；positive assertions与
  observed-negative facts分开建模。若现有final-ZIP语义已要求但实现漏跑，归类为implementation escape，
  不新增同义规则。
- 禁止 `test/stat/find/hash/git/command -v`、Make dry-run 与 provider-closure/短探针阻断 next-fresh；
  服务器端不得检查具体文件、目录或 module provider existence；编译完整性由原生 production compile
  自然裁决。失败机制复用只允许比较 exact 原生命令、
  工作目录、相关环境与完整日志，不得把历史 provider 工具的结论提升为 current readiness 或 family hold。
- next-fresh exact runner 必须由 `runtime_preflight_noninterference_final_zip` 在唯一
  `# CODEX_PRODUCTION_LAUNCH` 之前一次聚合扫描服务器 existence/probe 逃逸；launch 之后的 return
  collection 文件判断不受影响。该门只证明“没有阻止真实命令”，不证明服务器环境 ready。
- production 失败后才执行 native differential：回看 `ndp-sim` 原生 README/handler/mapper/encoder/
  planner/model_execplan/SCA writer 与活动 Make/TB/filelist，把实际 attempt 分类为 `SAME`、
  `PACKAGE_DERIVATION`、`NATIVE_DOCUMENT_IMPLEMENTATION_DRIFT` 或 `SERVER_RUNTIME_UNKNOWN`。
  UNKNOWN 不得猜测、不转成 preflight；只有 package-owned 命令/产物差异才进入 successor 修包。

## 5. Changed-surface 最小阻断门

规则 ID：`CDA-WHOLE-NET-CHANGED-SURFACE-MINIMUM-BLOCKING-GATE-001`

每个 fresh 包先生成 changed-surface 清单，并把本地检查分为：

- `blocking_applicable`：失败会阻止 production compile、simulation 启动、目标 stage 到达、结果收集
  或数值裁决；必须通过；
- `receipt_reuse`：最终 consumer 与已验证身份逐字节或语义归一化一致；复用收据；
- `record_only`：只影响格式、说明、冗余摘要或不参与本轮裁决；记录但不得阻止发布；
- `not_applicable`：未触发且有机器可验证理由。

禁止为了“检查完整”重复运行与 changed surface 无关的 numeric/W3/golden/full-design 测试。也禁止把
真正影响服务器执行或结果正确性的门降为 record-only。分类必须能由负控证明：删去一个真实
blocking consumer 时会 fail closed；修改 record-only 字段时不会改变服务器命令、目标 stage 或
结果门。

规则 ID：`CDA-WHOLE-NET-CURRENT-FAMILY-POINTER-AND-PLAN-DRIFT-001`

- 每次审计、排序或设计current successor前，先从current storage index和exact
  package-linked最新task record生成唯一`current-family-pointer-v1`；不得从
  `.agents/plan.md`、聊天历史或手工版本清单推断current包。
- plan只做mutable provenance coherence lint。pointer与plan不一致时报告全部缺失current
  package token及source SHA，但不自动改plan、不hold current包，也不触发重建。
- storage index SHA改变时旧pointer立即失效并重生成；被正式return消费并转入tested的包不得
  继续出现在current候选矩阵中。

规则 ID：`CDA-WHOLE-NET-BLOCKING-CAUSE-OR-RECORD-ONLY-001`

- 每个本地blocking项必须机器映射到`server_start/actual_input/state_safety/return`之一并给出
  直接consumer和失败影响；没有该映射的环境建议、格式偏好、冗余身份摘要或优化提示只能
  `record_only`。
- 同一构包事务先一次聚合全部廉价检查，再一次检查冻结staging tree，最后对exact final ZIP
  只调用一次顶层release driver；禁止逐错误压缩、逐错误重建和无changed-surface因果关系的
  全量复测。
- 该压缩编排不降低natural terminal、正式D、E4/E5、runtime-D absent、workload provenance、
  禁止host内部tensor replay和RTL授权门。

## 6. 单轮候选判别覆盖

规则 ID：`CDA-WHOLE-NET-DIAGNOSTIC-BATCH-DISCRIMINATION-001`

- successor 设计从 `LAST_PROVEN_GOOD → FIRST_DIVERGENCE` 的候选集合开始，而不是从“再加一个信号”开始。
- 对所有能在同一时钟域、同一仿真前缀和可控事件预算内观察的候选，必须在同一个包中形成
  `候选 × 直接观察 × 裁决` 矩阵；单一叶子包只在候选已唯一或额外观测会显著扰动/延长仿真时允许。
- observer 仅使用 source-bound actual net、owner-clock qualified handshake/edge、直接 consumer 或
  下游 accepted 证据；稳定 level 只能作为状态，不能计作 progress。必须一次覆盖 FIRST_DIVERGENCE
  上游/当前/下游和状态持有/清除路径，observer 重算 expected equation 不能替代 actual net。
- 设计前估算每个候选被本轮区分的概率、observer 开销与目标 stage 到达时间；优先最大化
  `预期关闭 blocker 数 / 服务器墙钟`，而不是最小化 observer 行数。
- 对显式`TB_VCD_BOUNDED_CAUSAL_CONE`，`$dumpvars` target union必须等于source-bound catalog，禁止
  module/aggregate over-dump；freeze只消费append VCD timestamps，heartbeat必须unsigned width>=64且
  cadence=16384 owner cycles。multiline timescale、target-entry、exact-set/no-hard-limit、flush/reap与live
  downstream/first-error均进入共享正负控；这些要求不改变observer默认路径。
- 首轮VCD因果锥不再无参照地从“最小可运行集合”开始：必须绑定本族当前`round>=3`参考回执和合理
  signal-count range，但signal/direct-driver/candidate/boundary数量是软参照；范围外只需记录关系、理由
  和owner确认即可告警通过，不得因计数单独阻断。每个HIGH候选的source-bound zero-hop driver是强目标，
  缺失时记录gap，只要matrix仍完整且两两可区分便不单独阻断。后续轮次采用自适应滚动替换：精确列出
  predecessor、signals added/removed/unchanged与candidates preserved/closed/new；删除记录理由、置信度和
  受影响候选，LOW置信度默认保留，HIGH/MEDIUM可按工程判断删除，不要求逐项形式化无关证明。
- 跨族退出比较必须以quiescent archive的VCD SHA/bytes/last timestamp为权威，不得信任未绑定archive
  tail的同名字段。outer runner只消费共享evaluator决定，不复制阈值；first-fresh必须回放timestamp推进、
  suspected-only、完整plateau及真实freeze四态。partial/unflushed/unreaped不能被任何外层状态提升为PASS。

规则 ID：`CDA-WHOLE-NET-ONE-ROUND-OBSERVABILITY-COMPLETENESS-FIRST-001`

- 对后续 fresh successor，整网优化 owner 必须先用
  `CDA-SERVER-ALWAYS-ON-TRIGGERED-CAUSAL-OBSERVABILITY-001` 形成完整
  `候选→因果边界→触发快照→canonical classification` 合同，再讨论删探针或压缩日志。
- 默认observer采用stage-gated signal-id catalog与分块4-state transition记录，覆盖全部选中actual
  signal的exact time/sequence/width、0/1/X/Z和end state；禁止逐周期重复同值。原路径不变。
- 主线可按fresh包显式选择`TB_VCD_BOUNDED_CAUSAL_CONE`作为并列选项，但不得与full observer JSONL
  同时启用。VCD必须由package-local TB标准tasks生成，只覆盖source-bound完整因果锥、四层首分歧边界
  和全部已知候选；禁止full hierarchy、memory array、VPD/FSDB/UCLI/vendor路径。两种模式的Make dump
  argv都为0/0/0。100,000,000 bytes只作软告警；hard cap、截断、采样或按大小删除必须fail closed。
- observer的100MB完整性软告警不得承担磁盘保护。规则激活后的next-fresh observer包另须绑定族内来源的
  compile/observer/log duplication/parser scratch/return staging/sidecar六项保守峰值与minimum-free reserve，
  并在compile、simulation、finalization分别监控exact paths/set。达到运行边界只能one-shot停止整个
  attempt，保留/flush全部已完成行并回传`DIAGNOSTIC_EVIDENCE_INCOMPLETE`；durable ZIP+sidecar校验前不得
  清理，之后也只能清理exact owned leaves且证明foreign siblings不变。v99的局部阈值不是共享常数。
- `50%` slowdown 是工程偏好线，不是硬阻断门。单轮定位所需边界完整性优先；超过偏好线
  必须机器报告和优化，但不得为了达标删除会使两个候选重新不可区分的边界。没有同事件
  A/B baseline 时标记 calibration pending，不猜测开销。
- observer模式的v1 no-progress仍只触发快照并继续原timeout。VCD模式可使用服务器规则定义的严格
  plateau交集：owner-clock/sim-time推进、全部qualified counters/完整因果状态/global witness均稳定、
  coverage完整且无未决X/Z；global witness推进时禁止局部早停。3×30秒freeze、60分钟、8GB VCD/
  10GB return投影和I/O故障是独立PARTIAL兜底，不构成DUT hang或natural terminal裁决。
- 公共 registry/schema/validator 应按失败机制复用；family owner 只负责把逻辑边界绑定到
  fresh final ZIP 的 exact source span、owner clock、actual consumer 和返回合同。设计合同
  不替代 production compile、natural terminal、formal D 或 E4/E5。
- 发布后的next-fresh常态/诊断包必须执行
  `CDA-SERVER-SOURCE-BOUND-GENERATED-OBSERVER-001`，不得再由family模板自由填写observer
  HDL变量或parser字段。必须先用`generate_server_source_bound_observer.py`从pinned RTL
  catalog生成symbol IDs，再由
  `HIGH_INFORMATION_CAUSAL_V1` plan统一物化observer/logger/parser/binding。family owner只选
  语义boundary和catalog symbol ID；多个未解析symbol、wrong-module、clock/reset/width和候选
  同签名必须一次聚合返回。`source_bound_observer_generation`映射`server_start+return`，其它
  不影响启动/actual input/state safety/return的附加探针仍为`record_only`。
- 单轮定位评价改为“已知候选signature两两可区分 + 因果role coverage闭合”，不再以探针数少
  为优先。qualified/state独立记录、multiclass bitmap、actual-signal 全 transition、end-state、
  payload rolling digest 与 final summary 为observer默认；observer模式禁止raw waveform，显式选择
  `TB_VCD_BOUNDED_CAUSAL_CONE`时则只允许该规则定义的有界source-bound标准TB VCD。允许超过50%偏好线，
  但必须同workload A/B报告，且不得为降开销删除判别必需边界。
- 若真实production已通过compile、进入目标因果区间且return可消费，仍不能在一轮中唯一化根因，
  必须在下一包设计前生成`RULE_GAP_AUDIT`，反向审计“本地两两可区分”为何没有覆盖真实候选：
  未列候选、missing actual driver/consumer、source identity漂移、触发窗口、early-stop/global witness、
  return/parser丢证据和X/Z裁决均须逐项排除。若发现shared coverage缺口，审计结论必须成为shared门/
  负控或successor first-fresh的机器输入；若规则与current门已充分、只是孤立偶发实现/人工操作失误，
  可输出`RULE_CONFIRMATION_NO_CHANGE`而不修改规则/tool/test，只要求successor修包并重跑原门。仅扩大
  信号集合而不解释逃逸机制不得发布。
- 同一目标连续两次fresh构包/final gate失败，或连续两次服务器运行被package-local缺陷挡在目标
  之前，第三次前必须执行`PACKAGE_BUILD_FAILURE_RULE_AUDIT`。优化owner按失败机制聚合generator、
  schema、validator与负控缺口，禁止版本号驱动的逐错重建；公共语义缺口先交主线激活。已有规则已
  覆盖且current门能捕获的孤立偶发错误允许`RULE_CONFIRMATION_NO_CHANGE`，无需新增共享负控；若current
  门实际放过同机制，才必须补真实反例负控后继续。
- source-bound生成后的单轮判别还必须把“逻辑boundary”收紧到exact canonical instance：每个
  decision boundary用pinned target与near-miss负控，parser按
  `boundary_id/canonical_instance/seq`分组，禁止跨slice/group/lane聚合。decision payload必须
  binary-known且位宽与catalog一致；X/Z或解析失败只能产生`EVIDENCE_INCOMPLETE`，不得用sentinel
  继续候选匹配。
- 单轮定位合同的semantic fingerprint覆盖plan、observer、parser、instance/payload合同与候选矩阵。
  指纹变化即触发一次exact final-ZIP typed first-use audit；指纹byte-equal才允许复用旧收据。该附加
  审计仍在一次aggregate调用中运行全部正负控，不得造成逐错误重建；纯可选probe失败仍为
  `record_only`。
- next-fresh required parser 还必须执行
  `CDA-SERVER-DIAGNOSTIC-PARTIAL-EXIT-LIVE-CAUSAL-RECORD-001`：对全部 required plugin 做 exact
  disposition coverage，并用不含 final-ring 的 qualified live `EVENT` 或 signal-safe persisted
  equivalent fixture 实跑 parser。自然退出 `final` block 的 `SUMMARY/RING_*` 只能补充，不能
  成为 `INT/TERM` 的唯一因果输入；非因果 plugin 可带理由 N/A，不为附加格式扩大阻断面。

## 7. Checkpoint 或最短合法前缀

规则 ID：`CDA-WHOLE-NET-CHECKPOINT-OR-SHORTEST-LEGAL-PREFIX-001`

- 若存在逐字节绑定、由同一硬件阶段产生且生命周期/地址/qdomain/layout 合法的 checkpoint，可从该
  边界启动窄测试；必须保留 producer receipt 与 visibility 条件。
- 若不存在合法 checkpoint，保留能复现首分歧的最短累计硬件前缀。不得用 host 预计算、golden
  内部 tensor、两次仿真 dump/reload 或静态 base 冒充运行时 producer。
- keep/drop ledger 必须说明每个保留项对复现或判别的作用，并估算删除项是否真的减少 compile/sim
  墙钟。若后续 stage 根本未启动，单纯删除其 payload 不得冒充运行时间优化。

## 8. 从 return 反馈到规则实现

规则 ID：`CDA-WHOLE-NET-RETURN-LESSON-TO-RULE-IMPLEMENTATION-001`

每次 return 出现 package/config/observer 逃逸时，专用会话必须回答：

1. 哪个现有规则本应捕获它；
2. 逃逸属于规则缺失、适用性判断错误、validator 未覆盖 actual consumer、focused model 与 production
   不一致，还是负控没有从 exact final bytes 派生；
3. 最小共享修复位于生成器、validator、规则语义还是调用编排；
4. 哪个历史反例可作为永久回归；
5. 修复后哪些旧检查可以合并、降为 receipt reuse 或删除。

若simulation已退出但family analyzer/collector阻止自然打包，默认归为共享return基础设施
逃逸，而不是继续给各family复制恢复脚本。专项应优先落实
`CDA-SERVER-POST-SIM-CORE-RETURN-INDEPENDENT-PUBLISH-001`：固定JSON-only helper、先落
sim-exit receipt、plugin隔离、plugin失败仍发布core return、同request幂等恢复，并用exact
final ZIP四场景一次验证。family-specific decision仍可作为plugin，但不能拥有core publish。

规则缺失时提出一个非同义 ID、适用范围、正控和至少三个相关负控。规则已足够时不得新增同义条目，
而应提出 validator/生成流程修复。任何成功经验也要给出可复用的 `RULE_CONFIRMATION`，防止只从失败
增加门而使本地自检无限变重。

规则 ID：`CDA-WHOLE-NET-WAVEFORM-INCREMENTAL-REVIEW-COORDINATION-001`

- 本ID协调历史raw-waveform、可选TB VCD和其它重型结果的本机流式审查；observer-only仍直接消费
  immutable event chunks。每个checkpoint必须绑定exact return/catalog/signal/time/candidate identity；
  `analysis_state.json`是原子current pointer，`checkpoints.jsonl`只追加，`report.md`随分析同步编辑，
  大ZIP/VCD/JSONL只按offset streaming读取且不得整体塞入会话上下文。
- `ROOT_CAUSE_UNIQUE_STOP` 后停止继续扫描同一 epoch 的无关波形是效率正控；若仍有两个可行
  候选、缺 FIRST_DIVERGENCE 或 transition 不完整，则停止为负控并必须保持 inconclusive。
- 每族重型原始结果最多三组，角色固定`MAX_PROGRESS + LATEST_1 + LATEST_2`并先按identity去重。只有
  analysis complete、family/mainline双消费、确定性core和保护集审计均通过的非保护旧组才能淘汰；
  收到第四组后在当前分析事务结束前恢复到三组。共享process-tree supervisor、simulation-time heartbeat
  与所选writer flush统一维护；不得复制kill/wait脚本，也不得把host CPU活跃冒充sim-time progress。

## 9. 阶段闭合与整网提升

规则 ID：`CDA-WHOLE-NET-STAGE-CLOSURE-TO-FULL-CHAIN-PROMOTION-001`

- 阶段局部证据只关闭该阶段的结构或数值门；不冒充整链 E4/E5。
- 某阶段已闭合且其输入、config、RTL causal cone 未变化时，不再重复服务器运行；使用冻结收据装入
  最短累计前缀或整网链路。
- 对同一算子族的多个实例，只有 materialized consumer signature、qdomain/layout、tail、地址约束和
  受影响 RTL causal cone 均等价时才可共享代表性证据；否则保留实例门。
- 当局部阻塞均关闭后，应优先构建一次覆盖最终 natural terminal 与正式 D 的全链，而不是继续扩展
  只读局部诊断。

## 10. 首轮固定交付物

专用会话首次工作必须输出：

1. 最近服务器轮次浪费机制排行榜及可避免时间估算；
2. 现有规则“语义已覆盖但实现未落实”和“本地过度严格”两张清单；
3. 可共享 validator/负控/反例登记表的具体方案；
4. 当前五个可运行包按信息增益、预计墙钟和整网关键路径给出的运行顺序；
5. 三项以内、可立即由主线裁决的规则或流程改进；
6. 机器可读报告与 task record，并主动回传当前主线。

首轮默认只读历史与 current package bytes；不得重建、替换或使当前五个包失效。若建议会改变现有包
或算子语义，必须停在提案并请求主线裁决。

## 11. 规则变更首包的独立复核与清晰通知

规则 ID：`CDA-WHOLE-NET-FIRST-IMPLEMENTATION-EXTRA-AUDIT-001`

- 专项发布会改变 next-fresh 构包行为的规则/schema/tool/test 后，必须同时给主线一份
  `ACTION_REQUIRED_BEFORE_UPLOAD` 结构化派发；消息必须绑定 rule-change epoch、首包适用 family、
  current 包冻结边界、owner ACK、上传 hold 条件、唯一复核命令和完整回传字段，不能只回传一组 SHA。
- 每个受影响 family 的首个 fresh 包是实现质量校准包。它必须在常规聚合检查和一次 final ZIP 生成后，
  从 clean extraction 独立复核 actual runner/input、source-bound exact logger→collector→parser、
  post-sim return core 四场景和全部剩余候选的判别矩阵。family 自己的 build PASS 不得替代该复核。
- 专项应把首包复核失败按机制登记为 generation/validator applicability escape；一次返回全部廉价错误，
  不得逐错驱动多次重建。只有映射到 `server_start/actual_input/state_safety/return` 的 findings
  可以 hold；其它项保持 `record_only`。
- 首包 PASS 后，同 family/epoch 的后续包绑定 exact receipt 即可恢复常规门；新 epoch 才重新触发。
  此机制用于降低规则首版实现不成熟造成的服务器零进展轮次，不改变 production compile、natural
  terminal、正式 D、E4/E5、runtime-D absent、workload provenance、host tensor replay 禁令或 RTL
  授权边界。
